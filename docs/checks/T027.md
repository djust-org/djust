### T027 — Template name held but not supplied (explicit exposure)
- **Severity**: Warning
- **Method**: AST (the view's source) plus regex (the template), the same
  extraction as T018 and `djust_typecheck`
- **What it detects**: A view under explicit exposure (the default since 2.0)
  whose template reads a name that the view sets as a public attribute
  (`self.count = 0`) or defines as a class value or property, and that
  nothing supplies. Under explicit exposure a template gets the declared
  `state()` fields, what `get_context_data()` returns and what the framework's
  providers supply, so the name renders as empty string with no error. This is
  what a view written for djust 1.x looks like after the default changed. A
  declared field counts as supplied, unless it is `state(render=False)` or the
  view's `get_context_data()` does not build on `super().get_context_data()`.
  T018 does not report it, because T018 counts an attribute as defined.
  The check follows `get_context_data()` through `super()` into djust's own
  classes. Each override supplies the keys of the dict it returns: a returned
  literal, `super().get_context_data(name=...)` keywords, and the keys and
  `name["key"] = ...` writes of a returned local bound to
  `super().get_context_data(...)` or a literal. A local dict that is not
  returned and code in a nested function supply nothing (#4224). Since #4278
  the returned local may also be filled by `name.update(key=...)`,
  `name.update({"key": ...})` and `name.setdefault("key", ...)`, so the
  common `ctx = super().get_context_data(**kwargs); ctx["k"] = ...; return ctx`
  override is checked. A template is read as the runtime reads it: the
  `{% extends %}` chain is resolved and `{% include %}` partials are inlined, so
  a name read only in a base template or an include is reported (without a line
  number, because it is not in the view's own file).
- **Also detects** (#4054): a template name `X_count` that nothing supplies,
  when `X` is supplied (returned from `get_context_data()` or a declared
  field). djust 1.x generated `items_count` from a QuerySet or list `items`;
  explicit exposure does not. The message points at `{{ X|length }}`. The
  check cannot see the value's type, so a supplied string `X` with an
  `X_count` is named too; silence it with the noqa comment below.
- **Fix**: Declare the name with `state()` (it then renders; persisting it or
  sending it to the browser takes `persist=` or `client=True`), or return it
  from `get_context_data()`
  (`return {**super().get_context_data(**kwargs), "total": self.total}`). For
  `X_count`, write `{{ X|length }}`. See
  [Migrating to djust 2.0](website/guides/migrating-to-2.0.md).
- **Suppression**: `DJUST_CONFIG = {"suppress_checks": ["T027"]}`, or one name
  with a `{# djust_typecheck: noqa name #}` template comment
- **Not checked**: a view on the deprecated 1.x exposure policy (`djust.V028`); a view
  whose `get_context_data()` does something the check cannot follow (it
  passes the context to a helper, calls `ctx.update(other)`, writes
  `ctx[name] = ...` with a non-literal key, or returns something other than
  a literal dict, `super().get_context_data()` or the context local); an inline
  `template` that uses `{% extends %}`. These views are counted in one
  `djust.T027` Info message ("T027: skipped N view(s) ..."), so a clean run
  can be told from one that examined nothing. With `DEBUG = True` the same
  condition is logged at render time for every view, once per view and name,
  on the `djust.exposure` logger (`DJUST_UNSUPPLIED_NAMES = "warn"` logs it
  whatever `DEBUG` is; `"error"` raises `UnsuppliedTemplateNameError` on every
  such render, which fails a test, #4279); at render time the `X_count` notice is given only when `X` is a
  QuerySet, list, tuple or set (the values 1.x counted).

### T027: Template name held but not supplied (explicit exposure)

**Severity**: Warning

**What causes it**: A view under explicit exposure (the default since 2.0) has
a template that reads a name the view holds as an attribute, and nothing
supplies it: it is not a declared `state()` field and `get_context_data()`
does not return it. The name renders as empty string, with no error. A view
written for djust 1.x looks like this:

<!-- djust-example: skip -- the view T027 reports, shown as the cause -->
<!-- doc-snippet-check: anti-pattern -->
```python
class CounterView(LiveView):
    template = "<div dj-root>{{ count }}</div>"

    def mount(self, request, **kwargs):
        self.count = 0
```

Message: "<view> -- the template reads 'count' at line 1 (<inline>) and the
view holds it as an attribute, but nothing supplies it to the template: ..."

**Fix**: Declare the name with `state()`, which renders it (or return it from
`get_context_data()`):

<!-- djust-example: skip -- executed by tests/test_doc_snippets_execute.py -->
```python
from djust import LiveView, state


class CounterView(LiveView):
    template = "<div dj-root>{{ count }}</div>"
    count = state(0)
```

Persisting the field or sending it to the browser takes its own grant
(`persist=`, `client=True`; see [explicit exposure](../state/explicit-exposure.md)).

T027 also names a template `X_count` that nothing supplies when `X` is
supplied (#4054): djust 1.x generated `items_count` from a QuerySet or list
`items`, and explicit exposure does not. Write `{{ items|length }}`, or return
`items_count` from `get_context_data()`.

Moving a whole 1.x view is covered in
[Migrating to djust 2.0](migrating-to-2.0.md). The check skips a view whose
`get_context_data()` it cannot follow (for example one that passes the
context to a helper function) and an inline `template` that uses
`{% extends %}`, and reports how many it skipped in one Info message. A
`template_name` view is read through its `{% extends %}` chain and its
`{% include %}` partials. With `DEBUG = True` djust logs the same condition at
render time for those too, and `DJUST_UNSUPPLIED_NAMES = "error"` in your test
settings turns it into an error that fails the test that renders it. Suppress with
`DJUST_CONFIG = {"suppress_checks": ["T027"]}` or a
`{# djust_typecheck: noqa count #}` template comment.
