# Process canonicalizations from the v1.3.0-11/12 retro arc (release audit, code scanning)

- **A CI log that seems to stop mid-run is truncated, not proof that the runner died (#3473).** `gh run view --log` cut a 24,882-line job log at about 8,000 lines. #3473 was then filed as a lost runner with "no test assertion", and a Python 3.14 security bug (GHSA-4h5m-xcmg-vvmw) sat red on `main` for four days as background noise. Before diagnosing a failed job, fetch the raw log from `GET /repos/{owner}/{repo}/actions/jobs/{job_id}/logs`, or read the check-run annotations, and grep it for `short test summary`. Treat a matrix cell that is red on `main` as a finding until its failing test is named.
- **The CodeQL PR check is neutral for note-level alerts, so list the PR's alerts before merging (#3475).** #3474 merged with a new `py/import-and-import-from` alert (#3076): the "CodeQL" check reported *neutral* because it fails only on error-level results. Before merging a PR that adds Python or JS, run `gh api "repos/djust-org/djust/code-scanning/alerts?ref=refs/pull/<N>/merge&state=open"` and fix or justify every alert it lists.
