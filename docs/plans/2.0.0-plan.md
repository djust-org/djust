# djust 2.0.0 plan

Status: **draft, opened 2026-10-16**. Tracking issue and milestone: `v2.0.0`. Development branch: `2.0`.

djust 2.0 is defined by three default flips (explicit state exposure, strict event parameters, strict event security) and the deletions they unlock. Everything else is cleanup that 1.4 warns about first, as [API_STABILITY.md](../API_STABILITY.md) requires. Baseline: `main` at 1.3.0rc10, which has 245k lines of Python, 27.6k lines of client JS and 112.5k lines of Rust; the installed wheel is 38 MB.

Line references are from that commit, and sizes are approximate. Items marked *(unverified)* come from a read-only survey and need a repro or a second look before work starts.

## 1. Default flips

ADR-036 and ADR-038 both say their legacy code is deleted "when a major release makes the new mode the default". 2.0 is that release.

| Flip | Today | What it lets 2.0 delete | Who it breaks |
| --- | --- | --- | --- |
| `exposure_policy` `legacy` → `explicit` (ADR-038 Step R) | `"legacy"`, `live_view.py:740`; `uses_legacy_exposure` has 102 call sites in 27 files | The reflective attribute walk; private-attribute persistence; `_FRAMEWORK_INTERNAL_ATTRS`; legacy session and signed-snapshot restore (`runtime.py:3622-3781`); the legacy save path; `security/state_snapshot.py`; `PersistentLiveView`; `enable_state_snapshot`; the legacy-only actor mode | Every app that relies on implicit public attributes as state. Needs a migration guide and a codemod. |
| `event_parameter_policy` `legacy` → `strict` (ADR-036 Step R) | `"legacy"`, `config.py:118` | `coerce_parameter_types`, `_coerce_value`, `_coerce_single_value`; the legacy client collectors and `_target` keys; the legacy branches of `checks/bindings.py` | Handlers that take untyped or extra parameters |
| `event_security`: remove `open` / `warn` | strict is already the default (`config.py:111-115`) | The two modes and their log path (`websocket_utils.py:140-163`) | Projects that set `open` or `warn` |

Defaults to switch at the same time:
- `hook_namespacing`: `lax` → `strict`.
- `DJUST_TENANTS['STRICT_MODE']`: removed, so isolation always fails closed.
- `DJUST_LIVE_RENDER_ALLOWED_MODULES`: defaults to the mount allow-list instead of permitting everything.

## 3. Simplifications

| Area | Today | Proposed for 2.0 | Effort |
| --- | --- | --- | --- |
| One transport core | Mount, auth, event security, side-channel flushes and background work are implemented per wire: WebSocket, SSE, the HTTP POST fallback and two API dispatchers. `websocket.py` (6,883 lines) and `runtime.py` (8,555 lines) keep twin copies. Server push, tick and db_notify work only on WebSocket. | `ViewRuntime` becomes the only path, and each wire is a thin adapter around one turn pipeline. A single error envelope strips debug fields in one place. | L |
| One render frame | About nine full-HTML frame shapes, plus a separate frame per side effect. The WebSocket and SSE dispatchers are copies of each other. | One `render {target, patches \| html, effects[]}` frame and one dispatcher table; `navigate` and `navigation` merged. | M–L |
| One component system | A button exists as a Python class, a `ui/` simple/stateful pair, a Django tag, a Rust-engine copy of that tag in `rust_handlers.py` (11,266 lines, where 192 of 197 tags duplicate a Django tag), a `theme_*` tag and `RustButton`. | One catalog of Django tags rendered inside Rust through the existing `{% load %}` bridge, after a benchmark. `theme_*` becomes a theme layer of tokens, CSS and overrides. | L |
| Fewer mixins | LiveView has 22 bases. Five side-channel mixins each keep their own queue and drain. Two stream APIs share method names *(unverified: the async one may be unreachable)*. | One outbound-commands queue, one streams API, and the HTTP verbs moved into the transport. Target is about ten bases. | M |
| One state codec per job | About eight serialisation paths | After the exposure flip, one render codec and one persistence codec | M |
| Rust is mandatory | The Python code falls back when the extension is missing, and components re-render with Django templates on any Rust error (`components/base.py:83-89`) | Remove the fallbacks and raise instead of re-rendering | M |
| Smaller public surface | `djust.__all__` has 65 names and disagrees with `decorators.__all__` | About 30 top-level names; client behaviour moves into `@event_handler` options; `djust.compat` for one release | S–M |
| Private modules into packages | 45 top-level `_*.py` modules | `exposure/`, `children/`, `state/`, `contracts/`, `transport/`; one log sanitiser instead of two | M |
| Template filters | ~75 filters reimplemented in Rust | Hot filters stay in Rust; cold, parity-heavy ones route to Django's own functions; parity frozen at the documented 98.57% | M |

## 4. Package split

The optional extras make nothing optional today: `auth`, `tenants`, `theming`, `admin` and `deploy` are empty. Only a separate distribution can take code out of the base install.

| Subsystem | Proposal |
| --- | --- |
| LiveView runtime, component machinery, uploads, presence, push, `db` notifications, `auth/core` | Stay in core. Add a `postgres` extra for `djust.db`. |
| WebSocket stack (`channels`, `msgpack`) | Moves behind `djust[live]`, as decided in #2560, with a 1.x warning first |
| Components catalog (~52k lines, 2.2 MB static) | `djust-components`, on the same release train |
| Theming (~42k lines) | `djust-theming`; the theme-head hook stays in core |
| Accounts pages, social, allauth integration | `djust.contrib.accounts` behind an extra |
| MCP, observability, AI discovery, bug capture, `audit_*` | `djust-devtools`; only the DEBUG hooks stay in core |
| Deploy CLI | Moves to djustlive, which drops `click` and `requests` from the base install |
| Scaffolding | `djust-create`, per ADR-007 |
| `admin_ext` | Separate distribution, or deprecate |
| `clocks`, `audio`, the LiveView Native renderers | Move under `djust.experimental` |
| PWA, tutorials | Behind an extra, with their client JS made opt-in |

djust.org and djustlive import `djust.theming`, `djust.auth`, `djust.components.base`, `djust.db` and `push_to_view`, so every move needs a re-export path for one release. Add import-linter contracts so core cannot import the split packages (ADR-007 open question 6).

## 6. Bugs found during the survey (1.3.x)

- The client drops `presence_event` frames: the server sends them, but the client has no case for them.
- The `i18n` flush calls `_drain_i18n_commands`, which nothing defines.
- *(unverified)* The HTTP POST fallback drains only flash, metadata and navigation, so it may drop `push_event`, deferred work and layout effects.
- *(unverified)* SSE error frames do not strip debug fields the way WebSocket frames do. This is latent: no caller passes them today.
- *(unverified)* `StreamsMixin` and `StreamingMixin` share method names.
- `djust_doctor` warns below Django 4.0, but the floor is 4.2.

## 7. Sequence

1. **1.3.0 final and 1.3.x**: the survey bugs and the packaging quick wins.
2. **1.4, the deprecation release**: a `warn_deprecated` for everything 2.0 removes, and warnings for views on legacy exposure or legacy parameters. A codemod or `djust_audit --fix` for the exposure migration. The 2.0 migration guide as a draft. The split distributions released alongside, with core re-exporting from them.
3. **2.0 alphas, flips first**:
   - Alpha 1 flips the three defaults and raises the floors to Python 3.12 and Django 5.2.
   - Each later alpha runs one deletion stream: ADR-038 Step R, ADR-036 Step R, the transport core, the render frame, the component catalog.
   - djust.org and djustlive are tested against every alpha.
4. **2.0 release candidates**: re-exports removed, the `djust.compat` shim in place, and the security audit re-run on the new transport core.
5. **2.0.0.** 1.x gets security fixes for the support window the policy sets.

## 8. Open decisions (owner)

- [ ] Explicit exposure as the 2.0 default (ADR-038).
- [ ] Strict event parameters as the default (ADR-036), and removing `event_security` `open`/`warn`.
- [ ] Python floor 3.12 and Django floor 5.2. CI tests only Python 3.12–3.15 and Django 5.2; Django 4.2 LTS ended in April 2026.
- [ ] Split distributions, or keep one wheel and only trim it.
- [ ] One component system: Django tags rendered through the Rust bridge, after a benchmark.
- [ ] Removing the Tokio actor system and the Rust component crate.
- [ ] Moving the deploy CLI to djustlive.
- [ ] A wire-protocol change (one render frame).
- [ ] `@client_state`, `@optimistic`, `@cache`: implement or delete.
- [ ] Target dates for 1.4 and 2.0.
