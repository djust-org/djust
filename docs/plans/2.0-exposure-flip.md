# djust 2.0: explicit exposure by default (ADR-038 Step R)

Status: draft for maintainers, 2026-10-16. Baseline: `main` at 1.3.0rc10 (`dad626e7`), which matches `origin/2.0` apart from the plan commit. Line numbers come from that commit. *(guess)* marks an estimate or an inference that has not been verified.

Sources: [ADR-038](../adr/038-explicit-context-and-state-exposure.md) (D-z, Step R), the [2.0 plan](2.0.0-plan.md) §1 and §7, the [explicit exposure guide](../website/state/explicit-exposure.md) and the [migration inventory note](../adr/notes/038-migration-inventory.md).

## 0. Summary

> **Direction settled (2026-10-19).** See [the 2.0 plan](2.0.0-plan.md#direction-settled-2026-10-19). For this document it means:
> - `"legacy"` does not survive 2.0.0. It stays a deprecated opt-in only during the 2.0 alphas, until PR 11 removes the arm. There is no broad compat mode in 2.x (§6 Q1).
> - 1.4 keeps `legacy` as the default and ships the warning, the checker and one combined opt-in for explicit exposure, strict parameters and strict-only event security (§2, §6 Q2). Its API is not chosen.
> - `lazy=True` children and upload resume are **ported**, not dropped or left unimplemented (§4.1, §4.4).
> - The actor order is: downstream `use_actors` inventory, these exposure PRs, Python actor removal (PR 2), then the Rust crate.
> - Still open: production diagnostics (§6 Q3) and public-page caching (§6 Q5).

- **PR 1** flips `LiveView.exposure_policy` from `"legacy"` to `"explicit"` (`live_view.py:740`) and changes the `_read_exposure_policy` fallback (`_exposure.py:211`). `"legacy"` stays accepted as a deprecated opt-in.
- **Later PRs** each delete one legacy target with its tests. The legacy arm itself goes last.
- **Two Step R targets cannot simply be deleted**, because explicit mode depends on them:
  - `_FRAMEWORK_INTERNAL_ATTRS`, used for reserved names and change detection (§5 G1);
  - the `serialization.py` sensitive-name floor, which protects deliberate model rendering under both policies (§5 G2).

  This doc proposes a reduced survivor for each, as ADR-038 Step R's exit conditions allow.
- **Prerequisites before the flip:**
  - framework-shipped LiveViews and several framework mixins still depend on the attribute walk (§4.1);
  - about 380 test files assume legacy implicitly (§4.2).

## 1. What explicit mode requires of an app

### 1.1 The rules

| Need | Declaration | Where |
| --- | --- | --- |
| Opt in (1.x; a no-op once 2.0 makes it the default) | `exposure_policy = "explicit"` | `live_view.py:740`, validated `:853-894` |
| Template context | `get_context_data()` additions, plus registered providers (components, actions, streams, uploads, forms, wizard, drafts, audio) and Django context processors | `mixins/context.py:584-688`, `:765-800`; providers `_exposure_providers.py:149-255`, `forms.py:43`, `wizard.py:98`, `drafts.py:13`, `audio.py:26` |
| Server persistence across reconnect, cross-worker restore and the HTTP POST fallback | `x = state(..., persist="server")` | `_state.py:85-124`; adapter `_exposure_sessions.py:165-189` |
| Raw browser data (`get_state()`, API `assigns`, debug panel) | `state(..., client=True)` | `_exposure.py:60-68` |
| Back-navigation snapshot | `state(..., persist="client", client=True)` | `_exposure_snapshots.py:21-38` |
| Schema change | `exposure_schema_version = N`, plus an optional `migrate_state(self, old_schema, values)` | `_exposure.py:358-370`; ADR D-j |
| Form input across reconnect | `form_input = persisted_form_input("name", ...)` | `forms.py:134` |
| Components | Declared at class level. Assigning one in `mount()` is an error (D-h). | `_exposure_providers.py` (`instance_assigned_component_error`) |
| In-place mutation of an object (a model, a form) | `self.set_changed_keys(...)` | `mixins/rust_bridge.py:658` |
| User-visible `@action` error text | Raise `ActionError` | `decorators.py:318` |

The code enforces these constraints:

- **Values.** Persisted and client values must be JSON primitives (`clone_json_state`, `_exposure.py:289-355`). `Decimal`, dates, `UUID` and model instances are rejected; store an id instead.
- **Field names.** A `state()` field name must match `[A-Za-z][A-Za-z0-9_]*` and must not be a framework name (`_exposure.py:440-448`). An underscore name cannot be declared at all.
- **Inheritance.** Grants are not inherited: each concrete class re-declares its fields (`_exposure.py:409-413`). An ungranted `state()` on an app base class is fine.
- **Sessions.** `persist="server"` needs a `db`, `cached_db`, `cache` or `file` session. Cookie sessions are refused (`_exposure_sessions.py:33`).
- **Plain attributes.** Ordinary attributes still trigger re-renders, because change detection walks `__dict__` under both policies (`websocket.py:420-428`, E2-8). They are never persisted or exported. Most legacy public attributes therefore only need a line in `get_context_data()`, not a `state()`.

### 1.2 Before and after

Before (legacy, typical):

```python
from djust import LiveView, event_handler

class TodoView(LiveView):
    template_name = "todos/list.html"
    enable_state_snapshot = True              # reconnect + back-nav restore

    def mount(self, request, **kwargs):
        self.filter = "all"
        self.items = []
        self.project = Project.objects.get(pk=kwargs["pk"])
        self._draft_count = 0                 # persisted via _user_private_keys

    @event_handler()
    def add(self, text: str = ""):
        self.items.append({"text": text, "done": False})
        self._draft_count += 1
```

After (explicit):

```python
from djust import LiveView, event_handler
from djust.decorators import state

class TodoView(LiveView):
    exposure_policy = "explicit"
    template_name = "todos/list.html"

    filter = state("all", persist="client", client=True)   # back-nav snapshot
    items = state(default_factory=list, persist="server")  # reconnect, HTTP fallback
    project_id = state(None, persist="server")             # an id, never the model
    draft_count = state(0, persist="server")               # was self._draft_count

    def mount(self, request, **kwargs):
        self.project_id = kwargs["pk"]

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context.update(
            filter=self.filter,
            items=self.items,
            # Reload under current permissions on every render (D4).
            project=Project.objects.get(pk=self.project_id),
        )
        return context

    @event_handler()
    def add(self, text: str = ""):
        self.items.append({"text": text, "done": False})
        self.draft_count += 1
```

`user`, `perms` and `messages` still come from context processors. A template key that nobody supplies renders empty, without an error. That silent failure is the main migration risk (§2.3).

## 2. Migration tooling for 1.4

### 2.1 What exists today

- **`djust_exposure_inventory`** (`management/commands/djust_exposure_inventory.py`; logic in `management/_exposure_inventory.py:251-363`) is a static AST scan. It never instantiates a view and never prints values.
  - It reports every inferred name with its kind, type and legacy destinations, plus a suggestion (`:226-248`).
  - For an `instance` name it suggests `state(persist="server")`. That over-grants: a legacy view without `enable_state_snapshot` remounts fresh on WebSocket reconnect (`runtime.py:3626-3631`), so the equivalent default is no persistence.
- **`_exposure_diagnostics.py`** is not a migration aid. It holds the D-a error-detail policy (`:58-75`).
- **Checks.** No check or warning fires today for a view that relies on legacy. `djust_check --fix` (`management/commands/djust_check.py:272`) has a fixer pattern a codemod could reuse.

### 2.2 Proposed codemod: `djust_exposure_inventory --fix`

It prints a diff to stdout; `--apply` writes the files.

**What it can infer and emit safely:**

1. **`get_context_data()` entries.** Take the names the view's template references (`mixins/jit.py:48` `_cached_extract_template_variables`) that are also inventory `instance`, `class_value`, `property` or `state` names. Emit `context[name] = self.name`, merged into an existing `get_context_data` if there is one. Names the template never references stay plain attributes, and the codemod lists them.
2. **The policy line.** Add `exposure_policy = "explicit"` to every concrete class that has no blocking finding (see the next list).
3. **Reconnect parity.** A view without `enable_state_snapshot` gets no `persist`, which matches legacy WebSocket reconnect.
4. **Type flags.** Mark any attribute whose literal or annotation type is not a JSON primitive with "store an id".

**What needs a human.** For these the codemod emits `# TODO(djust-2.0)` and exits non-zero:

- **Persistence choice** for `enable_state_snapshot` / `PersistentLiveView` views. Propose `persist="server"` by default. `persist="client", client=True` is browser-readable, so never propose it for names matching `_PII_NAME_PATTERN` (`checks/integrations.py:32`).
- **Reliance on the HTTP POST fallback.** Legacy restores the whole public context from the session (`mixins/request.py:1064-1080`). Explicit restores only `persist="server"` fields (`:1095-1105`). Handler-mutated state on views served without WebSocket needs `persist="server"`.
- **Underscore attributes** that were persisted through `_user_private_keys`.
- **Patterns explicit mode refuses or doesn't carry over:**
  - components assigned in `mount()`;
  - `lazy=True` children;
  - `use_actors`;
  - overrides of `_restore_snapshot` / `_should_restore_snapshot`;
  - templates that read presence `username` / `user_id` metadata;
  - time-travel jump or replay.
- **Grants on app base classes**, which each concrete class must re-declare.
- **Template visibility.** The template extractor doesn't see dynamic `{% include %}` / `{% extends %}` chains. *(guess: the extractor does not follow includes; verify)*

### 2.3 Proposed DEBUG dual-run check (1.4 and the 2.0 alphas; deleted with the walk)

Under `DEBUG`, for an explicit view, compute the names that the legacy walk would have supplied and that the template references, but that the explicit context lacks. Log those names, never values, once per class. This catches the silent-empty failure. The check needs the walk code, which is one reason the walk is deleted late (PR 7).

## 4. What breaks

### 4.1 Features that work only under legacy today

| Feature | Under explicit today | Proposal |
| --- | --- | --- |

### 4.4 Retained-feature ports (settled 2026-10-19)

Lazy children and upload resume are ported, not dropped. Both ports change ADR-038 decisions D-m and D-g; [ADR-038's 2026-10-19 amendment](../adr/038-explicit-context-and-state-exposure.md#amendment-2026-10-19) records that. The designs are not written yet. Each must meet these prerequisites before its legacy path is deleted.

| Feature | Prerequisites |
| --- | --- |
| `lazy=True` children | An authorization path for the lazy fill: view, handler and object checks run fresh on the fill, as for any server-originated turn (D-l). The child's state is declared (`state()` / providers), never walked. The fill and its result live in shared state, so any node can serve it and an HTTP-only client can poll for it. Tests show the fill works after a transport switch and on another node, and is refused for a revoked session. |
| Upload resume | The resume record (owner, offsets, file identity, expiry) lives in shared storage, not on the connection or the Python view object. It is bound to the session, user, tenant and view, and checked on every chunk. Offsets and ownership are validated server-side. The record holds no undeclared view state. Resume works over HTTP as well as WebSocket. Retention and cleanup are defined. Existing tests to extend: `python/djust/tests/test_resumable_uploads_821.py`, `test_upload_resume_owner_session.py`, `test_exposure_uploads.py`. |

Both depend on the shared-state interface in [2.0-delivery-plan.md](2.0-delivery-plan.md) §5; its API is still open.

## 5. Security notes: do the floors have an explicit equivalent?

| Legacy floor | What it protects | Explicit equivalent | Verdict |
| --- | --- | --- | --- |
| `_FRAMEWORK_INTERNAL_ATTRS` (`live_view.py:108-238`) | Keeps framework configuration and per-connection identity (`request`, `kwargs`, `login_url`, `_django_session_key`, `_websocket_*`) out of `get_state`, snapshots, private persistence, debug output and change detection (#762, #3248) | Projections read only declared descriptors (`_exposure.py:494-510`). Restores accept exactly the declared keyset (`:548-555`), followed by `safe_setattr(..., raise_on_blocked=True)` (`mixins/request.py:1105`). | Equivalent for exposure. **G1 (needs a replacement):** explicit mode still uses the set as (a) the reserved `state()`-name list (`_exposure.py:425-448`) and (b) the change-detection skip list (`websocket.py:436-451`, which runs for explicit views too). Deleting it lets `request = state(...)` register, and turns `_prev_context_fingerprints` / `_changed_keys` into re-render triggers (performance, #2664). PR 10 replaces it with `RESERVED_STATE_NAMES` (the public subset: `request`, `args`, `kwargs`, `view_is_async`, plus the LiveView MRO namespace) and a `CHANGE_DETECTION_IGNORED` set in `change_detection.py`. |
| Sensitive-name floor: `_ALWAYS_EXCLUDED_FIELDS`, `_SENSITIVE_MODEL_METHODS`, prefixes, `_sensitive_field_types()` (`serialization.py:62-101`, resolved at `:280-342`) | Keeps `password`, `is_staff`, `is_superuser` and the session-hash methods out of the Rust render state, the JIT serializers and the sidecar proxies when a model is rendered | None. Explicit views render models through the same path (`mixins/rust_bridge.py:1141-1143`, `:1245-1249`). | **G2 (keep):** it protects deliberate rendering (`context["user"] = request.user`), which ADR-038 D1 allows. Step R anticipates this ("if deliberate rendering still needs a floor, Step R records that and keeps it"). Record it as a survivor. |
| Private-attribute rules: `_x` kept out of context and `get_state`, but persisted via `_user_private_keys`; restore guarded by `allow_private=False` | Context and browser confidentiality for `_x`; no restore into dunder or framework slots | Underscores no longer matter: nothing persists unless declared, and declared names cannot start with `_` (`_exposure.py:25`). | Stronger; no gap. |
| Signed snapshot (`security/state_snapshot.py`): salt, session digest, tenant scope, TTL | Integrity and binding of the browser-held blob (not confidentiality) | `_exposure_snapshots.py`: separate salt; binding to session, user, tenant and route (`_exposure_sessions.py:146-162`); a `created` timestamp; exact-keyset restore | Stronger. **G4:** `get_max_age` (`state_snapshot.py:83-107`) accepts values above 86400 and int-like strings, which `ClientSnapshot` (`_exposure_snapshots.py:57-58`) rejects. So explicit snapshots silently turn off where the service worker still uses the value. Consolidate in PR 3. |
| C304 PII-name warning on views that opt into snapshots (`checks/integrations.py:134-180`) | Defense in depth against PII cached in the browser | None for `client=True` / `persist="client"` fields | **G3:** retarget C304 to declared client grants in PR 4. |
| `_read_exposure_policy` falls back to `"legacy"` (`_exposure.py:211`) | Not a floor | n/a | **G5:** an owner without the attribute, including `None` (`diagnostics_allowed`, `_exposure_diagnostics.py:110-123`), counts as legacy and gets full error details today. Flip the fallback in PR 1 so it fails closed. |

Conclusion: deleting the legacy walk, private persistence and the legacy snapshot removes no protection that explicit mode lacks, provided G1–G5 are handled in the PRs named.
