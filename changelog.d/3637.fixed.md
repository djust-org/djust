- **`sync_turn_wrapper` now covers the authorization checks, `on_mount` hooks, `connected()` / `disconnected()`, the cursor and presence hooks and time-travel replay (#3637).** These sync view hooks ran on the worker thread through a bare `sync_to_async` with no wrapper entry, so an app that opens a per-turn database scope in the wrapper (row-level security) had none of it there; the worst case was `get_object()`, which read no rows, so the object-permission check failed closed as "Access denied" for a caller who was allowed, on the socket only (the HTTP fallback was fine). Two new steps join `SYNC_STEPS`: `"auth"` (`check_permissions()`, Django's access mixins and replayed decorators, handler `permission_required`, and `get_object()` + `has_object_permission()`) and `"lifecycle"` (the `on_mount` chain, `connected()`, `disconnected()`); `handle_cursor_move()`, `update_presence_heartbeat()` and the `get_presence_key()` / `untrack_presence()` reads are `"hook"` steps, a time-travel replay runs its handler as an `"event"` step, and the remaining raw `get_context_data()` / `get_template()` / component-render hops (streamed fragments, sticky-child saves, scoped component render, actor mount, hot reload) are `"render"` steps. The steps are entered at the framework function that calls the hook (`check_object_permission`, `check_view_auth`, `run_on_mount_hooks`, ...), so every transport and every caller (mount, event, `url_change`, embedded and sticky children, HTTP, SSE, API) is covered by one change. Authorization steps fail closed: a wrapper that raises refuses the check, a wrapper that swallows an exception from the check or an `on_mount` hook can no longer turn it into a pass (it raises `PermissionDenied`), and the object-permission cache is written only after the step exits cleanly. `_should_restore_snapshot()`, `_restore_snapshot()` and `_capture_snapshot_state()` (documented subclass overrides) are `"lifecycle"` steps, and an `async def` hook is handed back unwrapped by the step helpers instead of being hidden behind a sync shim (it would otherwise never run once a wrapper was configured). **A wrapper that raises on a step name it does not know (`else: raise ValueError(step)`) fails every mount after this change: make it ignore unknown steps** (example in the turn middleware guide and the 1.3 upgrade guide). An allowlist pin fails when any callable handed to `sync_to_async` / `asyncio.to_thread` / `run_in_executor` is neither stepped, a verified leaf, nor on a reasoned framework-internal list, and when a documented override point has no recorded disposition. New cases in `python/djust/tests/test_sync_turn_wrapper_more_hops_3637.py`.
