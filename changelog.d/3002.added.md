- **`@push_handler`: an explicit marker for a method only server push may call (#3002).** `push_to_view(..., handler="name")` reaches a marked method under any name, and a browser event naming it is refused in every `event_security` mode (`strict`, `warn` and `open`) on the WebSocket, SSE, HTTP POST and HTTP API transports, with the same response as a method that does not exist. The marker is inherited by method name, so an unmarked override of a marked method stays push-only; the new system check `djust.V021` reports such an override (Info), or one that adds `@event_handler` (Warning). It is not an event handler: `djust.V004` no longer suggests `@event_handler` for it, `djust.T019` reports a template binding to it in every mode, and `LiveViewTestClient.send_event` refuses it while the new `send_push` helper delivers it. It cannot be combined with `@event_handler`, `@server_function`, or the decorators server push does not enforce (`@permission_required`, `@rate_limit`, `@debounce`, `@throttle`, `@cache`, `@optimistic`, `@client_state`): each is a `TypeError`. Existing `handle_*` push targets and `@event_handler` methods are unchanged. 31 regression cases in `python/djust/tests/test_push_handler_marker_3002.py`.
