- **Each pytest process now reports its worst generation-2 GC pause and its longest stall in the terminal summary (#3715).** `tests/timing_report.py` (registered in the root `conftest.py`) records gen-2 pauses from `gc.callbacks` and stalls from a 20 Hz daemon ticker thread that notes how late it ran (a thread needs the GIL, so a stop-the-world collection, a native call that holds it, a VM pause or CPU starvation each show up as one late tick), each with the test that was running. Serial runs print one line; under xdist every worker ships its numbers to the controller through `config.workeroutput` and the controller prints one line per worker, so the next timing failure on CI can be attributed from the log. It changes no outcome and no exit code, prints nothing for `--collect-only`, and removes its callback and thread when the session ends. Pinned in `tests/test_timing_report_3715.py`, which runs it through `pytester`, serially and under `-n 2`.
