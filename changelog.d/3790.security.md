- **A model form's values are held to the serialization floor under the native engine (#3790). BREAKING for a template that reads a floor field's value back from a form.** `ModelForm.initial` is `model_to_dict(instance)`, a plain `dict` of strings by the time a template reads it, so the engine's walk never met a `Model` and the model proxy had nothing to refuse. On a `UserChangeForm` bound to a `User`, `{{ form.initial.password }}`, `{{ form.password.value }}` and `{{ form.password.initial }}` printed the password hash while `{{ form.instance.password }}` was empty: the same secret by a different spelling. So did `form.cleaned_data.password` (a disabled field validates to its `initial`), `form.data.password` (and a prefixed form's `u-password`), `form.password.data`, `form.password.subwidgets.0.data.value` (and `form.password.0`, and iterating the field), the `as_text` / `as_textarea` / `as_hidden` renderers (they swap in a widget that prints the value), `{% for f in form %}{{ f.value }}`, `form.visible_fields`, `form.get_context.fields…`, `form.password.form.initial.password`, a `{% with %}` alias of any of these, the `data` / `cleaned_data` / `initial` of a formset over a model, and the same paths as the operand of a `{% load %}`-bridged tag. djust's own `dj_form`, `combobox` and `rich_select` tags drew a `UserChangeForm`'s hash into an `<input value="…">`. The floor is the model's, not the word `password`: `is_superuser`, `is_staff`, `DJUST_SENSITIVE_FIELDS`, a per-model `djust_exclude_fields` and `djust_serializable_fields`, the `djust_serialize_sensitive_fields` opt-out, and the field TYPE floor (`sensitive_field_types`, #1987) are all consulted through the one authority the model proxy uses (`_attr_is_serializable`).

  **Migration (read this if a template stopped showing a checkbox, a flag or a value).** A floor field's value is now missing from a template path, exactly as `{% if user.is_staff %}` already was on the model. `{% if form.is_staff.value %}checked{% endif %}` renders **unchecked**, and re-posting that page would then demote the user. Render the control with `{{ form.is_staff }}` (the widget the form's author chose, unchanged), or read the value in the view and pass it in `get_context_data()`, or opt the field in with `djust_serialize_sensitive_fields` on the model. The first refused read of each field is logged once as a warning naming the field (`User.is_staff … via .value`), so the break is found in the log and not by a user losing a flag.

  The cure is at the chokepoint where the engine reads a path, not at spellings. After the root and after every segment of a path, the engine now calls `djust.serialization._protect_sidecar_walk`, which is `_protect_sidecar_value` plus three arms: a `ModelForm` becomes a floor proxy whose `initial` / `data` / `cleaned_data` are COPIES without the model's floor fields (`data` is matched through its prefix: `u-password`, `form-0-password`; the form itself is never mutated: `initial` is what a disabled field validates against, and a rendered form still saves without clearing the user's password); a formset over a model gets the same for the lists it holds; and the `BoundField` of a floor field becomes a proxy that refuses `value`, `initial`, `data`, `subwidgets` (and indexing or iterating the field) and the three renderers that swap in a value-printing widget. A refused name is a missing name: it renders empty, as `form.instance.password` does. Every other `BoundField`, and every field of a form that holds no floor field, is the real object, byte-identical to before (checked against Django's output for the benign paths). `template_bridge_floor` walks a bridged tag's operand paths through the same function.

  **Policy, stated plainly.** Django itself prints all of these. The floor is the stricter policy djust adds (SECURE_DEFAULTS Pattern 1), and the Django template engine is unchanged by this fix; only the native engine and the bridge's operand walk apply it.

  **The limit: widgets are not blanked.** The floor guards what a template can READ BACK, not what a form DRAWS. `{{ form.password }}`, `{{ form.as_p }}`, `{{ form }}` and a loop's `{{ x }}` render the widget the view author chose: Django's `ReadOnlyPasswordHashWidget` (what `UserChangeForm` uses) shows a summary of the hash and never the hash, but a `TextInput` over the `password` column, or over a `DJUST_SENSITIVE_FIELDS` field, prints `value="…"`. Blanking an editable control would clear it on the next save (measured: a blank or an omitted text control clears the column and an unchecked checkbox demotes the user), so it is not done; tracked in #3797.

  **Components strip a value only when that cannot clobber.** `dj_form`, `combobox` and `rich_select` read `bound_field.value()` in Python (through one function, `_bound_field_value`). A **disabled** floor field (Django ignores what is posted for it: `UserChangeForm.password`) is now drawn without its value. An **editable** floor field (`is_staff`, a `DJUST_SENSITIVE_FIELDS` text field the form posts back) is still drawn with its value, because the alternative is silent damage on the next save; the component logs once, naming the field, that it did. Declare the form field `disabled=True`, or leave it out, to draw it without the value.

  **What a tag is handed.** A bridged tag is the application's own Python (djust's component readers; a third-party form tag), so it is handed the real form and the real `BoundField`, never the proxy. Only a template PATH is floored, so `{% tag x=form.initial.password %}` receives nothing and `{% tag form.password %}` receives the field. The engine therefore has two entry points: `_protect_sidecar_walk` for a path the template spells (`Context::walk_live`, the sidecar walk, the bridge's operand walk) and `_protect_sidecar_value` for an object handed to a tag (`value_into_handler_pyobject`, the handler dict). The Rust side looks the walk function up by name and falls back to the leaf floor when it is absent. The legacy sidecar walk used to hand the raw object on when its floor raised; it now drops the value (the cell renders empty). An extension that predates this fix keeps asking the leaf floor and would lose the form arms silently, so `DjustConfig.ready()` logs an error when `djust._rust.WALK_FLOOR_COVERS_FORMS` is missing: rebuild or reinstall the extension (`make dev-build`).

  **Reach, measured.** A LiveView's own top-level `self.form` attribute was never reachable by these paths (`mixins/rust_bridge.py` leaves a `BaseForm` out of the raw-object sidecar), so there it was not a leak. The exposed shapes were a standalone render (`DjustTemplateBackend`, `render_template`) with a form in the context, a form held by another object in a LiveView (`page.form.initial.password`), and the component tags.

  **What this does not floor.** A plain `Form` (no model behind it: #3799); a typed `PasswordInput` value that is not a model column, such as `UserCreationForm.password1` (#3798); `form.fields.<name>.initial` (a declared or model-default value, never the instance's); a tag author's own Python and a `takes_context` tag reading the context itself; the form's own widget rendering (#3797); an editable floor field in a component; and the Django template engine.

  Regression cases in `python/tests/test_form_initial_floor_3790.py` and `python/tests/test_form_floor_followups_3790.py` (the spelling table for an unbound and a bound `UserChangeForm`, each with a Django-engine control that prints the hash so the comparison is never two empty strings; prefixed, `QueryDict` and formset data; the components; what posting a rendered page back does; what widgets do; the real object handed to a tag; `LiveViewTestClient`, HTTP GET and WebSocket mount). Each mechanism is gate-off tested separately. The code is `_protect_sidecar_walk`, `_SidecarFormProxy`, `_SidecarFormSetProxy` and `_SidecarBoundFieldProxy` in `python/djust/serialization.py`, `_bound_field_value` in `python/djust/components/templatetags/_forms.py`, `protect_sidecar_walk_strict` in `crates/djust_core/src/context.rs`, and `release` in `python/djust/template_bridge_floor.py`. Requires the matching compiled extension (rebuild with `make dev-build`).
