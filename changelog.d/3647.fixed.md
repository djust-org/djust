- **The limits of per-container `dj-update` accumulation are resolved, or documented where they cannot be** — a container that renders its rows through an `{% include %}` is now decided by reading the included file (static names, found the way the renderer finds them, nested includes, `only` and `with` honoured; in the view's own template `./x` is `x` at the template-dir root, as the renderer reads it), so a plain list in an include no longer swallows a removal or an edit in a view that declares `temporary_assigns` for another key; a dynamic name, a missing file, a cycle, a chain over 8 deep or an `{% extends %}` stay as before (assumed to read a key). A `{% with items=rows %}` alias made outside the container, and a context key that holds the same object (`context["feed"] = self.rows`), now count as the temporary key; a `{% with rows=other %}` around the container hides the key there; a `{% if a > b %}` before `dj-update` in the container's tag no longer hides it; a nested container's body belongs to the nested container, so an outer list that is an ordinary attribute stays authoritative. Rows that repeat an `id` in a `prepend` container (the mount render, or one batch) used to produce `MoveChild` patches the client could not apply (`1/N patches failed`); rows are keyed by `id` plus their occurrence number, so each new row is one insert at the front again. The scan no longer goes quadratic on unterminated `{{` (20,000 of them took about 3 s once per class) and is bounded (1,000,000 characters, 1,000 nested elements, 2 s; over any limit the lists are re-rendered whole and a warning is logged); a timeout, an exception or an unreadable included file is not remembered (the next render scans again; one warning per class and cause), while the size, depth and include-count bounds are; its result is dropped by the dev file watcher when any template changes, so an edited template or included file is read again without a restart. Not fixable, and now documented plainly: a value derived from the attribute (`list(self.rows)`), a container whose tag lives inside an included file, and a tag that reads the view without naming the key leave the container re-rendered whole, which on a `temporary_assigns` view keeps only the latest render's rows and lets an unrelated event blank the list.
