- **`dj-track-static` detects a deploy (#2966).** The client compared its
  tracked URLs with themselves, so a deploy that changed asset URLs was never
  noticed. A reconnecting page now sends the URLs it loaded as `track_static`
  on its mount frame (WebSocket and SSE). The server answers with
  `stale_static`: each URL that names an older hashed build of an asset the
  current `ManifestStaticFilesStorage` manifest still has. The client then
  fires `dj:stale-assets`, or reloads for `dj-track-static="reload"`. There is
  no page render, GET or session write. A URL the server cannot judge is never
  reported, so a `"reload"` asset cannot cause a reload loop. Both fields are
  additive, and a page that tracks nothing sends neither. Regression cases in
  `python/djust/tests/test_track_static_stale_2966.py` and
  `tests/js/dj_track_static.test.js`.
