- **Escape inside a dialog could click an unrelated `dj-click` control (#3300).** For any `role="dialog"` the built-in keyboard handling pressed Escape by dispatching the first `dj-click` control it found in the dialog (a Delete or Confirm button, or a Next button that needs its value) when the dialog had no stock close button, and it acted again on keys that a component's own handler had already taken. It now uses only an explicit close control, the stock modal's `.dj-modal__close` or any `dj-click` control marked `data-dj-close`, and leaves a key alone when a handler closer to it has called `preventDefault`. A custom `role="dialog"` that relied on the old fallback should mark its close control `data-dj-close`. The first time Escape finds a dialog with `dj-click` controls but no explicit close control, the console says so (once per page) instead of pressing one. Escape now presses that control with a real click, so the event carries the control's own `data-value`. Djust's own dialogs carry the marker: the ImageLightbox close button (class, tag and Rust handler), the Tour's Skip button, and the theming modal's close button, so Escape closes them and tells the server as before. `data-dj-close` is a marker, not an event argument, and is not sent to handlers.
