- **`theme_context` renders its HTML lazily; its settings values stay eager (#3028).** The processor used to render `theme_head`, `theme_panel`, `theme_mode_toggle`, `theme_preset_selector` and `theme_switcher` on every request that built a `RequestContext`, including JSON views, redirects, admin and pages that never print them (about 23 ms per request with a large pack). Each is now a lazy trusted-HTML object that renders on the first read, once, for the request it was built for. The text a template gets is unchanged (byte-identical across every preset and mode on the Django engine, the Rust renderer and the HTTP page shell), and `theme_preset`, `theme_mode`, `theme_resolved_mode`, `theme_pack`, `theme_presets` and `components_gallery_url` stay plain, eagerly computed values. Nothing is shared across requests, so a CSP nonce or a user's preset never leaks. The five HTML variables are no longer `str` instances; `{{ }}`, `|safe`, `|length`, `{% if %}` and `==` against a string still work, and `str(...)` gives the text. A page that never reads `theme_head` no longer makes django-csp mint a nonce for the response. `djust_theming.E001` stays a Warning, and its docs entry no longer cites the per-request cost. Regression cases in `python/djust/tests/test_theming_lazy_context_3028.py`.
