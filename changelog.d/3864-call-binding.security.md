- **Safe-markup guard: a helper's result is judged with the arguments the call passes** (#3864, #3845). A function of the same file (a `def`, a lambda bound once, or a method of a fresh instance of a plain class) used to be judged with its parameters raw whatever it was given, so `mark_safe(tag(safe_url(x)))` of `def tag(u): return f"<a href={u}>"` and `mark_safe(helper(x))` of a helper that interpolates its argument were cleared, while `f"<p>{bold(escape(x))}</p>"` was flagged. Now the call is also judged with its parameters bound to its arguments: the sink is flagged when the result, for these arguments, is built from a raw value or places an escaper's output in an unquoted attribute; a call's result is clean only in element text, and a bound argument never in an unquoted attribute. Containers that outlive the call, recursion, `*args` / `**kw` and a sink inside a method's own body stay judged with raw parameters. Over the package this proves one audited function (`FeedbackWidgetNode.render`) and flags nothing new. Directed rows with their runtime oracle and a seeded differential generator (source x helper chain x placement, run against hostile payloads) in `python/tests/test_safe_markup_guard_3864.py` and `python/tests/safe_markup_call_fuzz_3864.py`.
