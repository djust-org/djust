- **Rows a view holds now show a handler's database write on every transport (#4112).** Over WebSocket and SSE a QuerySet kept on the view (`self._rows = Model.objects.filter(...)` in `mount()`, the documented pattern), a related-manager QuerySet held from `mount()`, or a `cached_property` listing rows kept answering with the rows from before the write; 1.3 behaved the same. djust now records the tables each step of the view writes (any step: an event handler, `async def` or not, `mount()`, `handle_params()`, `start_async` / `@background` work, `handle_tick()`, a server push, `handle_info()`, the connection hooks, a component's handler; on any database alias) and the tables the view's own code and renders read (lazy foreign keys, prefetches and per-row queries included; djust's own session and user checks excluded). When both are known and share no table, nothing changes: a handler that only wrote elsewhere still answers `noop`. Otherwise every QuerySet and `cached_property` the view holds is read again, once, before its next render, and the turn renders even if nothing else on the view changed. A write is known only in the exact single-table shapes the ORM emits; anything else (raw SQL with unquoted names, `TRUNCATE`, `MERGE`, `WITH`, several statements), a read djust cannot follow, held values not filled by a recorded render and a restored state make the decision "read everything again" (logged at DEBUG by `djust._held_rows`). A model instance (its prefetched relations included) and a list of rows stay snapshots on every transport. Writes the database makes by itself (triggers, `ON DELETE CASCADE`, a model over a database view) cannot be seen: `DJUST_REFRESH_ON_ANY_WRITE = True` makes every write refresh, and the new Info check `djust.C042` names unmanaged models and `DB_*` cascades while it is off. `self.rows_changed(*models_or_tables)` marks the view by hand for a write made outside its steps (a thread or task the handler started, an `on_commit` callback, another process); such a write shows on the view's next render, nothing is sent by itself. A sticky or embedded view whose neighbour wrote re-reads on its own next render. The mark is kept until a render of the view succeeds, and a mark made while that render ran survives it.
