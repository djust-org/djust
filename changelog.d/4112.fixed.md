- Rows a view holds now show a handler's database write on every transport (#4112). Over WebSocket and SSE a QuerySet kept on the view (`self._rows = Model.objects.filter(...)` in `mount()`, the documented pattern), a `cached_property` listing rows, or a model loaded with `prefetch_related` kept answering with the rows from before the write; 1.3 behaved the same. Now a step that runs any statement other than a read (an event handler, `async def` or not, `@background` / `start_async` work, `handle_tick`, a server push, `handle_info`, a component's handler; on any database alias) makes the view's next render read those rows again, once, and the turn renders even when the handler changed nothing on the view. A turn that wrote nothing adds no query. Lists of rows and model instances stay snapshots; `frozen_rows = ("name",)` keeps a QuerySet or `cached_property` as first read. The HTTP fallback's prefetched-model case, stale there too, is fixed with it.
