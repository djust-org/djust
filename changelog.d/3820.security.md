  What the guard learned, each rule shown by a dirty shape and its clean twin in `python/tests/test_safe_markup_guard_3820.py`: **flow** (`width = int(width)` leaves `f"{width}"` clean; a coercion in only one branch, past a `continue` / `break`, in a loop that comes back round, in a `try` body whose handler runs, in a `with` that can swallow, after a `+=` / `append`, in a closure, `global`, `:=`, `finally`, `import` / `match` rebinding or beside `locals()` does not); **narrowing** (`x in CONSTANT`, `x == "a"` and `isinstance(x, int)` clear `x` on the branch where they hold, from either edge; a mutated or non-literal collection, the wrong edge and `assert` clear nothing); **the project's escapers**, trusted by the module that DEFINES them, never a re-export or a same-named twin (`safe_url`, `url_attr`, `srcset_attr`, `attr_name`, `escape_json_for_script`; `safe_css_color` / `_length` / `_ratio` / `_number` when their `default` is clean; the record builders `upload_attrs`, `voice_extras`, `map_picker_attrs`, `pad_extras`, `cropper_extras`, `menu_attrs`, `clamp_columns`, `clamp_cells`, `rich_html`, `render_markdown`), each pinned by a hostile-payload test of its contract, plus relative-import resolution and an escaper imported two ways in one file being trusted nowhere; **class tables** (`self.ICONS.get(k, "")`), **`d.get(k, DEFAULT)`**, **calls to a helper the file defines** (judged by what it returns, with its parameters raw), `sum` / `max` of clean values and comprehensions of them, and **the block body of a Rust handler's `render(self, args, content, context)`**, which the engine hands over as a `SafeString` (checked against the compiled engine).

  Found while teaching it: `TABLE.get(key, default)` was judged by the table only, so a raw `default` came out clean (no site in the tree used it). Fixed, and pinned with the rule switched off. Three tag modules (`_advanced.py`, `djust_components.py`, `_forms.py`) imported `safe_url`, `_dev_tools.py` imported `conditional_escape` and three call sites imported `escape_json_for_script` through a re-export, which the guard rightly did not trust (the #3774 lesson); they import from the defining module now, and `TestNoEscaperIsImportedThroughAReExport` is the lint that finds the class without running the guard. A test also fails when a new function whose body is one call of a sink on its own parameter is not named a sink.

  The flow analysis is checked against real execution: a differential fuzz generates random functions (assignments, coercions, `if` / `for` / `while` / `try` / `with`, `break` / `continue` / `return`, narrowing, local helpers), runs them with a marker as the raw value, and fails when a `mark_safe` that received the marker was not flagged (no false negative in 40 000 programs across 16 seeds). Twelve deliberately broken analyses (a loop that forgets its `break` / `continue` states, an `if` that follows one branch, a merge that keeps the first path, narrowing on the wrong edge, an `assert` that narrows, an exception that sees only the state before the `try`, a helper that is always clean, ...) are each caught by the fuzz or a directed row. The payload sweep now also drives the Rust-native handlers (`handler.render(args, [content,] context)` with the payload in every operand, flags both ways) and parses what they print.
