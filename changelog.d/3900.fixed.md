- **A `Component`'s hybrid `template` now follows the same attribute rule as the Rust instance and `_render_custom()` (#3900).** `Component.render` draws a class that has a `template` through it when the crate constructor refuses a value (a lazy string, `gettext_lazy` / `format_lazy`, is one) and always when the class has no crate counterpart (`ButtonGroup`, `Checkbox`, `Input`, `Offcanvas`). That path wrote `{{ src }}` into an attribute with no URL check and only autoescape, which leaves a marked-safe value alone, so `Avatar(src=<lazy "javascript:alert(1)">)` printed a live script URL where the plain string printed `<img src="#">`, and a lazy `size` / `status` could leave its attribute. Every `{{ ... }}` inside a start tag of a hybrid template is now escaped whatever it is marked as, and in a URL attribute (`href`, `src`, `action` ...) checked against the scheme allowlist with the helpers the other paths use (`data_url_attr`). The template is read once per template string (cached), not listed per class, so it covers the 19 shipped hybrid classes and a template you write yourself. Behaviour change for your own hybrid components: a marked-safe value in an attribute is escaped (the browser decodes it, so the value it reads is unchanged) and a script-scheme URL becomes `#`. Text between tags and values that are not text (numbers, `None`) are unchanged. A URL read from a `{% for %}` / `{% with %}` variable, a dotted path or through a filter is escaped but its scheme is not checked (it is not in the context to be judged); no shipped template has one. The sweep in `test_marked_safe_attribute_sweep_3898.py` no longer sets the hybrid cells aside: it drives every template class through the template, and its reach test accounts for each parameter.
