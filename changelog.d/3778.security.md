- **`_rust.serialize_context` ran `render()` on any object and four `get_*` methods on any model, with no call guard, and shipped `password`, `is_superuser` and `is_staff` of a model (#3778).** The Rust function (`serialize_python_value` in `crates/djust_live/src/lib.rs`) is a public `#[pyfunction]` that no production path calls: a `git grep` over `python/djust`, `examples`, `benchmarks` and `scripts` finds only the Python helper of the same name in `djust.template.serialization` (a different function), every importer of `djust._rust.serialize_context` is a test, and a spy on it records zero calls across a `DjustTemplateBackend` render and a LiveView mount. So the exposure was a caller who hands it an object, not a template author. Reproduced first against the real call path: a `render` carrying `alters_data` still ran, a `get_username` marked `alters_data` deleted the row (`User.objects.count()` 1 -> 0), `get_absolute_url` marked `do_not_call_in_templates` ran, and the model's dict contained `password`, `is_superuser` and `is_staff` because the arm built it with `model_to_dict` and never asked the serialization gate (the one `serialize_queryset` asks since #2685). The issue named the calls; the floor bypass was found by running it.

  Both arms now follow the rule the queryset serializer follows. Every call goes through `djust_core::template_call_guard` (#3772): a `render` or `get_*` that carries `do_not_call_in_templates` or `alters_data` is not called, a refused `render` falls back to `str(obj)` and a refused `get_*` is left out. Every model field and method name goes through the serialization gate (`djust.optimization.codegen.emittable_names`), so the floor, `DJUST_SENSITIVE_FIELDS` and the per-model allow and deny lists apply, and a name it refuses is dropped before the method behind it can be called. If the gate is missing or raises the model is `str(obj)`; if the gate fails internally it permits no names and the model ships as an empty dict. It is never an ungated dict. The gate call is now shared with the queryset serializer (`permitted_among`), not copied. A callable with neither marker is still called, so the output of an ordinary model and component is unchanged.

  Decision: guarded, not deleted. The function is listed in `_rust.pyi` and `docs/TYPE_STUBS.md`, so removing it is a public-surface call for a maintainer; with no production caller, deleting it later is a pure removal and is tracked as the follow-up on #3778. The stub also declared a `field_paths` argument the function never took; it now matches the signature and describes the guard. Regression cases in `python/tests/test_serialize_context_guards_3778.py`: a component whose `render` deletes rows, each of the four `get_*` names under each marker, the floor fields, a configured sensitive field, a per-model allowlist and exclusion, a nested model at every container depth, and a gate that raises.
