- **A late storage failure on an explicit save no longer reaches the `asyncio` log with its message and traceback on Python 3.14.** The save deadline waited with `wait_for(shield(save))`; since 3.14, `asyncio.shield` hands the exception of a shielded future whose waiter has gone to the event loop's exception handler, so a save that outran its deadline and then failed was logged a second time, with the storage exception's text, next to the runtime's own value-free warning. The deadline now waits with `asyncio.wait`, which leaves the save running and observes nothing, so the runtime's warning is the only report. The supported-Python test matrix is also green again on CPython 3.13.15 and 3.14.7: the pinned `striptags` reference records the `html.parser` change to abruptly closed empty comments (`<!-->`, `<!--->`) that those patch releases made, and the Unicode sweep of the `title` filter pins the 52 code points that Unicode 16.0 (CPython 3.14) made cased and the filter's 15.x tables do not know.
