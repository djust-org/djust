- **Push scopes are tenant-scoped for tenant views.** The group of a `push_scope` now includes the tenant, so two tenants that use the same room name or document id each have their own: a `TenantMixin` view joins the scope groups of its own tenant, and `push_to_view(..., scope=...)` / `apush_to_view` take `tenant=` (a tenant id or a `TenantInfo`), defaulting to the tenant bound to the running context. A push to a view that is not tenant-scoped is unqualified, and group names for such views are unchanged. A tenant view whose tenant did not resolve receives no scoped push, and a scoped push to a tenant view with no tenant reaches none; each logs one warning. Push hooks, `handle_info` and the `start_async` work they queue now run with the view's tenant bound, as event handlers do. From a Celery task or management command, pass `tenant=`. During a rolling upgrade, pods on the old and new versions name a tenant view's scope groups differently until the old pods are gone.
