- **Form fields are filled with a new `--input-background` token, not the `--input` border colour.** `--input` is the field border (`.border-input`, the shadcn convention), but `components.css` (`.form-input`, `.form-select`, `.form-textarea`, `.form-checkbox`, `.form-radio`, `.table-search`, `.data-table-search input`, `.data-table-filter`, `.data-table-cell-editing input`, `.data-table-row-editing td input`, `.multi-select-search`, `.otp-digit`, `.number-stepper-input`, `.tag-input-field`, `.dj-search-input__input`) and the generated Bootstrap overrides (`.form-control`, `.form-select`) used it as the fill, so a preset with a mid-slate border painted every field slate with dark text on it. The theme generator now emits `--input-background` for every preset in light and dark mode (default: the page `--background`; `ThemeTokens.input_background`, `bg-input-background` in Tailwind), and those rules read it with a `--card` fallback. A test fails on any djust CSS, static or generated, that fills with `--input`, and every preset's field text is gated at 4.5:1 on the new fill. Field outlines now read `--input`, the input-border token, instead of the `--border` divider token, as `hsl(var(--input, var(--border)))`: the same field rules plus `.number-stepper-controls`, and the pack `.form-control` / `.form-select` (`.data-table-cell-editing input` keeps its `--ring` edit border; the stepper's inner dividers keep `--border`). A test pins each outline to `--input`, and `--input` is gated at 3:1 on `--input-background` (WCAG 1.4.11) for every preset and mode, with the shipped presets' documented `--input` exemptions still honoured.
