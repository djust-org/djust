- **The stateless HTTP fallback POST now runs `handle_params()` and `start_async` work** (#3624). With `view_state_in_session: False` (and whenever the fallback rebuilds the view with `mount()`), the POST called `mount()` but never `handle_params(params, uri)`, so a page that read its URL there met the event with its defaults and answered with a diff that removed the rows the user was acting on; it also discarded `start_async` / `@background` work, so a page that loads after its first render kept its loading state on every POST. The fallback now calls `handle_params()` after `mount()` with the POST's query string (one shared helper with the GET), and runs queued background work inside the request, before the answer is rendered, through the dispatch the socket and SSE share. The one-off "background work does not run" warning is gone. Refs #3503: its `push_event` / `set_layout` / `defer()` gaps were already closed by #3541; new tests pin that every queue a view can fill reaches the HTTP answer.
