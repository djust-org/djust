- **A QuerySet inside a dict or a list of dicts renders its related rows on a LiveView, `{{ u.groups.all.count }}` / `.all.exists` / `.all.first.name` render instead of empty, and a called `all` has a row cap (#3788).** Three same-symptom paths #3785 (the #3777 fix) did not reach, each re-measured against the real render path before the fix. (1) `{"d": {"users": qs}}` with `{% for g in x.groups.all %}` rendered empty while `{{ x.username }}` worked: `get_context_data` only read the template when a TOP-LEVEL value was a Model / QuerySet, and the JIT looked its paths up by the dotted name `d.users`, which the extraction map (keyed by root name) does not have, so the value fell to the flat field-dict serializer. The template source is now read on the first nested DB value (a context with none pays one `type()` lookup per value, not a template read), a dotted name resolves to its root's paths without the leading segments (`_paths_for_variable`, one resolver for the QuerySet, model and model-list producers), a list of dicts is walked like a dict, and the generated serializer's function name is sanitised (`serialize_d.users_…` did not compile). The same lookup fixed a Model and a model list inside a dict beside a top-level QuerySet, which rendered `{{ d.user.username }}` empty from the identity-only map. (2) `all` read only through QuerySet methods is shipped as `{"count": n, "exists": b, "first": {...}, "last": {...}}`, each method run on the QuerySet `all()` returned (`COUNT`, `EXISTS`, `LIMIT 1`) under the one call guard, a `first` / `last` row through the serialization floor (and, when the row is also read whole, `{{ u.groups.all.first }}` beside `.first.name`, carrying the `__str__` a serialized model carries, so it prints its text rather than a dict). The tree cannot tell `u.groups.all.count` from `{% for i in o.items.all %}{{ i.count }}`, so the method reading is used only when the template does not read the relation as rows (a whole-path mark, `with_whole_marks` / `ALL_WHOLE_KEY`), every child is a method name, and the row model has no attribute of that name. Rust (`serialize_all_methods`) and the Python codegen twin (`all_methods_value`) are compared in `test_rust_and_codegen_ship_the_same_methods`; the codegen `all` step now also honours `alters_data` / `do_not_call_in_templates`, as the Rust one does. (3) `LIVEVIEW_CONFIG["queryset_all_row_cap"]` (default 100,000; `0`, or any value of 2**62 or more, removes it; `None` is the same as unset, i.e. the default; a non-integer is logged and replaced by the default) bounds the rows read through a called `all` (`qs[:cap + 1]`: a SQL `LIMIT` on an unevaluated relation) in both serializers, logs a warning when a relation is cut, and never applies to `.count` / `.exists` / `.first` / `.last`. A container is searched four containers deep; below that the QuerySet is left as the view built it, a flat field dict, so its relations render empty with no error. The cap bounds the work the serializer does, not memory: the optimizer still prefetches the whole relation first. Not fixed, tracked at #3801: a template that reads the same `.all` as rows AND through a method still renders the method empty on a LiveView (a loop next to `.all.count`, `{{ u.groups.all|length }}/{{ u.groups.all.count }}`, `{% if u.groups.all %}{{ u.groups.all.count }}`, `{% with gs=u.groups.all %}{{ gs.count }}`, `|slice` plus `.count`); a model with a `count` / `exists` / `first` / `last` field keeps `all` a list of rows, so `.all.count` stays empty there, and on a `list[Model]` the Python serializer drops a row's integer `count` / `exists` field (pre-existing); `{{ g }}` beside `{{ g.name }}` inside a loop over `.all` prints a dict (pre-existing, the loop's iterable cannot be told from a whole read); the extractor erases the index of `.all.0.name`; the relation prefetch loads all rows regardless of what the serializer ships; and a leaf-only `all` runs `str(row)` for every row. Pinned through `DjustTemplateBackend`, a LiveView mount, an event re-render, an HTTP GET and a WebSocket mount, with Django's engine as the control (`python/tests/test_queryset_all_followups_3788.py`).
