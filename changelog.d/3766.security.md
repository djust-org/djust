- **`{% theme_icon %}` no longer writes `size` into the markup it marks safe (#3766).** `theme_icon(name, size=20)` built each icon with an f-string that interpolated `size` and returned it under `mark_safe`, the banned `mark_safe(f'...')` with an interpolated value: `{% theme_icon 'check' size=u %}` with `u = '1" onload="alert(1)'` printed `<svg width="1" onload="alert(1)" ...>`, an attribute injection whenever `size` holds user-influenced data (a literal `size=16` was inert, which is why nothing showed it). `size` is now validated and the markup is built with `format_html`. A number above zero and at most 1000 with up to three decimals, optionally followed by `px`, `em`, `rem`, `ex`, `pt` or `%`, is accepted as an `int`, `float`, `Decimal`, a digit string or a lazy string (`16`, `"16"`, `1.5`, `"24px"`, `"1.5rem"`) and is re-printed from its parsed value (`"016"` and `16.0` both print `16`); every size that worked before prints byte for byte what it printed. Anything else (a quote, `>`, an entity, whitespace, a sign, an exponent, a `bool`, zero, a negative, a huge number, a non-number) renders the default size `20` and logs a `WARNING` (the value's type, never its content), and never raises, the way a disallowed URL renders `#` in the sibling tags; `size=None` means "not given" and renders the default silently. `theme_icon` has no Rust tag handler of its own (`djust.theming.rust_handlers` registers the `theme_tags` tags only), so both engines run this one function, and the tests drive it through both. Sweeping `djust/theming` for the same shape found one more site, the gallery's tooltip example (`mark_safe(f"<button>Hover ({position})</button>")`, a constant from a literal tuple), now `format_html`. Regression cases in `python/tests/test_theme_icon_size_3766.py`, including `TestNoInterpolatedMarkSafeInTheming`, which derives from the source (an AST walk of every file under `djust/theming`) that no `mark_safe` call takes an interpolated string.
