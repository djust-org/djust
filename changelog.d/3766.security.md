- **`{% theme_icon %}`, `{% theme_form %}`, `{% theme_form_errors %}` and the inline theme switcher no longer write a raw value into markup they mark safe (#3766).**

  `theme_icon(name, size=20)` built each icon with an f-string that interpolated `size` and returned it under `mark_safe`, the banned `mark_safe(f'...')` with an interpolated value: `{% theme_icon 'check' size=u %}` with `u = '1" onload="alert(1)'` printed `<svg width="1" onload="alert(1)" ...>`, an attribute injection whenever `size` holds user-influenced data (a literal `size=16` was inert, which is why nothing showed it). `size` is now validated and the markup is built with `format_html`. A number above zero and at most 1000, with at most three decimals, optionally followed by `px`, `em`, `rem`, `ex`, `pt` or `%` in any case, is accepted; an `int`, `float` or `Decimal` is rounded to three decimals first (so a computed `14 * 1.1` prints `15.4`), any other type is read by its text. Anything else renders the default size `20` and logs one `WARNING` per call (the value's type, never its content; an icon rendered in a loop logs once per icon), and does not raise: that includes a value whose `__str__` raises and an int over Python's 4300-digit limit, both of which used to propagate. `size=None` means "not given" and renders the default silently. `theme_icon` has no Rust tag handler of its own (`djust.theming.rust_handlers` registers the `theme_tags` tags only), so both engines run this one function, and the tests drive it through both.

  What changes for a size that worked before: it prints what it printed when it is an int, or text of the form `16` / `1.5` / `24px` / `1.5rem` with a lower-case unit. Deliberate differences: the number is re-printed from its parsed value (`16.0` prints `16`, `"016"` prints `16`, `"1.50"` prints `1.5`); a unit is lower-cased (`16PX` prints `16px`); a `float` or `Decimal` is rounded to three decimals (`Decimal("1E+2")` prints `100`, `0.1 + 0.2` prints `0.3`); and a size outside the range now renders `20` with a warning (a number over 1000, such as `1001` or `1234.5`; zero or less; a float that rounds to zero, such as `0.0001`; a type whose text is not a plain number, such as `Fraction(3, 2)`). Everything else a hostile or malformed value can be (a quote, `>`, an entity, whitespace, a sign, an exponent, a `bool`, a very long string) renders `20` too.

  The same class, found in review where the first guard could not see it, because the value never sat inside `mark_safe(<f-string>)`: `theme_form` and `theme_form_errors` (`theme_form_tags.py`) appended f-string lines holding the configured `css_prefix` and `BoundField.id_for_label` (built from the FIELD NAME, the form `prefix` and `auto_id`) to a list and marked the join safe, so a form with a field named `a" onfocus="alert(1)" x="` printed `<label for="id_a" onfocus="alert(1)" x="" class="theme-label">`; every line is now a constant or `format_html`. The `{{ theme_switcher }}` chunk (`context_processors._render_theme_switcher`, marked safe by `LazyThemeHTML`) printed `preset["name"]` and `preset["display_name"]` into `<option value="...">` unescaped; they are escaped now (`&`, `<`, `>` and `"`; the apostrophe is left alone, because both places sit between double quotes or in text and the built-in preset `Synthwave '84` keeps its bytes, so a name containing `&` prints `&amp;`, which a browser shows unchanged). `_passthrough_attrs` joined `name="value"` parts built with an f-string; `name` is validated first so it was inert, and it is `format_html` now with the same output. The gallery tooltip example (`python/djust/theming/gallery/context.py`, a constant from a literal tuple) is `format_html`. A benign form renders byte for byte what it did (40 renderings across prefix, layout and form, captured before the change, are pinned in `python/tests/test_theme_markup_escaping_3766.py`).

  The guard is `scripts/lib/safe_markup_taint.py`, tested in `python/tests/test_safe_markup_guard_3766.py`. It is **name-based and single-function**: it reads the syntax tree one function (or the module body) at a time, does no type inference, and never follows a call into another function. It follows a value through local variables, tuple unpacking, `:=`, containers (`d[k] = ...`, `.append`, `.extend`, `.insert`, `+= [...]`), list / dict / generator comprehensions, `+=`, `join`, `%`, `+`, `.format`, `.format_map` and `Template.substitute`, to a `mark_safe` / `SafeString` / `SafeText` call under any alias, or to the format string of `format_html`. What counts as an escaper is decided by where the name comes from, not how it is spelled: `escape`, `conditional_escape`, `format_html` and `format_html_join` imported from `django.utils.html`, `html.escape`, and `int` / `float` / `bool` / `len` clean a value; `re.escape`, `shlex.quote`, an `escape` imported from anywhere else, and a locally defined `def escape(v): return v` do not. `min` / `max` / `round` / `abs` / `str` of clean arguments, `uuid.uuid4().hex`, `secrets.token_hex`, an f-string field with a numeric format spec (`{n:.2f}`), an `enumerate` index and `.render(...)` output (trusted by method name) are clean. It flags the pre-fix `theme_icon`, `theme_form`, `theme_form_errors` and `_passthrough_attrs`, which the earlier literal-shape check did not, and flags nothing under `djust/theming` now (the audited allowlist is empty).

  What it does not see, probed and pinned in `KNOWN_MISSES` of its test: anything that crosses a function (a string built in one function and marked safe in another, a module global appended to in one function and joined in another, a value stored on `self`, a helper that returns an interpolated string); `mark_safe(param)`; a sink reached without a call to it by name (`partial(mark_safe, ...)`, `map(mark_safe, ...)`, `getattr(safestring, "mark_safe")(...)`); `functools.reduce` over raw items; and any builder not listed above. In particular the inline theme switcher (`preset_options += f"..."` inside `_render_theme_switcher`, marked safe by `LazyThemeHTML` elsewhere) is protected by its own tests in `python/tests/test_theme_markup_escaping_3766.py`, not by the guard. `build_theme_head_context` builds the `<style>` / `<link>` blocks that `ThemeMixin` marks safe; that was read, not machine-checked.
