- **A view's state is saved server-side between requests again, as in 1.x; client exposure stays explicit.** After the page load and after each event that changed it, a page view's state is saved in the server-side session: its public attributes, the `_private` attributes `mount()` created, its `state()` fields and the state of the components it holds. Over the HTTP fallback a later request rebuilds the view from that state and does not run `mount()` again, then runs `handle_params()` and `handle_restore()`; what a handler set goes back over `handle_params()`'s defaults. Over a socket, a mount or reconnect runs `mount()` and puts back only what a handler changed since `mount()`, so what `mount()` computes (a permission flag, a loaded model instance) is fresh on every socket mount. A full page load runs `mount()` and starts a new saved state. No declaration is needed, and nothing becomes renderable or client-settable by being saved: the template, the client state, signed snapshot tokens and debug payloads still come from `state()` declarations and `get_context_data()` only. Differences from 1.x, each deliberate: one saved state per tab (the page carries a tab id; two tabs on one route no longer share state; at most 8 per route are kept); every plain Python value comes back with its type (tuples, sets, `Decimal`, dates and times, `UUID`, bytes, enum members); a value that cannot be saved (a queryset, the request's user, an arbitrary object) is skipped with one WARNING on the `djust.automatic_state` logger instead of being turned into a string, and makes the next fallback request run `mount()` again so it is re-created; saved state past 512 KB per view (`DJUST_AUTOMATIC_STATE_MAX_KB`, `automatic_state_max_kb`) refuses the event's change whole, with a warning from 100 KB (`DJUST_AUTOMATIC_STATE_WARN_KB`), and is never saved in part; the store is bound to the session, user, tenant and route and expires with `DJUST_SERVER_STATE_MAX_AGE`; password, one-time-code and payment-card form inputs are never stored. A model instance is saved as a dict of its fields, as in 1.x. The new `state(..., persist=False)` keeps a field out; `persist="server"` keeps its strict behaviour and stays per route. `djust.V029` now reports only a handler that reads and then changes a `persist=False` field. A view on the deprecated `exposure_policy = "legacy"` saves nothing. (#4107, #4106)
