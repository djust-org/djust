- **A view's state is saved server-side between requests again, as in 1.x; client exposure stays explicit.** After the page load and after each event that changed it, a page view's state is saved in the server-side session: its public attributes, the `_private` attributes `mount()` created, and its `state()` fields. Over the HTTP fallback a later request rebuilds the view from that state and does not run `mount()` again, then runs `handle_params()` and `handle_restore()`; over a socket `mount()` runs and the saved state is put back over it; a full page load runs `mount()` and overwrites what was saved. No declaration is needed, and nothing becomes renderable or client-settable by being saved: the template, the client state, signed snapshot tokens and debug payloads still come from `state()` declarations and `get_context_data()` only. Differences from 1.x, each deliberate: every plain Python value comes back with its type (tuples, sets, `Decimal`, dates and times, `UUID`, bytes, enum members; 1.x turned tuples into lists and `UUID`s into strings); a value that cannot be saved (a queryset, the request's user, an arbitrary object) is skipped with one WARNING on the `djust.automatic_state` logger instead of being turned into a string, and makes the next request run `mount()` again so it is re-created; saved state past 512 KB per view (`DJUST_AUTOMATIC_STATE_MAX_KB`, `automatic_state_max_kb`) refuses the event's change whole, with a warning from 100 KB (`DJUST_AUTOMATIC_STATE_WARN_KB`), and is never saved in part; the store is bound to the session, user, tenant and route and expires with `DJUST_SERVER_STATE_MAX_AGE`; password, one-time-code and payment-card form inputs are never stored. A model instance is saved as a dict of its fields, as in 1.x. The new `state(..., persist=False)` keeps a field out; `persist="server"` keeps its strict behaviour. `djust.V029` now reports only a handler that reads and then changes a `persist=False` field. A view on the deprecated `exposure_policy = "legacy"` saves nothing. Not restored from 1.x in this change: components' own state. (#4107)
