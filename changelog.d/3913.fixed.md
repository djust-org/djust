- **The inline `template` of a `LiveComponent` and of a class-level (`BoundComponent`) component gets the attribute rule of the hybrid `Component` template (#3913).** All three draw their `template` string through one helper, `_render_inline_template` (`components/base.py`), which applies `djust.components._hybrid_attrs.harden_context` before the engine; an AST census of the package fails when another site renders a component's inline template (under any spelling: an alias, another module, a direct `Template(...).render(...)`). So every `{{ ... }}` in the value of an attribute is escaped whatever the value is marked as (a marked-safe string, a lazy one, an object whose text form is marked safe, a callable the engine calls; also `|safe` and under `{% autoescape off %}`), a URL attribute (`href`, `src`, `action` ..., and the `dj-navigate` / `dj-patch` / `dj-patch-reload` directives) is judged with the scheme allowlist on the whole value as it is assembled, and the text of `<textarea>`, `<title>` and HTML comments is escaped (#3914). **Behaviour change for existing inline templates, measured over a corpus of 9,950 renders (118 differ):** (1) a scheme outside the allowlist in a plain-name URL slot becomes `#` (`href="{{ url }}"` with `javascript:alert(1)`, and `sms:`, `whatsapp:`, `zoommtg:`, `webcal:`, `geo:`, `slack:`, silently; the no-op `href="javascript:void(0)"` / `javascript:;` is kept, in an `href` only, so in an `<img src>` or `dj-navigate` it becomes `#`); (2) a marked-safe value, or a plain value written with `|safe`, in an attribute, in `<textarea>`, in `<title>` or in a comment is escaped (`title="{{ v|safe }}"` with `mark_safe('{"a": "b"}')` printed the quotes raw, ending the attribute, and now prints `&quot;`; `mark_safe("a &amp; b")` prints `a &amp;amp; b`, so pass plain text); (3) a number or date in an attribute prints in its canonical form (`2026-01-02`, `33.5`, not `Jan. 2, 2026` / `33,5`). **Not changed**: `<script>`, `<style>`, `<xmp>`, `<noscript>` ... keep the author's markup (`<script>var cfg = {{ cfg|safe }};</script>` stays JSON; use `json_script` or a `data-*` attribute to put data in a page); relative, `http(s):`, `mailto:`, `tel:`, fragment and query URLs, ids, `component_id` and every ordinary value render byte for byte as before; a text slot keeps a marked-safe value's markup. **Also fixed: `{% blocktranslate %}` / `{% blocktrans %}` in an attribute** (`aria-label="{% blocktranslate %}Delete {{ item }}{% endblocktranslate %}"` printed `Delete ` because the rewrite renamed the catalog-keyed variable; the mechanism came in with #3915 for the hybrid `Component`). A translation block's body is now never rewritten, and what it prints is escaped once (a variable it reads from the context is escaped around it, a `with` argument gets `|force_escape`, a `count` argument is left alone); it works on both engines, for plural, `with`, `trimmed`, `context` and `asvar`, in an attribute and in `<textarea>` / `<title>` / a comment. A block in a URL attribute is escaped, not scheme-checked. What is escaped but not scheme-checked (a URL whose slot is a dotted path, a filtered expression or a `{% for %}` / `{% with %}` variable, a translation block; an unquoted value), the slots of an `{% include %}`d partial (neither escaped nor checked), a tag that prints text inside `<textarea>` / `<title>`, and shapes the scanner cannot follow like a browser does are named by one warning per component class (class, tag/attribute/element names, shape names and a count; never an attribute value or anything from the context; an attribute name is template text and is logged, so keep names static in a template built per instance). An `{% include %}` of a literal name that the loaders find and that holds nothing to harden is no longer reported. Two behaviours: a callable in a URL slot is called when the context is prepared, even if its branch does not render (it must be judged first), where a callable in `<textarea>` / `<title>` text is called only where the engine reaches it. Not changed: a `template_name` file (loaded by the project's loaders; #3933) and a LiveView's own `template`. See the components guide.
