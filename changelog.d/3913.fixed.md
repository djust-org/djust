- **The inline `template` of a `LiveComponent` and of a class-level (`BoundComponent`) component gets the attribute rule of the hybrid `Component` template (#3913).** All three draw their `template` string through one helper, `_render_inline_template` (`components/base.py`), which applies `djust.components._hybrid_attrs.harden_context` before the engine; a test pins the one caller. So every `{{ ... }}` in the value of an attribute is escaped whatever the value is marked as (a marked-safe string, a lazy one, an object whose text form is marked safe, a callable the engine calls; also `|safe` and under `{% autoescape off %}`), a URL attribute (`href`, `src`, `action` ..., and the `dj-navigate` / `dj-patch` / `dj-patch-reload` directives) is judged with the scheme allowlist on the whole value as it is assembled, and the text of a raw-text element is escaped (#3914). **Behaviour change for existing inline templates**: before, `<a href="{{ url }}">` with a state value `javascript:alert(1)` printed it as written, and a marked-safe value could leave its attribute. Now a scheme outside the allowlist (`javascript:`, `data:` for a link, `sms:`, `magnet:` ...) becomes `#` (the no-op `href="javascript:void(0)"` / `javascript:;` is kept, in an `href` only), a marked-safe value in an attribute is escaped again (`mark_safe("a &amp; b")` prints `a &amp;amp; b`; pass plain text), and in an attribute a number prints in its canonical form and a date in its ISO form (`2026-01-02`). An ordinary template is unchanged: a corpus of relative, `http(s)`, `mailto:`, `tel:`, fragment and query URLs, titles, ids and `component_id` renders byte for byte as before. What is escaped but not judged (a URL whose slot is a dotted path, a filtered expression or a `{% for %}` variable; an unquoted value), a tag that prints text inside a raw-text element, and the templates named by an `{% include %}` / `{% extends %}` (not scanned) are named by one warning per component class (class and tag / attribute names only, never template text or a runtime value). Not changed: a `template_name` file (loaded by the project's loaders) and a LiveView's own `template`. See the components guide.
