- **`WizardMixin` can resume stored progress (#3965).** `mount()` always started at step 0 with nothing answered, so a reload or a reconnect that mounted the view again lost the person's place. `get_wizard_initial()` (`{step_name: {field: value}}`) and `get_wizard_step()` (an index or a step name) are now called by `mount()`; the defaults return `{}` and `0`, so a wizard that overrides neither behaves as before. Values are stored as the text the browser would submit (wizard state is JSON), steps and fields the wizard does not declare are ignored with a warning, a step that does not exist starts at the first one, and every step before the one resumed counts as completed (so `go_to_step` can return to it; `next_step` and `submit_wizard` still validate). `on_step_saved(step_name, data)` runs when `next_step` has validated a step, just before the wizard moves on, so "save on every step" does not need an overridden handler; a hook that raises leaves the person on the step. Not added: `wizard_step_param` (URL-synced step) and a hook for `prev_step`, whose step is not validated. Regression tests in `python/djust/tests/test_wizard_submitted_step_3964_3965.py`.
