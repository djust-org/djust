- **An inserted `{% if %}` block inside `<svg>` or `<math>` keeps the SVG / MathML namespace.** The client parsed the HTML of every `InsertSubtree` patch in an HTML `<template>`, so the elements of a conditional block inside `<svg>` or `<math>` came out as HTML elements, while the full render has them as SVG or MathML elements: an `<iframe>`, `<a>`, `<form>`, `<details>` or `<video>` written there is inert in the full render but was a working HTML element after the patch. The client now parses that HTML as children of the element it is inserted into: inside an `<svg>` or `<math>` wrapper for an SVG or MathML parent (a MathML `mi`, `mo`, `mn`, `ms`, `mtext` or `annotation-xml` parent is reproduced as well), and as HTML, as before, for an HTML parent and for the HTML integration points (`foreignObject`, `desc`, `title`, and `annotation-xml` with an HTML `encoding`). The server writes that HTML for that parse. An HTML `<noscript>` in an inserted block is written with its text escaped, so its content stays text as in the full render. Regression tests in `tests/js/insert_subtree_namespace.test.js`, `python/tests/test_vdom_foreign_raw_text.py` and `crates/djust_vdom/src/lib.rs`; `tests/playwright/test_insert_subtree_namespace.py` compares real patches with a full render in Chromium.
