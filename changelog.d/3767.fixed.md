- **A Django `Form` held as LiveView state reaches the template as the form, not as `{field_name: widget HTML}` (#3767).** `LiveView` state is JSON, so `_sync_state_to_rust` flattened a `BaseForm` held on the view to `{name: SafeString(str(form[name]))}` (`serialization.render_form_value`) and left it out of the raw-Python sidecar. That keeps `{{ form.name }}` and loses what a form *is*: `{{ form.name.errors }}`, `{% field_error field=form.name %}` and `{% for f in form %}{% field_error field=f %}{% endfor %}` rendered nothing, `{% for f in form %}{{ f.label }}` iterated the field *names*, `{{ form.is_bound }}` and `{{ form|length }}` read a dict, and `{{ form }}` printed it, while `DjustTemplateBackend` (since #3755) and Django rendered all of them. **The cure is not one of the three options the issue lists, and it needs no Rust change.** All three assume the form must also be *in the Rust state* (flattened, or as a handle-bearing value that is diffed, re-sent and serialised on every event). The engine already has a channel for a live object that is not state: the raw-Python sidecar, resolved lazily at the lookup, per segment, under the serialization floor. So a context name for which `djust.serialization.holds_form` is true — a `Form`, a `BoundField`, a formset, or a `dict` / `list` / `tuple` holding one (up to four containers deep: a wizard's `steps`, `{"login": ..., "signup": ...}`) — is kept **out of the state** and rides the sidecar only, so the value stack has nothing to answer first. The same decision is read at every entry that hands the engine a state dict and the raw objects separately: `_sync_state_to_rust` (HTTP GET, WebSocket mount and event, SSE and the runtime all call it), the page shell (`render_full_template`, both branches) and a `template_name` component. The set of `update_state` call sites is pinned from the source. **Cost, measured on a release build (an event that assigns a new form and renders; min of 5 batches of 150; the figures are for 4, 20 and 60 fields):** a template that reads a field (`{{ form.f0 }}`, `{{ form.f0.errors }}`) goes from 1.2 / 2.1 / 4.6 ms to 1.0 / 1.2 / 1.4 ms, and one that never touches the form from 1.2 / 2.3 / 4.9 ms to 0.9 / 1.0 / 1.4 ms, because only what the template touches is converted and the per-field flatten is gone; an event that does not change the form costs the same as before (0.7-0.9 ms either way). **The one thing that got slower is the whole-form spelling:** `{% for f in form %}{{ f }}{% endfor %}` goes from 1.1 / 2.1 / 4.5 ms to 2.0 / 6.0 / 15.2 ms and `{{ form }}` from 1.1 / 2.3 / 5.1 ms to 1.7 / 4.5 / 10.4 ms. That is the engine's eager conversion of a form object (`str(form)`, the `as_div` render), the cost #3769 measures on `DjustTemplateBackend` (6.3 ms for the loop at 20 fields), and those spellings printed the wrong thing before (the loop yielded the field names, `{{ form }}` a dict). #3769 (a lazy `Encoded.display`) is the cure and is unchanged by this fix. **The floor holds on every route:** the form crosses as the already-floored proxy (#3790, #3798), and `python/tests/test_form_floor_differential_3790.py` now runs its whole grammar (4998 templates in 213 groups) against a root form held as an attribute of a `LiveView`, asserting both that no part of the secret appears and that the render equals the plain backend's. That also closes a flattened-copy exposure the old shape had for the `DJUST_SENSITIVE_FIELDS` text field: `{{ form|pprint }}` and `{% for k, x in form.items %}{{ x }}{% endfor %}` printed the control's `value="…"` for a held form and a held formset, which the plain backend never did. **What does not change:** JSON state. `get_state()`, the session save and the signed snapshot use `normalize_django_value`, which still flattens (`state_roundtrip=True`) and still treats a form attribute as the non-serialisable value it always was; a form restored from the session (`enable_state_snapshot`, the HTTP POST fallback) is therefore still the JSON dict. **Not covered:** a form nested more than four containers deep, or held by a container that is not a `dict` / `list` / `tuple` (a `deque`, a `set`, a `QuerySet`), stays flattened as before; the Tokio-actor transport's MOUNT frame hands the engine `str(form)` (identical before this change; the render after an event is correct), pinned as a strict `xfail`.
