- **A tag rendered through the `{% load %}` bridge no longer walks raw objects past the serialization floor (#3771).** `{{ obj.user.password }}` has always been empty under the Rust engine, because the engine's walk re-protects after every segment of a path. A bridged tag (`relative_time`, `avatar_group` and the other object-taking djust component tags, every third-party `simple_tag` / `inclusion_tag` / raw `@register.tag`, `{% blocktranslate %}`, `{% cache %}`) resolves its operands in Django's own node with `Variable._resolve_lookup` over the raw objects of the handler dict, and nothing re-protected those steps: `{% relative_time datetime=obj.user.password %}` printed the password hash, and so did `form.instance.password`, `form.fields.owner.queryset.first.password`, `obj.users.first.password` and, since #3770 hands a bridged tag a live `BoundField`, `{% for f in form %}…f.form.instance.password`. The leaf floor only wrapped a `Model` / `Manager` / `QuerySet` that was itself the root of the path, so a `Form`, a `BoundField` or a plain object holding a model passed through.

  The node stays Django's. What changes is the walk: while a bridged node renders, every `Variable` it resolves against the `Context` the bridge built (`FilterExpression` operands, `|filter:argument`, and the `template.Variable` a raw tag constructs itself, at compile or at render time) is resolved by Django's own `_resolve_lookup` over a context whose lookups return floor-checked wrappers, and the next step is re-protected after every segment, **including after a floor proxy**: a stock queryset method or a model property that returns a plain container of models (`qs.in_bulk.<pk>.password`, `obj.user.friends_prop.0.password`, `obj.user.get_friends.0.password`) hands Django a container, and the model inside it is protected on the step that reaches it. This is the re-protection `Context::walk_live` does for `{{ }}`, applied to the steps Django's resolver takes; it is not a second implementation of that walk, and the two can differ for an exotic object (see below). The value the walk ends on is released: a wrapper is unwrapped; a model reached on the way is the floor-enforcing proxy; a container that holds a model is re-protected like a top-level container; anything else, including a container with no model in it, arrives as the caller's own object. The refused path is "missing", as in `{{ }}`: an unresolved operand is the empty string and a filter argument that does not resolve raises `VariableDoesNotExist`, exactly as Django treats any missing variable. The gate is exact (the `Context` registered by the bridge for that node, per thread and task), so a Django engine in the same process, another thread, and the `Context.new()` an inclusion tag renders its own template on are untouched. Benign output is unchanged (the walker is transparent to `callable`, `do_not_call_in_templates`, `alters_data`, `silent_variable_failure`, signature binding and a property that raises `AttributeError`).

  **Behaviour change.** A model reached by a path now arrives in a tag as the floor proxy (as a top-level `{% tag user=user %}` always did) rather than the raw instance. So `isinstance(operand, User)`, `operand._meta`, `operand.save()` and an ORM filter on the instance no longer work on a path-spelled operand, exactly as they do not on a top-level one. Equality did flip silently (`{% t obj.user obj.user %}` and `{% t request.user obj.user %}` compared two distinct proxies and went from equal to unequal); the proxy's `__eq__` / `__hash__` now delegate to the model behind it, which reveals identity and no field, so those comparisons are as they were. `isinstance` cannot be restored without making the proxy a `Model`, which would let `_protect_sidecar_value` treat it as a model to wrap again, so it is not attempted.

  **What this does not floor** (the template author's reach through the tag author's Python): a generic accessor tag that takes a path as a string (`{% getattr obj "user.password" %}`, `get_item`, `call_method`) receives a released plain object and walks it in its own code; a `takes_context` tag reading `context["obj"]` itself; a tag function's body, which receives its released operands; an inclusion tag's own template, rendered on `Context.new()`; a node that never uses `Variable`; and an operand released as a non-`list` / `tuple` / `dict` / `set` iterable (a dict view, a generator, a `RawQuerySet`), which arrives as the raw object. Whether a particular third-party tag is one of the unfloored shapes is the tag author's code, not something the engine can see.

  Regression cases in `python/tests/test_bridge_floor_3771.py` (the five spellings from the issue and their neighbours, under ten operand shapes, for an inline tag, a raw tag that builds its own `Variable`, a raw-block tag and a cache vary-on operand, through `DjustTemplateBackend`, `LiveViewTestClient`, an HTTP GET and a WebSocket mount); each mechanism is gate-off tested separately. The code is `python/djust/template_bridge_floor.py`; the three places the bridge renders a node (`_render_node`, the raw-block handler, the cache operand) enter its scope. `install()` is one assignment of a constant and reads nothing back, so it cannot lose a race.
