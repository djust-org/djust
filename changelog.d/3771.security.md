- **A tag rendered through the `{% load %}` bridge no longer walks raw objects past the serialization floor (#3771).** `{{ obj.user.password }}` has always been empty under the Rust engine, because the engine's walk re-protects after every segment of a path. A bridged tag (`relative_time`, `avatar_group` and the other object-taking djust component tags, every third-party `simple_tag` / `inclusion_tag` / raw `@register.tag`, `{% blocktranslate %}`, `{% cache %}`) resolves its operands in Django's own node with `Variable._resolve_lookup` over the raw objects of the handler dict, and nothing re-protected those steps: `{% relative_time datetime=obj.user.password %}` printed the password hash, and so did `form.instance.password`, `form.fields.owner.queryset.first.password`, `obj.users.first.password` and, since #3770 hands a bridged tag a live `BoundField`, `{% for f in form %}…f.form.instance.password`. The leaf floor only wrapped a `Model` / `Manager` / `QuerySet` that was itself the root of the path, so a `Form`, a `BoundField` or a plain object holding a model passed through.

  The node stays Django's. What changes is the walk: while a bridged node renders, every `Variable` it resolves against the `Context` the bridge built (`FilterExpression` operands, `|filter:argument`, and the `template.Variable` a raw tag constructs itself, at compile or at render time) is resolved by Django's own `_resolve_lookup` over a context whose lookups return floor-checked wrappers, one segment at a time, and the value the walk ends on is released (a wrapper is unwrapped; a model reached on the way stays the floor-enforcing proxy, which is what `{% tag user=user %}` already was handed for a top-level `user`; a container that holds a model is re-protected like a top-level container; anything else, including a container with no model in it, arrives as the caller's own object). The refused path is "missing", as in `{{ }}`: an unresolved operand is the empty string and a filter argument that does not resolve raises `VariableDoesNotExist`, exactly as Django treats any missing variable. The gate is exact (the `Context` registered by the bridge for that node, per thread and task), so a Django engine in the same process, another thread, and the `Context.new()` an inclusion tag renders its own template on are untouched. A tag author's own Python (`takes_context`, the function body) is not floored: it is the application's code, not the template author's. Benign output is unchanged (the walker is transparent to `callable`, `do_not_call_in_templates`, `alters_data`, `silent_variable_failure`, signature binding and a property that raises `AttributeError`). One visible difference: a model reached by a path now arrives in a tag as the floor proxy (as a top-level `user` always did) rather than the raw instance. Regression cases in `python/tests/test_bridge_floor_3771.py` (the five spellings from the issue and their neighbours, under ten operand shapes, for an inline tag, a raw tag that builds its own `Variable`, a raw-block tag and a cache vary-on operand); each mechanism is gate-off tested separately. The code is `python/djust/template_bridge_floor.py`; the three places the bridge renders a node (`_render_node`, the raw-block handler, the cache operand) enter its scope.
