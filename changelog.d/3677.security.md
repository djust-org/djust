- **`djust_theming` now sanitises every URL with the same allowlist `djust_components` uses, instead of its own denylist (#3677).** The theming tags kept a denylist (`javascript:`, `vbscript:`, `data:`, and since #3665 `livescript:` and `mhtml:`), so every scheme it did not name passed through 19 sinks in both engines: `theme_button`, `theme_nav`, `theme_nav_group`, `theme_nav_item`, `theme_breadcrumb`, `theme_avatar` `src`, and the `action` and `*_url` of every `theme_*_page` that has them. `blob:`, `file:`, `jar:`, `view-source:`, `intent:`, `ms-word:`, `feed:`, `ws:`, `git:` and custom application schemes are not script schemes in a current browser, so none of this is a script-execution hole today; a denylist ages badly, though, since every new dangerous scheme is a hole until someone adds it. The theming helpers now call a new `djust.components.utils.url_allowed` (the decision `safe_url` already made, now callable without its escaping) and the theming denylist is deleted: a rejected data-derived URL renders as `#` as before, and a developer-supplied literal (`theme_button href=`, or `href`/`src`/`action`/`formaction` in `**attrs`) still raises `ValueError`. `url_attr` and `safe_url` behave as before and the components allowlist is not widened. **Behaviour change for theme authors:** a link whose scheme is not `http`, `https`, `ftp`, `ftps`, `mailto` or `tel` (for example `sms:`, `geo:`, `webcal:` or an app deep link such as `myapp://record/42`) now renders as `#` in a `theme_*` tag or page; it passed through before. The URL-scheme sweep (`scripts/template-library-url-sweep.py`) now reads every scheme outside the allowlist, not only the script schemes, with 20 new payloads in the forms a browser still reads as that scheme; run over the tags with the test corpus on `main` it reported 38 holes in the theming tags (19 sinks in each of the two engines), and the sweep test finds none after the change. That wider scanner also found one gap in `djust_components`, recorded and pinned, not changed here: the Rust `Avatar` (`crates/djust_components/src/simple/avatar.rs`) does not strip a leading C0 control character before reading the scheme, so `\x01blob:...` reaches an `<img src>` where the Python `url_attr` returns `#`. New cases in `test_theming_url_allowlist_3677.py` (replaces `test_theming_url_denylist_3665.py`), `test_theming_url_scheme_guard.py` and `test_url_scheme_sweep_3665.py`.
