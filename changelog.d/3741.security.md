- **`pulldown-cmark` is pinned to `>= 0.13.6`, past RUSTSEC-2026-0414 and RUSTSEC-2026-0433 (#3741, #3742).** Both advisories (an exponential event blow-up from `[[a|]]`, and quadratic work on nested `![[` wikilinks) affect `pulldown-cmark` 0.13.0 through 0.13.5 and only with `Options::ENABLE_WIKILINKS`. `v1.3.0rc14` shipped 0.13.4 in its `Cargo.lock` and SBOM; `v1.3.0rc15` and `main` already lock 0.13.6, so the weekly scan clears once it next reads a newer tag. djust is not reachable by either advisory: `crates/djust_templates/src/markdown.rs::to_pulldown` starts from `Options::empty()` and sets only tables, strikethrough and task lists, never wikilinks. This change raises the `Cargo.toml` requirement from `0.13` to `0.13.6`, so a lockfile regeneration cannot resolve below the patched version, and adds a Rust test that `Options::ENABLE_WIKILINKS` is unset and wikilink syntax stays literal text under every `RenderOpts` combination. One behaviour difference between 0.13.4 and 0.13.6 reaches `render_markdown`: a link reference definition followed by a whitespace-only line (`[b]: /u\n\t\n`) no longer renders an empty `<p></p>`. A differential of the two versions over the 401 markdown files in this repository (zero differences) and 200,000 generated inputs under all eight option combinations found that one class and nothing else. Regression case `wikilink_syntax_is_never_a_link` in `crates/djust_templates/src/markdown.rs`.
