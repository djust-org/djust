- **A tag that names its own closing tag now works under the Rust engine, including through `{% extends %}`.** Two parts. The ADR-030 wrapper probe looked for `end<name>` rather than the end tag the tag's closure names, so a wrapper such as `end_theme_card_block` was refused as having more than one body segment (`LibraryBlockTagHandler` already used the right name at render time). And the inheritance resolver (`crates/djust_templates/src/inheritance.rs`) re-serialised a block or raw-block custom tag as `{% end<name> %}` instead of the end tag its handler registered, so a LiveView template that `{% extends %}` a base and used such a tag failed to parse; it now writes the registered end tag. **Needs the Rust extension rebuilt.** `get_theme_manager` also treats a falsy request (the `""` a render context without `request` yields) as no request.
