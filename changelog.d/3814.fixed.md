- **`_rust.serialize_context` no longer overflows the stack on a symmetrical self-referential relation, a container that holds itself, or a very long chain of related rows (#3814).** With `Person.friends = ManyToManyField("self")` and A <-> B, `_rust.serialize_context({"p": a})` ended the interpreter with `Fatal Python error: Segmentation fault`: the all-fields model arm builds a model's dict with `model_to_dict` and recurses into every value, and a relation hands back a FRESH instance of the row it came from, so no identity check ended it. `guard_panic` cannot catch that (it is the process's stack, not a Rust panic), and a list or dict that contains itself did the same. Every recursive step now goes through one function, `serialize_nested`, which fails CLOSED to `str(obj)`: into a container or a model row (class + primary key) the walk is already inside of, or past a depth ceiling (128 levels, for a chain of DISTINCT rows). The row check runs before `model_to_dict`, so the query that would fetch the next ring of the cycle is not made. A row reached from two different parents is not a cycle: the path is popped on the way out. Before, in a bounded child process, the model, list and dict cases exit with SIGSEGV and the non-`str` `render()` raises; after, all exit normally with bounded output.

  **A `render()` that returns a non-`str`** (an `int`, `None`) no longer raises `TypeError` out of `serialize_context`; it falls back to `str(obj)` exactly as a `render()` that raises does.

  **The production serializers were checked for the same shape and do not have it, so none was changed.** `serialize_object_with_paths` / `serialize_queryset` walk the template's field-path tree, which is finite whatever the data is (and `queryset_template_value` carries its own 64-level cap), and the Python encoder is capped at `serialization_max_depth`. Run against the same relation through `serialize_queryset`, the `DjustTemplateBackend` (`{{ p.friends.all.0.friends.all.0.friends.all.0.name }}`, a `{% for %}` over `p.friends.all`, a bare `{{ p }}`), a LiveView attribute and the encoder, each exits normally on the unchanged build as well. `serialize_context` has no production caller (#3778).

  Regression cases in `python/tests/test_serialize_context_cycles_3814.py`, each run in a child process watched on the clock and on memory (a segfault is exit `-11`), with a control that proves the harness sees a crash. Each mechanism (container check, model-row check, depth ceiling, the shared chokepoint, the pop, the non-`str` fallback) is gate-off tested separately.
