- **Removed time-travel debugging (#4184, owner decision 2026-11-15).** The
  per-view recording (`time_travel_enabled = True`, the `djust.time_travel`
  module), the jump, component jump and forward replay, the debug panel's Time
  Travel tab, and the WebSocket frames `time_travel_jump`,
  `time_travel_component_jump`, `forward_replay` and `bug_capture_share` are
  gone, with the `reset_view_state` and `eval_handler` observability endpoints
  and their MCP tools. The bug-capture Share button,
  `djust.bug_capture.encode_view_state()` and `time_travel_excluded_fields`
  read the time-travel buffer and went with it; a capture is now built from
  the states you supply, `BugCapture(state_before=..., state_after=...,
  vdom_patches=...).encode(scrub=scrub_fields(...))`, and the replay viewer,
  snapshot store and `djust replay` CLI are unchanged. Nothing that turned the
  feature on is ignored: a view that sets `time_travel_enabled` or
  `time_travel_excluded_fields` to a true value is refused with
  `ImproperlyConfigured` when the class is created, the `LIVEVIEW_CONFIG` /
  `DJUST_CONFIG` keys `time_travel_enabled`, `time_travel_max_events` and
  `bug_capture_default_scrub` are refused at startup, `from djust import
  time_travel` and `from djust.bug_capture import encode_view_state` raise
  `ImportError` naming the replacement, and an older client that sends a removed
  frame gets the standard `Unknown message type` error on a connection that
  keeps working. To follow state changes event by event, use the debug panel's
  State tab (under `DEBUG`), which lists each event with the state after it and
  what changed. System checks `djust.C501`, `djust.C502` and `djust.V014` are
  retired. Signed back-navigation snapshots and `persist=` state on a
  reconnect are a different feature and are unchanged.
