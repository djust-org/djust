- **Marked-safe values are no longer exempt from the URL scheme check; the no-op `javascript:void(0)` / `javascript:;` hrefs are still accepted (#3898, #3894).** Behaviour change: a `mark_safe` (also lazy, or `__html__`) value used as a URL anywhere a component prints one (the class-based components, the native handlers, the template tags' item data and their own keywords such as `{% avatar src=... %}`) is now checked against the scheme allowlist and escaped like any other string (an already-escaped `&amp;` is escaped once more, so pass the plain URL). An ITEM value (an entry of a list of items, or an item dict) that lands in an attribute is escaped whatever it is marked as in every class-based component and in the template tags this change edits (`avatar_group`, `presence_avatars`, `chat_bubble`, `mentions_input`, `sortable_grid`, `rich_select`, `live_indicator`, `activity_feed`, `data_card_grid`, `org_chart`, `carousel`, `lightbox`, `model_table`'s row id and filter value); 34 other tag parameters still leak an item value and are listed, and pinned exactly, in #3904. A scalar argument (a constructor argument or a tag keyword) in an attribute other than a URL is the developer's own and is unchanged. Text slots keep their markup. The literal no-op hrefs `javascript:void(0)` and `javascript:;` (exact text, `href` only, never an image source) are accepted marked or not, so a dropdown toggle needs no `mark_safe`. URL helpers convert values to the exact `str` type before checking them. `test_marked_safe_attribute_sweep_3898.py` derives the classes, parameters, tags and item keys from the code and fails on any URL call that leaves `honor_safe` at its default.
