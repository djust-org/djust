- `T019`-`T022` now run when `TEMPLATES` lists only `DjustTemplateBackend` (the `djust new` default). They previously did nothing, silently, because no Django template engine was found; a compile-only engine is now built from the Djust backend's directories, installed-app tag libraries (`{% load static %}` and the rest), `OPTIONS["libraries"]` and builtins. A `templatetags` module that fails to import is skipped rather than aborting the checks, and if the engine cannot be built at all the scan is skipped. When a project has views but no usable template engine, a new info message `djust.T023` says the checks were skipped (silence it with `suppress_checks`). The same engine feeds the recovery-target scan that strict-policy dispatch consults, so on a Djust-only project a template that compiles now reports a complete answer (it used to report "incomplete" for every view and fall back to parsing each render); a template that does not compile still reports incomplete (#3299).
