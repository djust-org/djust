- A client can no longer grow a form's submitted data without bound over a WebSocket, and a template that reads `form.data` many times no longer pays for it each time (#3834). `max_message_size` bounds one frame, but `FormMixin.form_data` outlives it (one client-named key per `validate_field` event, every key of a `submit_form` event, all bound to the form on every event), so `LIVEVIEW_CONFIG["max_form_fields"]` (default 1000) and `["max_form_data_size"]` (default 2,621,440 characters) now hold what `FormMixin`, `WizardMixin`, the admin form view and a `params_form` keep, with Django's own `DATA_UPLOAD_MAX_*` defaults; an event past them is refused whole, logged without the keys, and reported in `form_errors` / `wizard_step_errors["__all__"]` / `params_errors["__all__"]` (`0` removes a limit; a value that is not a non-negative integer is the default, never unlimited). Separately, the serialization floor's filter of `form.data` is kept on the form and trusted only while the mapping is the same object with the same keys under the same floor (a widget swapped on a live form, a model's floor, `DJUST_SENSITIVE_FIELDS` are all followed), so ten reads of 100,000 dashed keys filter once (~1 s) instead of ten times.
