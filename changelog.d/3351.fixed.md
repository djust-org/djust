- **Draft mode saved and restored only the fields present at page load (#3351).**
  With `DraftModeMixin`, a `data-draft` field that a patch inserted (a conditional
  `{% if %}` block, a wizard step) saved nothing, a field replaced by a new element
  stopped saving, and a draft root inside a `dj-lazy` view was never wired, so text
  typed there was lost on reload. Saving is now one delegated listener installed
  once, and a field is restored once when it first appears, never over a field the
  user is typing in or has edited. Each draft root saves the fields inside it under
  its own key. Separately, the page-load restore of a static field was undone by
  the mount morph of the prerendered page, which wrote the server's value back; the
  draft is now restored after that morph. Covered by the vitest suite
  `tests/js/draft-mode-after-init-3351.test.js` and a real-browser script in
  `tests/playwright/`.
