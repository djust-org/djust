- **The native handlers of eight component tags dropped or invented `dj-*` event attributes the Python tag emits (#3669).** Under the socket render a click or input handler wired by the first, Django-engine render was missing or renamed. `dj_button` kept `dj-click` only while enabled and never emitted `dj-confirm`, and ignored `preset=` (a preset can carry `event` / `confirm`); `color_picker` ignored `swatches=`; `pagination` drew no numbered page buttons (each fires `next_event` with the page as `data-value`); `data_table` ignored `row_click_event` and the `prev_event` / `next_event` pager shown when `total_pages > 1` without `paginate`; `nav_item` with an `event` and a text body became a dropdown with no `dj-click`; `filter_bar` took each control's own `event` and never drew the "Clear filters" button, because a native block handler is handed only the rendered children, so it is now a raw block tag (Django's own `filter_bar` renders the bar, children included, as `tabs` and `split_pane` already do; a child outside a bar renders nothing, as in Python; the default id stays `filter-bar` rather than a per-render random one). The Python tag is the reference. `python/djust/tests/test_component_dj_attr_parity_3669.py` renders 95 argument combinations of the twelve tags through both engines and compares the `(element, dj-attribute, value)` multiset, with hostile event names (quotes, `<`, `&`, `</script>`, U+2028) and a strict-CSP check on both. `combobox` and `toast_container` already agreed and are now pinned. Not changed, and why: `tree_view` / `kanban_board` differ only for a `SafeString` operand (native escapes it, which is the safe side); the native `data_table` also wires about a dozen features the Python template never renders; a `nav_item` nested three levels deep; a block tag's unresolved-variable argument; and the Python `data_table` template's own `sortable: False` quirk. Markup outside `dj-*` (classes, text, ids, ARIA) is #3663.
