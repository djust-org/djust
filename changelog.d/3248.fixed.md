- **Back restores the latest rendered state under slow or failing session storage (#3248).** A legacy `enable_state_snapshot` view's per-event save is best effort; a save that was skipped because the previous one was still running, or that failed, left the session older than the last render, and Back restores the session copy in preference to the client's token. The latest state is now written once more by a coalesced trailing save: one write per burst, ordered after the pending save so an older write never lands over a newer one, and waited for (3 s at most; the wait ends once the save in progress has been running for 1 s, so hung storage holds a navigation for about 1 s at most, and a save still running after 1 s is abandoned and Back restores the last stored copy) before a disconnect, `live_redirect`, replacing mount or SSE close releases the view. It writes nothing into a session that was logged out or whose key changed since the state was rendered. A failing save is retried once and the latest state kept. Restored state is historical view state: handler permission checks still run against the current request.
