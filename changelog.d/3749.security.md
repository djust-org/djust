- **`djust_theming` judged the URL a template prints, not the value it was handed (#3749).** A `theme_nav` / `theme_nav_group` / `theme_breadcrumb` / `theme_sidebar_nav` item whose `url` is a callable (`def url(self): return "javascript:alert(1)"`) printed `href="javascript:..."`: the check ran before the template engine called the callable, judged `"<bound method ...>"`, and the engine then printed what the method returned. The item's value is now looked up and resolved the way the engine does it: `item["url"]` first and the attribute second (for any object with a `__getitem__`, not only a `Mapping`), then called once by the engine's own rules (`do_not_call_in_templates`, `alters_data`, a call that needs arguments), and the item is rewritten with a value the engine will not call or convert again; a callable that returns a callable is written back as the text the engine would have printed for it. A callable `items` on a sidebar section is resolved the same way. A value is converted to text once, and that text is what is judged and printed (an object whose `__str__` answers differently the second time can no longer pass the check and print something else). A lazy value that prints as marked-safe text (`lazy(lambda: mark_safe(...), str)()`) is plain text like a `SafeString`.

  The `**attrs` pass-through of `theme_button` / `theme_input` / `theme_select` / `theme_progress` judged only `href` / `src` / `action` / `formaction`. These are now also judged by `djust.components.utils.url_allowed`: `ping`, `srcset` (entry by entry, so one bad entry does not drop the good ones), `poster`, `data`, `background`, and the framework's own `dj-navigate` / `dj-patch` / `dj-patch-reload`. A rejected scheme renders `#` and logs a warning, and these never raise (only the four that always did still do). The set is an explicit list decided name by name, not a pattern: `cite`, `longdesc`, `manifest`, `codebase`, `usemap`, `icon`, `profile`, `archive`, `classid`, `itemid`, `itemtype` (no browser follows them on the elements these tags print, or they hold text such as `icon="mdi:home"`) and every author-defined `data-*` / `dj-*` name (`data-url`, `dj-action`, `data_location="Paris: France"`) are printed as written. One visible consequence: `data="x:y"`, `data` being the `<object>` fetch attribute the issue names, renders `#` like `href="x:y"`.

  What this covers, and what it does not: the tags' own arguments and the pinned pass-through names. A project template override (`components/badge.html` in the project's templates) that prints an `attrs.<name>` into a URL attribute is outside it, because a tag cannot see which key an override reads; no template in this repository does (the set of such reads is derived from the templates and pinned in `TestAttrsReadsInUrlPositionsArePinned`). Regression cases in `TestCallableUrl`, `TestEveryPassthroughTagAndAttribute`, `TestThePassthroughSetIsPinned` in `python/tests/test_theming_url_hardening_3749.py` and in `python/tests/test_theming_url_review_3765.py`; the sweep (`scripts/template-library-url-sweep.py`) drives every URL attribute the scanner reads through every tag that takes `**attrs`, so a new pass-through sink fails `test_url_scheme_sweep_3665.py` until it is classified.
