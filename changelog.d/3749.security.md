- **`djust_theming` judged the URL a template prints, not the value it was handed (#3749).** A `theme_nav` / `theme_nav_group` / `theme_breadcrumb` / `theme_sidebar_nav` item whose `url` is a callable (`def url(self): return "javascript:alert(1)"`) printed `href="javascript:..."`: the check ran before the template engine called the callable, judged `"<bound method ...>"`, and the engine then printed what the method returned. The value is now resolved by the engine's own rules (`do_not_call_in_templates`, `alters_data`, a call that needs arguments) before it is judged, so a callable item `url`, a callable `items` on a sidebar section and a mapping that is not a `dict` all reach the allowlist. The `**attrs` pass-through of `theme_button` / `theme_input` / `theme_select` / `theme_progress` judged only `href` / `src` / `action` / `formaction`; `ping`, `poster`, `srcset`, `data`, `background`, `cite`, `longdesc`, `manifest`, `icon`, `profile`, `archive`, `classid`, `codebase`, `usemap`, `itemid`, `itemtype` and a `data-*` / `dj-*` attribute whose name says it is a URL (`dj-navigate`, `data-image-url`) were printed as written; they now go through `djust.components.utils.url_allowed` too (`srcset` and `ping` entry by entry, so one bad entry does not drop the good ones). A rejected scheme renders `#` and logs a warning, and these attributes never raise (only the four that always did still do). A lazy value that prints as marked-safe text (`lazy(lambda: mark_safe(...), str)()`) is converted to plain text like a `SafeString`, which closes the third gap in the issue. Regression cases in `TestCallableUrl`, `TestEveryPassthroughTagAndAttribute`, `TestListValuedAttributes` and `TestThePassthroughSetIsPinned` in `python/tests/test_theming_url_hardening_3749.py`; the sweep (`scripts/template-library-url-sweep.py`) now drives every URL attribute the scanner reads through every tag that takes `**attrs`, so a new pass-through sink fails `test_url_scheme_sweep_3665.py` until it is classified.
