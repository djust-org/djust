- **ActivityFeed, Terminal and Tour now ship the interactions their docstrings describe (#2985, batch 3).** Each rendered a `dj-hook` that no shipped script answered; `components/static/djust_components/activity-feed.js`, `terminal.js` and `tour.js` now do, and the catalogue page of each includes its script. A streaming ActivityFeed puts pushed events at the top, keeps `max_items` rows, announces new activity and follows the WAI-ARIA feed keyboard pattern. Terminal appends streamed lines with the same ANSI colour and bold the server renders (flat spans built with the DOM API, bounded work per line), follows the newest line until the reader scrolls up, and gains an optional `max_lines`. Tour dims the page around the target with a cut-out and ring, places the popover beside it, follows scrolling and resizing, falls back to a centred popover when the target is missing, traps focus and returns it, lets a field in the spotlight keep focus, and answers the arrow keys and Escape by pressing its own buttons; it stays aligned inside a transformed ancestor. Markup changes are additive only: `data-max-items` on a streaming feed and `data-line-numbers` / `data-max-lines` on a terminal, on the component class, template tag and Rust handler alike; a byte comparison of 945 renders against the previous release is identical once those attributes are removed. The scripts register in `window.DjustHooks` and only when neither hook registry already holds that name, so an app's own hook is never replaced. 9 components from the issue remain.
