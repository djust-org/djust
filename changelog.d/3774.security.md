- **An HTML attribute NAME built from a template argument could carry markup (#3774).** `djust._html.build_tag` escaped every attribute value but wrote the name as given, so `{% live_input "text" handler="h" event=var %}` with `var = "dj-input onfocus=alert(1) autofocus y"` rendered `dj-input onfocus=alert(1) autofocus y="h"`. Names are now checked against the HTML rule (no whitespace, control, quote, `<`, `>`, `/` or `=`) by the new `djust._html.attr_name`, which `build_tag` and `FormMixin.as_live`'s `BaseAdapter._build_tag` share; an invalid name raises `ValueError`. The writers that did not go through `build_tag` now call it too: `render_icon`'s extra attributes (the name was only `html.escape`d, which cannot make one safe), the `data-*` keys of `Button`, `Card` and `PaginationComponent`, and the trigger and `dj-value-*` keys of `LiveComponent.event_attrs`. Every real name (`dj-input`, `aria-label`, `@click`, `dj-keydown.enter`) renders exactly as before. Found by auditing the 125 `mark_safe` sites the safe-markup guard flags outside `djust.theming`: none of those was vulnerable.
