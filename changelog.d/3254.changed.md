- **Presence is stored per connection and aggregated per user and room (#3254).** A user stays present until their LAST connection leaves or times out: closing or navigating one tab never removes a user who is open in another. Each view that calls `track_presence()` is one connection (key `(room, user, connection_id)`); `list_presences()`, `presence_count()` and `online_count` still have one record per user, with the unchanged shape `{"id", "joined_at", "meta"}` (`joined_at` is the earliest connection's, `meta` the most recently joined connection's). `handle_presence_join` now fires only when a user's FIRST connection arrives and `handle_presence_leave` only when their LAST one leaves; before, a second tab fired the join and the first tab to close fired the leave. Each connection has its own heartbeat and 60 s timeout, and the WebSocket ping now refreshes every view mounted on the socket (`mount_batch` siblings included).

  Contract changes (see the presence guide, "Custom presence backends"):

  - `PresenceBackend` gains three non-abstract methods: `join_connection(key, user_id, connection_id, meta) -> (record, first)`, `leave_connection(key, user_id, connection_id) -> record | None` (the record only when it was the user's last connection) and `heartbeat_connection(key, user_id, connection_id)`. Their defaults call the existing `join` / `leave` / `heartbeat`, so a third-party backend written against the old contract keeps working unchanged, with the old one-record-per-user behaviour (a second tab collapses, a close removes the user, the hooks fire on every track and untrack). The abstract methods and their required signatures are unchanged.
  - `PresenceBackend.per_connection` (False by default, True on the four built-ins) and `PresenceManager.per_connection()` say whether the configured backend stores one record per connection. Only then is a replaced view's untrack held until the replacement mounts; a backend on the old contract keeps leave, mount, join (its one record is shared), and keeps the #3313 SSE reconnect guard. A built-in subclass that overrides `join`/`leave`/`heartbeat` with the old signature (no `connection_id`) counts as an old-contract backend and its overrides are called as they always were.
  - The built-in backends' `join`, `leave` and `heartbeat` take an optional `connection_id`. Omitted, `join` and `heartbeat` address the user's one legacy connection (heartbeat refreshes all of the user's), and `leave` removes every connection of the user and returns the record when the user is gone, `None` when never there.
  - `PresenceManager` gains `join_connection`, `leave_connection`; `join_presence`, `leave_presence` and `update_heartbeat` take an optional `connection_id`. `leave_presence` / `leave_connection` return `None` while the user is still present through another connection.
  - Redis (and tenant Redis) keys hold one zset member / hash field per connection (the bare user id for a legacy connection, `<user_id>\x1f<connection_id>` otherwise), so a record written by an older node reads as one legacy connection (a connection a stopped pod leaves behind lingers up to 60 s beside the restored view's). `heartbeat` no longer re-creates an expired member (`ZADD XX`), `count()` reads member names only (one `ZRANGEBYSCORE`), and `join` / `leave` decide first/last inside one `MULTI`.
  - `PresenceMixin` gains `_presence_connection_id` (per view, regenerated on state restore, never trusted from saved state) and a `_on_presence_user_left` hook that `LiveCursorMixin` uses to drop the cursor with the user's last connection. `untrack_presence()` on a view that joined no connection removes nothing.
  - The WebSocket consumer holds a replaced view's presence untrack until the replacement frame has mounted (`_defer_presence_untrack`, flushed at the end of `receive()` and on disconnect); SSE navigation untracks after the new page mounts. A `handle_presence_leave` hook for a replaced view therefore runs after that view's teardown. A user whose every connection timed out is still removed without calling `handle_presence_leave`.
