- **What a custom filter or tag receives for a model is pinned and documented (#3949).** No djust entry hands custom code a live Django instance: `DjustTemplateBackend` and `render_template` hand a floor proxy, a LiveView hands a plain `dict`, and the two still differ (a `QuerySet` passed whole reaches a filter and a tag differently on the backend, and the keys of a LiveView `dict` follow what the rest of the template names). `python/tests/test_custom_callable_model_argument_3949.py` records the type each entry hands a custom filter, `simple_tag`, `simple_tag ... as`, `inclusion_tag`, `takes_context` tag and a Django-library tag reached through `{% load %}`, for a model, a list, a `QuerySet`, a loop variable and a `dict` holding models, and the floor that holds on every entry (`password` and a field named in `djust_exclude_fields` are never present, as a value or as a key). The new section "What a custom filter or tag receives for a model" in `docs/website/core-concepts/templates.md` shows the table and the guidance to pass the field rather than the model. No behaviour changes. Unifying the entries is tracked in #3949 and #3936 for 1.4.0.
