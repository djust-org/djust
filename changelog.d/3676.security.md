- **Native Rust handlers of raw `@register.tag` component tags read a bare variable's value as `key=value` pairs, so data passed as a bare operand could set a parameter of the tag** — `{% alert val %}body{% endalert %}` with `val = "title=PWNED type=danger"` rendered the title `PWNED type=danger`, and `{% card val %}` / `{% accordion val %}` could be made to set `class` / `id`. Output stayed escaped, so there is no markup or script injection, and it needed a template Django itself refuses (`Unexpected argument 'val'. Use key=value format.`). Measured on the `djust_components` library: 134 native handlers belong to raw tags; Django refuses a bare variable on 125 of them, and 117 of the 134 took the injected parameter. Each such handler is now wrapped at registration (`with_argument_contract`, `djust._positional_args`) so that at template compile time the tag's own Django compile function checks the tokens through the existing `validate_at_parse` hook, stopping where the tag asks for its body (no Rust change). The Rust engine therefore refuses a bare variable, attribute path, filtered variable, literal or number on those 125 tags with Django's message as a `TemplateSyntaxError`, before any context exists; the keyword form `title=val` is unchanged, and the 9 raw tags whose compile function never reads its arguments (`menu_divider`, `timeline`, ...) still accept and ignore a bare token, as Django does. **Behaviour change:** a template that put a bare operand on one of these tags rendered under the Rust engine and is now a `TemplateSyntaxError`; it was already invalid under Django.
