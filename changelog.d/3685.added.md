- **`djust_audit --a11y` and `manage.py check` gain Y005 (a chart or `<svg>` with no accessible name) and Y006 (a legend told apart by colour alone)** (#3685). A hand-built chart passed all four existing `Y` rules even when a screen reader got nothing from it. Y005 flags an element with `role="img"`, or an inline `<svg>`, that has no non-blank `aria-label` / `aria-labelledby` / `title` and, for an `<svg>`, no `<title>` child (WCAG 1.1.1); it skips `aria-hidden="true"`, `role="presentation"`/`"none"`, an `<svg>` inside a `<button>` or `<a href>` (the control owns the name; Y001 covers a control with none), a nested `<svg>`, hidden sprite sheets, opening tags with `{{ }}`/`{% %}` between their attributes, HTML comments, and `<script>`/`<style>` bodies. Unlike Y001, an empty `aria-label=""` is not a name. Y006 flags a `<li>` inside an element whose `class` has a `legend` token (`legend`, `chart-legend`, `legend__list`) that has no text, no `<img>` with an `alt`, no `{{ }}`/`{% %}` and no name attribute (WCAG 1.4.1). Both are warnings, suppressible by id (`Y005`, `Y006`), and are found by a one-pass tag scan that stays linear on unterminated and unclosed tags. Not included: the rendered-page axe-core pass from the issue (contrast, heading order, names that exist only after render), which needs a browser and is tracked separately. Documented in the accessibility guide, `docs/system-checks.md` and the error-code reference.

  **Behavior change**: (a) Y005 and Y006 are registered system checks, so `manage.py check` (and `check --fail-level WARNING`) now report them for every project, not only `djust_audit --a11y`. (b) A decorative icon `<svg>` outside a `<button>`/`<a href>` with no `aria-hidden` is reported by design; on the demo project all 11 hits were such icons. (c) Mark decorative graphics `aria-hidden="true"`, name a chart with `aria-label`/`<title>`, or silence with `DJUST_CONFIG['suppress_checks'] = ['Y005']` (or `Y006`).
