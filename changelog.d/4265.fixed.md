- **A component's `template_name` file can `{% include %}` a template by a relative `./` or `../` name (#4265).** A `LiveComponent` or descriptor (`BoundComponent`) `template_name` file without `{% extends %}` is drawn through the LiveView engine entry, which was never told the file's name, so `{% include "./part.html" %}` failed with a "Template not found" error (the same name worked in a file with `{% extends %}`, and in Django's own engine). The file's template name is now passed to the engine (`set_template_origin`), so the name resolves against the file on both branches. The "not scanned" hybrid-attribute warning also resolved such a name by its raw text, which the loader joins to the template root, so it counted the wrong file (a slot-holding target went unreported; a slot-free relative `{% extends %}` target was reported); it now resolves the name against the file, and counts a relative name in an inline `template` (which has no file to be relative to). An embedded `{% live_render %}` child whose `template_name` file includes a partial by a relative name now keeps that partial's `dj-model` fields in its allowlist (the walker had no origin, so they were silently refused). Tests in `python/djust/tests/test_component_hybrid_rawtext_and_live_templates_3913_3914.py` (`TestRelativeNamesInATemplateNameFile`, `TestRelativeIncludeNamesInTheWarning`) and `test_live_render_relative_include_allowlist_4265.py`.
