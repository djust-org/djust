- **Words run together in LiveView pages: `<b>A</b> <i>B</i>` rendered as "AB"
  (#2999).** The VDOM parser dropped every whitespace-only text node, and the
  egress normalizer collapsed every `> <` to `><`, so the space between two
  inline elements vanished from `render_with_diff()` and the WS frame (e.g.
  `**Lead.** \`code\`` in rendered Markdown read "Lead.code"). Both now keep
  whitespace between two inline-level siblings as a single `" "` text node and
  still drop indentation between block-level siblings. The client counts a
  text node that is exactly `" "` when it resolves patch paths, so server and
  client agree on child indices. Keyed lists whose items are separated by text
  exposed a client bug in `MoveChild`: moves were applied one at a time before
  the inserts, so a forward move landed one slot early (`[a,b,c]` → `[b,c,a]`
  came out "bac", also for plain keyed lists); a parent's inserts and moves
  are now applied together as placements at their final index, the model the
  server's `apply_patches` uses. Regression tests:
  `python/djust/tests/test_inline_whitespace_2999.py`,
  `crates/djust_vdom/tests/test_inline_whitespace_2999.rs`,
  `tests/js/inline_whitespace_parity_2999.test.js`.
