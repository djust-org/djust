- **A native BLOCK tag's argument naming an unresolved variable became that variable's NAME (#3871).** `{% nav_menu toggle_event=nope %}` with `nope` undefined rendered `dj-click="nope"` under the socket render (an event name the view may well have), and `{% card title=nope %}` printed `nope`; the Django tag renders both empty, and an inline tag's argument (`{% dj_button event=nope %}`) already did on both engines. The engine resolves a block tag's arguments through a channel that keeps the raw token when a name does not resolve, so the handler was handed text it could not tell from an operand that resolved TO `nope` (a lookup against the context, the `context.get(val, val)` in `_parse_args`, answers a different question). Block handlers now declare `TYPED_ARGS` without `TYPED_ARGS_STANDINS_ONLY` (`_TypedBlockOperands`): the engine says which operands resolved, and the wrapper empties exactly the ones that did not, so a block handler sees what an inline handler sees. A quoted literal, a number, `True` / `False` / `None`, a dotted lookup, a falsy variable (`0`, `""`, `None`, `False`) and a value that merely reads like an unresolved name (`shadow = "nope"`) are untouched. Still different, and pinned in `test_a_value_that_is_also_a_variable_name_is_resolved_a_second_time`: that same `context.get(val, val)` fallback looks a RESOLVED value up a second time, so `ev = "name"` prints whatever the variable `name` holds natively; it stays because about 400 tests call a handler's `render` with a raw token and rely on it (filed separately). `python/djust/tests/test_component_arg_handling_3870_3871_3872.py` renders 24 argument shapes through `nav_menu`, `nav_item`, `filter_bar`, `card`, `dj_button` and `badge` on both engines. The `{% call %}` / `{% component %}` handlers keep their own argument reader, whose operands arrive as raw tokens by declaration (`RESOLVE_ARG_POSITIONS`), so a lookup there is the resolution, not a second one. Behaviour change to know: an unresolved operand on a block tag (`title=view.page_title`, a namedtuple attribute `pt.x`, both of which resolve on neither engine) now renders empty instead of its own text.
