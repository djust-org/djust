- **A `Decimal` refusal message now spells the type name the way the running interpreter does (#3255).** djust reproduces CPython's `'X' object is not iterable` wording, and it carried `decimal.Decimal` as a literal. That is the C `_decimal` accelerator's spelling — a *static* type, so its `tp_name` carries the module. An interpreter without `_decimal` falls back to the pure-Python `_pydecimal`, a *heap* type whose `tp_name` is the bare `Decimal`, so `{% for x in a_decimal %}` said `'decimal.Decimal' …` where Django — and CPython — said `'Decimal' …`. The name is now measured once per interpreter, alongside the class `is_decimal` already resolves, so djust matches Django on both. Where no interpreter is initialized at all — the pure-Rust renderer path, where the measurement is impossible and previously unnecessary — it falls back to the C spelling rather than requiring one. This is what made the informational Python 3.15 CI shards red (its build has no C `_decimal`) while passing on every other interpreter; the two tests that listed the spelling now ask CPython for it (`tests/cpython_scalar_names.py`) instead of hardcoding it.
