- **Attributes passed through to a tag now follow one policy: no inline event handlers, no script URLs, no `type` that submits (#3818).** `{% live_input %}` forwards every keyword it does not know as an HTML attribute, and `FormMixin.as_live` forwards a Django widget's `attrs` and `render_icon` its extras. `build_tag` escapes the value and (since #3774) checks the name, but neither says what the attribute does: `live_input("text", handler="h", formaction="javascript:alert(1)")`, `onfocus=...` and `type="image" src="javascript:..."` rendered as given on both engines (the native engine bridges to the same tag), while `djust.theming`'s `_passthrough_attrs` already refused them. `djust._attr_policy.passthrough_attrs` is now the one place that decides, called by `live_input`'s collector, `BaseAdapter._merge_widget_attrs` (and `_get_field_type`, where a widget's `attrs={"type": ...}` becomes the tag's own `type`) and `render_icon` (and with it the native `{% icon %}` handler). Only an attribute NAME raises: an event-handler attribute (`on*`, and the `@`, `x-on`, `v-on` and `hx-on` spellings) raises `ValueError`. A VALUE never raises, because a template can take it from data (`formaction=profile.website`) and an error page that a stored hostile value triggers for every viewer would be an availability hole of its own: a URL whose scheme the shared allowlist rejects (`javascript:`, `vbscript:`, `data:`, `blob:`, `file:`, custom; read the way a browser reads it) renders `#` and is logged by attribute name in `href`, `src`, `action`, `formaction`, `poster`, `srcset`, `ping`, `data`, `background`, `xlink:href`, `dj-navigate` and `dj-patch` (a `srcset` / `ping` list is judged entry by entry), and a `type` value of `image`, `submit`, `reset` or `button` is left out so the field keeps its own type. Everything else passes through byte-identically, including other `type` values (`date`, `color` ...), `aria-*`, `data-*`, `style`, `x-*` and `hx-*`. Behaviour change: a project that passes `onclick=` / `onchange=` through `live_input`, widget `attrs` or an icon now gets a `ValueError` (use a `dj-*` binding); a `javascript:` URL in `formaction` / `href` now renders `#` instead of a live script URL. `djust.theming`'s own implementation is unchanged (it still raises for a script-bearing `href` / `src` / `action` / `formaction`); `python/tests/test_passthrough_attr_policy_3818.py` runs both against the same payloads, asserts the documented differences and nothing else, and pins the URL attribute sets equal. Regression cases there cover both engines, the widget route, the icon route, theming parity and a tripwire over the set of passthrough writers; gate-off verified.
