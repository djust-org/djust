- A `dj-model` input inserted after the page initialized (by a patch, inside a lazily hydrated `dj-lazy` view, or by a `live_redirect` morph) is now bound and sends `update_model`; before, `bindModelElements()` ran only at init and `reinitAfterDOMUpdate` did not call it despite its comment. `reinitAfterDOMUpdate` now calls it, scoped to the updated subtree. The bind guard stays a JS property on the element (never a DOM attribute a morph would strip), so unchanged inputs are skipped on every pass, and a surviving input whose `dj-model` attributes a patch changed is rebound (#3334).
