- **Native component handlers stripped the whitespace of a variable-valued argument; the Django tags keep it (#3872).** `{% dj_button event=ev %}` with `ev = "x "` (or `"x\n"`, `"x "`, `" x"`) rendered `dj-click="x"` natively and `dj-click="x "` under Django, and `{% badge label=ev %}` lost the same padding from visible text. `_parse_args` ran `val.strip()` on the argument text, but the engine splits a tag on whitespace, so a source token never carries any: only a RESOLVED value was ever stripped. The text is now read as it arrives; a padded text is never read as a number (`int(" 5 ")` is 5) or as `True` / `None`, and a lone quote character is no longer read as the empty literal. A lone space now wires on both engines.
