- **The T002 and T012 system checks now agree about a LiveView template that never connects (#3225).** A template with `dj-*` directives and neither `dj-root` nor `dj-view` renders as a static page: djust stamps no `dj-view` and the client mounts only `[dj-view]`. T002 fired on it anyway with "This is OK — dj-root is auto-inferred from dj-view", although nothing is inferred without `dj-view`; T002 now fires only when a template has `dj-view` and no `dj-root`, and its hint shows `<div dj-root>`. T012 knew ten event names, so a template driven only by `dj-viewport-bottom`, `dj-model`, `dj-hook`, `dj-poll`, `dj-upload` and others got no warning; its trigger set is now derived from the client's directive table (`djust._template_bindings.DIRECTIVES`) plus the non-event attributes that bind to the view, and matches modifier suffixes such as `dj-model.lazy` and `dj-keydown.enter`. The `dj-view` test was also a bare substring, so `dj-viewport-bottom` itself counted as a `dj-view` and silenced T012. A LiveComponent template whose root carries `data-component-id` is now skipped alongside `dj-component` and `{# djust:partial #}`. New cases in `python/tests/test_checks_t002_t012_3225.py`, including a drift test that scans the client source and fails when the client reads an attribute T012 has not classified.
