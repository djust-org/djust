- **A Python-bridged tag inside an overriding `{% block %}` rendered the parent for every call it made, whether or not it read `block.super` (#2918).** Output matched Django's, but side effects in the parent (a counter, a cache warmer, a bridged tag) ran several times as often: 60 handler calls against Django's 12 in the #2916 probe. The `block` a bridged tag receives is now a lazy object whose `super()` renders the parent when it is read, and renders it again on every read (no memoization, as Django's `BlockNode.super()` is a method call), so the parent's tags run exactly as often as in Django's engine and the parent's own exception class reaches a tag's `except` and a `{% blocktranslate with s=block.super %}` unchanged. It has Django's `BlockNode` shape: `context["block"].super()`, `"super" in block` (never renders). The older dict-style reads keep working as a deprecated path (see the Deprecated entry). The object is only valid for the bridged call it was handed to, so a tag that keeps the context it receives no longer forms an uncollectable cycle. A user variable named `block` is no longer replaced. 30 regression cases in `python/tests/test_block_super_bridge_lazy_2918.py`, one of them a 57-template matrix compared against Django's own engine on rendered output and per-tag call counts.
