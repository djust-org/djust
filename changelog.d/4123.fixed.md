- **A `start_async` / `@background` result that changed nothing no longer renders the whole template (#4123).** The result paths (the runtime's `_render_async_result` and the consumer's background render) synced and rendered unconditionally; with no changed key Rust took its "no change info" branch and rendered the full template to send `patches: []`, which happened on every later completion when several tasks finished close together. `_sync_state_to_rust()` now returns whether the next render has anything to do (`False` only when no key changed or was removed since the last sync and no render was requested), and an async result, its error arm and a cancelled task's settle skip the render and the frame when it says no and the frame's snapshot fields hold nothing new (no client-persisted token, same turn serial as before the commit). Pending work (push events, deferred callbacks) is still flushed, and the client's loading state still ends with the batch's `async_complete` frame. A result that changes state, through `handle_async_result` or by mutating a list in place in the callback, still patches; a write the change detector cannot see (an attribute on a model instance) needs `set_changed_keys()`, as on the event path.
