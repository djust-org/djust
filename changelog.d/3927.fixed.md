- **An option whose value contains `&`, `<`, `>`, `"` or `'` is drawn as selected (#3927).** `{% combobox %}` decided "selected" by comparing the HTML-escaped option value with the raw selected value, in single mode (`value=`) and in multi mode (`selected=`), so a value such as `a&b` was never drawn as selected (no `combobox-option-selected` class, `aria-selected="false"`) while `ab` was. Both modes now compare the raw text of the option value and of the selection (as `str`, so an integer `1` still matches `"1"` and `None` still matches `None`), and escape only what they write; `a&amp;b` as a raw value stays a different value from `a&b`, and a marked-safe or lazy value is compared by its text, not by its marker. The same escaped-versus-raw comparison was in three other places, all fixed: the native `dj_select` handler (`selected`), the native `dj_radio` handler (`checked`; the Django tag already compared raw, so the two engines disagreed), and the class-based `DependentSelect`. `dependent_select`, the data-table select filter and `dj_select` on the Django engine compare two values escaped the same way, or two raw ones, and are unchanged.
