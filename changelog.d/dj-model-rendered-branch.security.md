- **`dj-model` accepts only fields bound in the branch the template rendered.** The `update_model` allowlist was every static `dj-model="<field>"` binding in the template source, across all `{% if %}` branches, so a field bound only inside a branch that was not rendered for a view instance (for example `{% if user.is_staff %}<input dj-model="note">{% endif %}`) was still writable by that instance's client. The static set is now narrowed, on every render, to the `dj-model` element attributes present in that render's HTML (parsed as an HTML5 tree; embedded child views keep their own allowlists), so the allowlist follows the condition as it flips. The rendered output only narrows the set and can never add a field the template does not bind. `allowed_model_fields` is unchanged.
