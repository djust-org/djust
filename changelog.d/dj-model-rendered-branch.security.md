- **`dj-model` accepts only fields bound in the branch the template rendered.** The `update_model` allowlist was every static `dj-model="<field>"` binding in the template source, across all `{% if %}` branches, so a field bound only inside a branch that was not rendered for a view instance (for example `{% if user.is_staff %}<input dj-model="note">{% endif %}`) was still writable by that instance's client. A binding now counts only when its template text rendered for the current state: bindings on always-rendered paths are granted as before, and a binding inside an `{% if %}`/`{% for %}` branch, an include, a custom block tag or a lazy site is checked on every render with a bindings-only render of the current state (no render cache is touched and inline custom tags are not run). Embedded `{% live_render %}` children record the template text their render executed, under Django's engine and djust's own backend alike. Rendered data — an unquoted `attr={{ value }}`, a `dj-model="{{ field }}"`, `|safe` HTML — can never add a field. The allowlist follows the condition as it flips; `allowed_model_fields` is unchanged.
