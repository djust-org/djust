- **A filtered rebinding of a top-level single model reads its relation empty through `DjustTemplateBackend` (#3902).** `{% with q=user|default:user %}{{ q.groups.count }}{% endwith %}` over ONE model passed as a top-level context variable rendered nothing where Django's own engine prints the count; so did `q.groups.exists`, `q.groups.first.name`, `{% for g in q.groups.all %}`, a model method that returns a queryset, a method call on the model through the rebinding (`{% with q=obj|default:obj %}{{ q.describe }}{% endwith %}`), a `*_id` attname, and `{% if user in users %}`. `DjustTemplate.render` replaced the model with a dict of its fields before the engine saw it, so a filtered operand (which registers no loop alias) had no manager and no relation to read. A plain render is not state, so the model now reaches the engine whole, as a list row has since #3888: a **floored live handle**, checked against the serialization floor on every attribute read, with the same refusals (underscore-prefixed names, Python-defined classes and modules, a function's `__globals__`, a UUID is its text, a Python-defined `tzinfo`, a dict's model keys). A model reached through a context processor (`request.user` as `user`, a lazy object) takes the same route. `serialize_value(for_render=True)` also stops treating a model as a file: it asked `hasattr(value, "url") and hasattr(value, "name")`, which a model with a `name` field and a `url` field satisfies, so `{{ link }}` over a list of such rows rendered the row's URL instead of its `str()`, and a row whose `url` property raised anything but `AttributeError` failed the whole render. **Behaviour changes for a template that depended on the old dict (top-level model, `DjustTemplateBackend` only; each was run against the old and the new code):** **a bare `FileField` now prints its stored NAME, as on Django, not its URL** (`{{ doc.attach }}` printed the URL and now prints the stored name, which has no leading slash; `{{ doc.attach.url }}` prints the URL on both), so `<img src="{{ profile.avatar }}">` written against the old dict must become `<img src="{{ profile.avatar.url }}">`; the model is no longer a mapping or an iterable of field names, so `{% for f in user %}` and `{{ user|unordered_list }}` now fail the render (a `RuntimeError`; Django raises `TypeError`) where they iterated the field names, `{{ user|join:"," }}` is `str(user)` where it was `id,pk,__str__,...`, `{{ user|pluralize }}` is empty where it was `s`, `{% for k, v in u.items %}` renders empty and `{% if 'username' in u %}` is false, as on Django; `{{ u|pprint }}` and `{{ u|json_script:"x" }}` print the model's `str()` where they dumped its fields (Django's `json_script` raises for a model), so code that reads such data in JavaScript must build the data explicitly; and a custom Python FILTER that receives the model gets the floor proxy (attribute reads work, `row["field"]` does not) where it got the dict (a `simple_tag` already received the proxy, so nothing moves for tags), and a filter that `copy.copy`s, `copy.deepcopy`s or pickles the model now gets `copy.Error` / `pickle.PicklingError`. A bridged or native tag argument is still the same denylist dict text, byte for byte. **Not in this change:** a `LiveView` holds the model as state (ADR-027: client payload, msgpack, change detection), so the same template still renders empty there (#3936).
