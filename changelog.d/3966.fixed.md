- **`FormSetHelpersMixin.add_row` / `remove_row` (and the module-level helpers) dropped `instance`, `queryset` and every other formset argument (#3966).** They rebuilt the formset as `formset_cls(data, prefix=prefix)`: an inline formset lost its parent after one "Add row" (saving then created items with no order) and a model formset fell back to the model's whole table, where a posted row id outside the view's queryset would be saved. `add_row()` / `remove_row()` now take `**formset_kwargs` and pass them through, and the mixin gets `get_formset_kwargs(name)` (default `{}`; `data` and `prefix` are refused) which both handlers call and `mount()` can use to build the same formset. When the bound data has no management form yet (a view that starts with `_formset_data = {}`) and formset kwargs are given, the formset those kwargs build is the starting point, so the rows it already shows are kept; passing the kwargs alone would still have shown only the new row. With no formset kwargs nothing changes. Regression tests in `python/djust/tests/test_formset_kwargs_3966.py`.
