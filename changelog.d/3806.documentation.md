- **A row's `__str__` is documented as public text (#3806).** `djust_exclude_fields`, `djust_serializable_fields` and the serialization floor decide which fields of a row a template can read; they do not decide what `str(row)` says, because `"__str__"` is an identity key every serialized model carries (and Django's own engine prints the same text). A model whose `__str__` prints a field the floor withholds therefore shows that field's value in `{{ row }}` while `{{ row.that_field }}` is empty. `docs/SECURE_DEFAULTS.md` (section 1) and `docs/SECURITY_GUIDELINES.md` (Common Vulnerabilities 8, and the review checklist) now state the paths that ship it (a top-level loop over a QuerySet, a model in the context, a foreign key read whole, a row reached through `.all`, and on the `DjustTemplateBackend` a QuerySet's `.first` / `.last`), that the exclusion and allowlist rules do not constrain it, the Django parity, and the author guidance: build `__str__` from public fields only. No behaviour changes. Pinned, with Django's engine as the control, in `python/tests/test_row_str_is_public_text_3806.py` (which also records, as a strict `xfail`, that a LiveView attribute that is a top-level QuerySet renders `{{ rows.first }}` as nothing: it withholds more than documented, never less).
