- **Defining `_drain_announcements` or `_drain_focus` on a `LiveView` is deprecated** (#3629, follow-up to #3503). The WebSocket consumer and the SSE runtime drain these two duck-typed hooks behind `hasattr` and send an `accessibility` / `focus` frame, but nothing in djust defines them, so no built-in API ever queued an announcement or a focus command, and the shipped client has no `window.djust.accessibility` object to receive the frames unless the application's own script assigns one. The HTTP fallback never drained them, so a view that defined them lost them there silently. The frames are wire-protocol and `djust.d.ts` types the client object, so rather than delete the flush (or add a producer and a client half for a feature the 2.0 line has already removed, #3539) a view class that defines either hook (in its own body or through a mixin) now emits one `DeprecationWarning` per hook at its `class` statement, naming the removal (no earlier than 2.0.0) and the replacement: a `role="status"` live region the view renders, and `JS.focus()` through `push_commands()`, which every transport carries (a live region announces only a changed text, so a repeated identical message needs the alternating-suffix workaround in the guide). Behaviour is unchanged until 2.0.0. New: an "Announcing a change and moving focus from the server" section in the accessibility guide and an entry in `API_STABILITY.md`.
