- **`sync_turn_wrapper`: the teardown hooks, the private-state restore and three more missed hops now enter a step, and the structural pin that should have found them is rebuilt (#3646).** Hardening follow-up to #3637. Rebuilding the pin to actually verify what it allows turned up real hops that ran an application hook (or a row read) on a worker thread with no wrapper entry: (1) a released view's teardown hooks `_on_sticky_unmount()`, `_cleanup_on_unregister()` and `_cleanup_uploads()` are now `"lifecycle"` steps wherever the release runs on a worker thread (SSE navigation, the release of a view mounted beside the page, `response.close()` of an unstarted stream, and a WebSocket `live_redirect` that discards a sticky child whose auth now fails via `_preserve_sticky_children`); on the event loop (the WebSocket release, the SSE stream's own close) they stay unwrapped, since a wrapper that opens a transaction raises there. A wrapper that raises on entry no longer skips a teardown hook (the failure is logged and the hook runs without the scope). (2) `_restore_private_state()` is a `"lifecycle"` step: it re-fetches private model references (`Model.objects.get`) and assigns with `setattr`, so under row-level security a private model attribute came back `None` after a reconnect. (3) the worker-pool server-push turn called the push handler raw in its one hop, while the stock turn enters a `"hook"` step. (4) a `{% live_render lazy=True %}` child's `mount()` and `get_context_data()` ran raw when its slot was filled; they are `"mount"` and `"render"` steps now. (5) the per-event signed-snapshot refresh called `_capture_snapshot_state()` raw (the mount twin was stepped in #3637). The pin (`test_sync_turn_structural_pin_3646.py`, moved out of the #3637 test) is keyed by (file, enclosing function, target text) instead of a bare name, so a nested helper named `run` / `call` / `turn` or a raw `component.render` no longer hides; it sees the bare `@sync_to_async` decorator, aliased imports, `SyncToAsync`, `executor.submit`, `threading.Thread` / `Timer` (and a `Thread` subclass) and `anyio.to_thread.run_sync`; every hand-off it allows is verified (a leaf must enter its step, a plumbing hop may not reach a stepped hook outside a step unless it declares it); and the documented-override points are derived from every class in the package, each with a checked `stepped:<step>` / `inside:<steps>@<function>` / `unwrapped:<category>:<reason>` disposition. The guide's "entries per request" list now includes `handle_params`, the second render and the POST event step (measured, and pinned by a test), and its "Not wrapped" text states which thread runs each teardown hook. Review follow-up: every `inside:` disposition in the hooks table is now checked by running the hook with a recording wrapper (it had asserted `inside:render` for hooks that a template tag calls, which run with no step open: `as_live()` / `as_live_field()`, the `field_value` filter, form adapters, component `get_context_data()` / `_render_custom()`, `_on_sticky_update()`, `get_template()`; of the 34 `inside:` entries 16 were exactly right, 7 listed steps that never ran, 3 missed that the hook also runs with no step open, and 8 named a step that was not open); those are now `unwrapped:template-time` and the guide has a "Not wrapped: template-time form and tag hooks" section stating that a row read there (a `ModelChoiceField` queryset) runs without the wrapper scope. `_restore_private_state()` is a guarded step, like `_restore_snapshot()`, so a wrapper whose `__exit__` swallows an exception can no longer turn a failing private-state restore into a silent partial one. The pin also reports a `functools.partial(sync_to_async, ...)` factory. New cases in `python/djust/tests/test_sync_turn_structural_pin_3646.py`, `python/djust/tests/test_sync_turn_inside_audit_3646.py` and `python/djust/tests/test_sync_turn_lifecycle_gaps_3646.py`.
