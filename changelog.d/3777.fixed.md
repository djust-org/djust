- **`{% for g in u.groups.all %}{{ g.name }}{% endfor %}` over a QuerySet renders the related rows on a LiveView and under `DjustTemplateBackend`, as Django and `_rust.render_template` do (#3777).** The Rust queryset serializer (`serialize_object_with_paths` in `crates/djust_live/src/lib.rs`) walked the extracted paths `groups.all` / `groups.all.name` with `getattr`: `groups` is the related manager and `all` is its *bound method*, which has no `name`, so it shipped `{"groups": {"all": {}}}` and the loop ran over an empty dict. The Python codegen twin (`python/djust/optimization/codegen.py`) has always iterated `.all()`; the Rust one never did, and the key-count fallback to that codegen cannot fire because the `groups` key is present. Only a QuerySet was affected, so a `list[Model]` of the same rows rendered the names. Sibling spellings of the same missing step were wrong too and are fixed with it: `{{ u.groups.all|length }}` counted the characters of the QuerySet's `repr` (41 for a two-row relation), `{% if u.groups.all %}` was true for an *empty* relation, and `u.groups.all.0.name` was empty. This holds for a custom QuerySet class (`SomeQS.as_manager()`, which a related manager's `all()` hands back) as well as a plain one: the check is an `isinstance`, not a class-name test. Every row reached through `.all` goes through the serialization floor exactly as a row reached any other way does (`password`, `is_superuser`, `is_staff`, a model's `djust_exclude_fields` and `djust_serializable_fields`), at every depth of a chain. A called `all` still goes through the one `template_call_guard` (#3772), so a related manager whose `all` is marked `alters_data` or `do_not_call_in_templates` is never run and its name is omitted. A raising `all()` is no longer swallowed: only the two exceptions the codegen catches (`TypeError`, `AttributeError`) become an empty list; a database error propagates to the caller's existing `[JIT ERROR]` handler, which logs it and falls back, instead of rendering a user with no groups. Rows that are plain `dict` / `list` / `tuple` data (a model *method* named `all`) keep their data. Pinned through `DjustTemplateBackend`, a LiveView's HTTP GET, its WebSocket mount and the serializer itself, with Django's engine as the control and real rows (`python/tests/test_queryset_all_traversal_3777.py`, `python/tests/test_queryset_all_floor_and_errors_3777.py`). Same-symptom paths this does not reach (a QuerySet nested in a dict value, `.all.count` / `.all.first`, no row cap) are tracked at #3788.
