- **Four intermittent `python-tests` failures on `main` were timing races in the tests, not framework bugs** — each was reproduced deterministically by forcing the interleave, and none is a product defect. (1) `python/djust/tests/test_view_replacement_teardown_3244_3245.py` read the presence list when a replacement `mount` frame arrived, but a replaced view is untracked in `receive()`'s `finally`, after that frame (by design, #3254): it now waits for the consumer to finish the frame with `frame_barrier` (a ping/pong) in `python/djust/tests/_ws_frames.py`. (2) `python/djust/tests/test_live_auth_denials_and_wrappers.py` timed out in `communicator.connect()` at Channels' 1 s default, because the root `conftest.py` lengthened four of the seven communicator waits (#3464) and left `connect`, `wait` and `get_response` out; the list is now derived from the Channels classes and pinned in `python/djust/tests/test_ws_communicator_defaults_3464.py`. (3) `python/djust/tests/test_stream_terminal_flush_3227.py` passed an explicit `timeout=3` that overrode the 30 s default; it now waits for the frame. (4) `python/djust/tests/test_ratelimit_post_fallback.py` (#3707) drained a `rate=1` bucket and asserted it stayed empty, which holds only while under a second of wall clock passes; the bucket clock is now owned by the test, as it is in the other rate-limit tests that drain a bucket and assert it stays empty. The likely shared cause of (2) to (4) is a worker stalling for seconds (not witnessed in the CI logs, which carry no GC data): a full local run on Python 3.12 measured generation-2 GC pauses of median 0.32 s and up to 3.4 s in a worker holding every imported test module, and `gc.freeze()` when collection finishes (`conftest.py`) cuts that to median 0.10 s, max 1.05 s (#3692, #3707).
