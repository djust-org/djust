- **The template-library bridge no longer treats `tabs` and `split_pane` as bridgeable, and no longer lets one entry decide for a whole library** — `_may_override` ignored the raw-block registry, so djust's native raw handlers for `tabs` / `split_pane` were counted as `djust_components`' and bridged as a dead handler (their output is unchanged: byte-identical before and after), and a library could have displaced a djust raw-block handler. Separately, a library's module-keyed policy and #3655's "is this djust's own?" log level came from the first-registered entry, so they changed with the import order of a multi-module library and one re-exported function could classify a third-party library as djust's. Policy is now keyed on the module every entry shares, the shared-name check compares an order-independent identity, and the log level reads the refused tag's own module (#3668).
