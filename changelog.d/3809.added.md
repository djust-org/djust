- **`self.server_push()`, `self.live_transport` and `tick_interval` over SSE (#3809).** A view can now push from its own code on any live transport: `await self.server_push("handle_x", {...})` runs the same `push`/`server_push` turn the WebSocket runs for `push_to_view()` (turn chain, render lock, busy deferral in arrival order, one render, a `source="broadcast"` frame) on a WebSocket **or an SSE session**, and is a documented no-op returning `False` on the HTTP render, an HTTP fallback POST's fresh instance, `LiveViewTestClient`, and a closed or replaced view. `self.live_transport` (`"websocket"`, `"sse"` or `None`) answers "is a live transport attached?" and is already set inside `mount()`. `tick_interval` + `handle_tick()` now tick over SSE (they stood still), stopped by a close, a navigation or a failed mount. `push_to_view()` groups, push scopes and `db_notify` stay WebSocket-only over SSE; documented in `server-push.md` and the `sse.py` limits.
