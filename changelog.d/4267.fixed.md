- **`dictsort` / `dictsortreversed` by a method key the template also prints renders empty, as on Django (#4267).** `{% for u in users|dictsort:'get_username' %}{{ u.get_username }}{% endfor %}` sorted the rows by the called value, because the path serializers file a called method's result where a column would be; Django's `dictsort` never calls a method key, compares bound methods and renders `""` (one row is never compared and still renders). Both path serializers (the Rust `serialize_queryset` and the generated codegen serializer) now file the names they called under `__djust_called__` as a `djust.serialization.CalledKeys` tuple, read by the engine as a new `Value::CalledKeys` marker (tagged in msgpack state, a plain list in JSON, never minted from data), and the engine's `dictsort` hands Django an unorderable object for those keys. Explicit LiveViews and `DjustTemplateBackend`, `QuerySet` and `list[Model]` rows.
