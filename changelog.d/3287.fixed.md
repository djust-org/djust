- **Uploads work with default settings again (#3287).** `allow_upload()` and `UploadConfig` defaulted `chunk_size` to 64 KiB, which the server sent to the client in preference to the client's own 63 KiB default. A 64 KiB chunk plus its 21-byte frame header is 65,557 bytes, over the default `max_message_size` (65,536), so every upload larger than one chunk was rejected as "Message too large". The default is now 63 KiB (`djust.uploads.DEFAULT_CHUNK_SIZE`), and a slot's `chunk_size` is clamped to `max_message_size` minus the frame header (with a warning) so a lowered limit or an explicit large value can't reproduce the failure. Resumable uploads that are in flight when a deploy ships this change restart from the beginning: the server's persisted chunk ranges are indexed in 64 KiB units while the client now sends 63 KiB chunks, so a resume across the deploy cannot line up.
