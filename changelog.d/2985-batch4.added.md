- **DashboardGrid, MentionsInput, CursorsOverlay and CollabSelection now ship the interactions their docstrings describe (#2985, batch 4).** Each rendered a `dj-hook` that no shipped script answered; `components/static/djust_components/dashboard-grid.js`, `mentions-input.js`, `cursors-overlay.js` and `collab-selection.js` now do, and the catalogue page of each includes its script. `DashboardGrid`: drag a panel by its header to move it and its bottom handle to resize it (also by touch, and in right-to-left or scaled grids), with the arrow keys on a focused panel (Space/Enter grabs, arrows move, Shift+arrows resize, Enter drops, Escape cancels); a dashed cell previews the drop and the server stays the authority, receiving `{id, col, row}` through `move_event` and `{id, width, height}` through `resize_event` in whole grid units (untrusted: the docstring has handlers that validate and clamp them). `MentionsInput`: typing `@` offers the people in `users`, filtered by the start of any word of their name, as a proper combobox; Enter or Tab or a click inserts `@Name`, and Enter submits `{text, mentions: [ids]}` (the ids of the people still mentioned, with the plain input event's `value`, `field`, `key` and `code` kept; untrusted). `CursorsOverlay`: keeps name labels inside the overlay and off each other, announces people appearing and disappearing, and eases cursors unless the user prefers reduced motion; it stays presentational, fed by the app's presence data. `CollabSelection` gains an optional `target` selector: with it the selections' `start`/`end` offsets index the text of that element, the ranges are highlighted in the page's text with the CSS Custom Highlight API (no page node is touched) and each name is placed above its range and follows scrolling and edits; without it the component shows each selection's text where it is rendered, as before. The only markup change is an added `data-target` on a CollabSelection that was given a `target`: a comparison of 276 renders (hostile text, junk data, boundary values, all three render paths) against the previous release is identical. The scripts register in `window.DjustHooks` and only when neither hook registry already holds that name, so an app's own hook is never replaced. Components from the issue still without a script: the five of batch 5, and the optional `resize_event` of ResizablePanel and `toggle_event` of FileTree.
