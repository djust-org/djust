- **`scripts/check_pr_body.py` and a non-gating `pr-body-lint` workflow: lint a PR body for placeholders and dangling references (#3713).** It fails on unresolved placeholder tokens (`TBD`, `XXX`, `<N>`, `N tests`, `#NNN`) and on a `#<number>`, a `github.com/<this repo>/(issues|pull)/<number>` URL or an `issuecomment-<id>` that does not resolve in this repo. It leaves fenced and inline code, HTML comments, `#` inside URLs, the text of a link (the target is checked, not the label), `owner/repo#N`, a word or slash glued to the `#`, and HTML entities alone; a line carrying `pr-body-lint: ignore` is skipped. The logic is a pure function with the resolver injected; a lookup that could not be made (network, rate limit) is `unchecked` and does not fail the run. The workflow (`.github/workflows/pr-body-lint.yml`) is `continue-on-error: true` and is not in the `test-summary` condition, so it cannot block a merge until it has run green on the runner once (the rc4 rule); it passes the body through an environment variable, never into the shell. Run over the last 200 merged PR bodies it reports no findings; the first pass over the last 40 found one false positive (a Dependabot body linking another repo's issues as `<a href=...>#363</a>`), which is why link text is not read as a reference. 39 regression cases in `tests/unit/test_check_pr_body_3713.py`; `scripts/check-pr-body-gateoff.json` (run with `scripts/gate_off.py`) drops 28 rules in turn and every drop turns a test red. It does not cover claims about code, which stay with the differential-test habit. `docs/patterns/unverified-claim.md` also records that `gh run view --log-failed` and `--log` show a truncated view of a long job and to read the job log with `gh api --allow-escape-sequences repos/<repo>/actions/jobs/<id>/logs`.
