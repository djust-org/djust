- **`scripts/check_pr_body.py` and a non-gating `pr-body-lint` workflow: lint a PR body for placeholders and dangling references (#3713).** It fails on unresolved placeholder tokens (`TBD`, `XXX`, `<N>`, `N tests`, `#NNN`), also inside a URL (`.../pull/NNN`, `.../runs/XXXXXXXX`, `#issuecomment-TBD`), and on a `#<number>`, a `github.com/<this repo>/(issues|pull)/<number>` URL, an `<this repo>#<number>` or an `issuecomment-<id>` that does not resolve in this repo. It leaves fenced code (including one opened on a list-item line), inline code, `<code>` / `<pre>`, HTML comments, `#` inside URLs, the text of a link (the target is checked, not the label, for inline and reference-style links), `owner/repo#N` of another repo, a word or slash glued to the `#`, `List<N>` and HTML entities alone; 4-space indented code is not recognised; a line carrying `pr-body-lint: ignore` is skipped. The logic is a pure function with the resolver injected; a lookup that could not be made (network, rate limit) is `unchecked` and does not fail the run. Its work is bounded: at most 50 distinct references are looked up per body and the rest are reported as one `too many references to check` note, and every pattern is linear (a 64 KiB body of `[` or `<a>` is instant). `--annotate` prints `::warning` lines so findings show on the run summary of a job that is green. The workflow (`.github/workflows/pr-body-lint.yml`) is `continue-on-error: true` and does not appear in `test.yml`'s `test-summary` condition, so it cannot block a merge until it has run green on the runner once (the rc4 rule); a test parses the YAML and pins the trigger (`pull_request` only), a read-only token, no `${{ }}` in any `run:`, and the body arriving only through an environment variable. Run over the last 200 merged PR bodies it reports no findings; the first pass over the last 40 found one false positive (a Dependabot body linking another repo's issues as `<a href=...>#363</a>`), which is why link text is not read as a reference. 61 regression cases in `tests/unit/test_check_pr_body_3713.py`; `scripts/check-pr-body-gateoff.json` (run with `scripts/gate_off.py`) drops 48 rules in turn and every drop turns a test red. It does not cover claims about code, which stay with the differential-test habit. `docs/patterns/unverified-claim.md` also records that `gh run view --log-failed` and `--log` show a truncated view of a long job and to read the job log with `gh api --allow-escape-sequences repos/<repo>/actions/jobs/<id>/logs`.
