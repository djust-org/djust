- **Text in an SVG or MathML `<style>` / `<script>` is serialized as escaped text.** The VDOM wrote the text of any element named `script`, `style`, `noscript`, `xmp`, `iframe`, `noembed`, `noframes` or `plaintext` verbatim, by tag name alone. The HTML serialization rules apply that only to HTML elements: inside `<svg>` or `<math>` these are foreign elements, whose text the parser decodes, so it has to be escaped again when written back (`&lt;` stays `&lt;`). The serializer now tracks the namespace while it writes (`svg` and `math` switch to foreign content; `foreignObject`, `desc`, `title`, MathML text elements and HTML `annotation-xml` switch back), so re-parsing the HTML gives the same tree. HTML `<style>` and `<script>` output is byte-identical, and so is SVG CSS without `<`, `>` or `&`. HTML raw-text content is written verbatim exactly as the HTML serialization algorithm writes it, including a script that holds `</script>` inside `<!-- … -->` (the legacy `document.write` pattern) and `<plaintext>`. Only text read as HTML raw text away from its real context (an inserted `{% if %}` block inside `<svg>`, which the client parses as HTML) is escaped, and only when the tokenizer would end the element before the text ends. A `<noscript>` read that way is always escaped: the client parses the payload with scripting disabled, where `<noscript>` holds markup, not raw text. Such an element that holds child elements (an SVG `<style>` containing another `<style>`, possibly deeper down), and likewise an SVG `<title>` or `<textarea>` holding elements (read there as an HTML RCDATA element), has its whole content written as escaped text, since a descendant's end tag would otherwise end the element when the payload is read as HTML. The `render_binary_diff` text-only fast path now updates a text node only when the HTML's text runs and the tree's text nodes line up one for one, and never inside a raw-text element: it mapped changes by byte offset, so dropped whitespace or text outside the root sent a change to the neighbouring node, and it decoded `&lt;` inside a `<script>`. The text fast paths (the in-place update, `try_text_only_vdom_update`, `try_text_patches`, and the fragment and text-region paths of `render_with_diff`) also require each text node to sit in the element the source has open around its text: text directly inside a `<table>` is moved before the table by the parser, so two equal texts could line up in the wrong order and a change was applied to the other node. Such updates, and any start tag the parser would move out of a table, now take the full parse. The text fast path also falls back to a full parse for every `<style>` or `<script>` that follows an `<svg>` or `<math>` start tag; it used to count `</svg>` / `</math>` to decide when foreign content closed, and the tree builder ignores some of those end tags (a stray `</math>` inside `<svg>`, an `</svg>` inside `foreignObject` or `desc` content), so a text change could still be sent to the wrong node. The serializer also starts from the real namespace of the root: the parser reports it, so a `dj-root` on an element inside `<svg>` or `<math>` (`<svg><g dj-root>`) writes its `<style>` / `<script>` text escaped, as does its `dj-update="ignore"` cache, and an `InsertSubtree` payload knows whether its parent is HTML (its raw text is then verbatim) or foreign; the text fast paths run only under an HTML root. Regression cases in `python/tests/test_vdom_foreign_raw_text.py`, `python/tests/test_vdom_html_raw_text_verbatim.py` and in `crates/djust_vdom/src/lib.rs`.
