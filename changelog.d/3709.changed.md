- **Test waits on Channels communicators take the 30 s default again; a ratchet keeps explicit short timeouts from regrowing (#3709).** An explicit `timeout=3` on `receive_json_from` / `receive_from` / `receive_output` / `connect` / `disconnect` overrides the 30 s default the root `conftest.py` installs (#3692), so the wait is a 3 s wall-clock bound again; a stop-the-world GC pause was measured at 3.38 s (#3708). 404 such waits in 152 test files now wait with the default, 36 helper definitions whose short `timeout=` default was forwarded to a wait (`_receive_until(..., timeout=3)` and its siblings) default to 30 s, 25 `try: await ws.receive_*(timeout=N) / except: pass` drains of the connect frame (which always arrives) and 2 read-until-the-terminal-frame loops became plain waits; the one such drain that reads a `websocket.close` is an absence window and is kept. `python/djust/tests/test_communicator_timeouts_ratchet_3709.py` counts, by AST, an awaited communicator wait with a short numeric timeout, a helper with a short forwarded default, and a call to such a helper with a short literal, per file against a baseline; it exempts only absence idioms (`receive_nothing`, the last line of a `pytest.raises` block, a `try` whose handlers only `pass` / `break` / `continue`). **It does not cover everything**: waits whose `timeout` is a variable (`remaining`, `deadline`), `asyncio.wait_for(..., <10)` and `asyncio.timeout(<10)` (not communicator waits), helpers imported from another module, and the exempt drains are counted in `UNCOVERED_BASELINE` (which also only falls) but not converted, so #3709 stays open for them. The baseline holds one entry on purpose: `python/djust/tests/test_ws_communicator_defaults_3464.py` pins that an explicit timeout still wins over the default, so it passes `timeout=0.01`.
