- **`ResizablePanel(resize_event=...)` and `FileTree(toggle_event=...)` send what the reader did to the server (#2985).** Both are optional and additive. With `resize_event`, when a drag or key press on a ResizablePanel's handle ends the hook sends that event with `{"size": <whole pixels>}` (the panel's own `dj-resize` CustomEvent still fires); render the remembered size back as `initial_size`. With `toggle_event`, expanding or collapsing a FileTree folder (by click or keyboard, never by a server re-render) sends it with `{"path": ["src", "utils"], "expanded": true}`, the folder's name and its parents' names from the root down, so the server can remember which folders a user opened and render them with `expanded`; the page follows the server again once the two agree. Both payloads come from the browser and are untrusted: the docstrings show handlers that clamp the size and look the path up in the rendered tree. The only markup change is a `data-resize-event` / `data-toggle-event` attribute on the component's root when the kwarg is set: a comparison of 864 renders (hostile text, junk data, boundary values, all three render paths) against the previous release is identical without it.
