- **`{% json_viewer data=v %}` renders a `datetime` / `date` / `Decimal` as Django does (#3756).** The Python tag dispatches on `isinstance(value, ...)` and spells every type it does not know as `str(value)` with no type modifier (`<span class="dj-json__value">2024-03-15</span>`); the native handler was handed the engine's stand-in for a value it cannot carry (`str(datetime)`, a `float` for a `Decimal`) and dispatched on *that*, printing `dj-json__value--string` with quotes and `--number`. The same went for a `UUID`, an `Enum`, a `Path`, `bytes`, a `set` and a `tuple`, and for a `datetime` / `date` / `Decimal` / `UUID` nested in a dict or a list. A handler can now declare `TYPED_ARGS = True` (`rust_handlers.TYPED_ARGUMENT_TAGS`, read by `registry.rs` at registration): the engine resolves each `key=<expression>` operand through the same floored walk `{{ }}` uses (`get_value`, which re-protects every segment of a dotted path) and hands the typed Python value to the handler in the context under a reserved key; `json_viewer` reads its `data` from there, with the operand's runtime-safe flag (`{% with p=x|safe %}`, a `mark_safe`d value) carried through the channel so a safe operand is raw as in Django (`typed_operands` uses `get_value_safe`; without it the flag was dropped and the operand over-escaped; a hostile unsafe value stays escaped, tree and raw `<script>` copy, byte for byte against Django, `python/tests/test_typed_args_provenance_3770.py`). It deliberately stays native. A first version of this change moved it onto the `{% load %}` bridge so Django's own node could dispatch on the type, and the bridge walks raw objects with no serialization floor: `{% json_viewer data=form.instance.password %}`, `data=f.form.instance.password` in a form loop, `data=form.fields.owner.queryset.first.password`, `data=obj.user.password`, `data=obj.users.first.password` and `data=view.user.get_session_auth_hash` all printed the hash, which `{{ }}` and the native handler refuse. Every one of those is a test now (`python/tests/test_typed_args_floor_3756.py`). The tags that depend on a value's *type* are measured, not guessed (`scripts/lib/template_library_parity/typed_values.py`, 208 tags x 15 types): the Python tag is run on a value and on the stand-in the engine would hand a handler, and a tag whose output differs depends on the type. Of the 781 type-sensitive cells, the tags still wrong for a type a template realistically passes (`datetime`, `date`, `time`, `timedelta`, `Decimal`, `Enum`, `Path`) are four, all a date or path in a CSS-class / URL slot (`theme_mode_toggle`, `theme_preset_selector`, `theme_switcher`, `map_picker`); they are recorded in `KNOWN_TYPE_LOSS`, which the test compares with the measurement in both directions (an entry that stops being wrong fails; a new loss fails until it is looked at), and the remaining isolated cells (a tuple, UUID, bytes or set in a text or number slot, and a tuple holding an `OrderedDict`) are tracked at #3768. A tag rendered through the bridge still has no floor (#3771).
