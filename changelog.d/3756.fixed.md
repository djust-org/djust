- **`{% json_viewer data=v %}` renders a `datetime` / `date` / `Decimal` as Django does (#3756).** The Python tag dispatches on `isinstance(value, ...)` and spells every type it does not know as `str(value)` with no type modifier (`<span class="dj-json__value">2024-03-15</span>`); the native handler was handed the engine's stand-in for a value it cannot carry (`str(datetime)`, a `float` for a `Decimal`) and dispatched on *that*, printing `dj-json__value--string` with quotes and `--number`. The same went for a `UUID`, an `Enum`, a `Path`, `bytes`, a `set` and a `tuple`, and for a `datetime` / `date` / `Decimal` / `UUID` nested in a dict or a list. `json_viewer` joins the tags rendered by the Python node through the `{% load %}` bridge (`rust_handlers.TYPE_ARGUMENT_TAGS`, `OBJECT_ARGUMENT_TAGS` is now the union of it and `ATTRIBUTE_ARGUMENT_TAGS`) and its native handler class is removed. The tags that depend on a value's *type* are now measured, not guessed (`scripts/lib/template_library_parity/typed_values.py`, 208 tags x 15 types): the Python tag is run on a value and on the stand-in the engine would hand a handler, and a tag whose output differs depends on the type. Of the 781 type-sensitive cells, the tags still wrong for a type a template realistically passes (`datetime`, `date`, `time`, `timedelta`, `Decimal`, `Enum`, `Path`) are four, all a date or path in a CSS-class / URL slot (`theme_mode_toggle`, `theme_preset_selector`, `theme_switcher`, `map_picker`); they are recorded in `KNOWN_TYPE_LOSS` and may only shrink, and the remaining isolated cells (a tuple, UUID, bytes or set in a text or number slot) are tracked at #3768.
