- **`LIVEVIEW_CONFIG["state_models_as_handles"]` now defaults to `True`.** A model, model list or QuerySet held as LiveView state is handed to the template as a floored handle for the render. A filtered rebinding (`{% with q=user|default:user %}{{ q.groups.count }}`) and a filtered loop operand read relations as Django does, and custom filters and tags receive the floor proxy (see #3949). State, change detection, the state backend and the client payload keep the serialized dict. Set it to `False` to restore the 1.x dict (kill-switch). A key the dict path already answers keeps it: a QuerySet whose `count` / `exists` / `first` / `last` the template reads, and rows the JIT serialized with the relations the template walks (prefetched, `queryset_all_row_cap` applied), so the overlay adds no query. A model inside a dict held in state keeps its dict (top-level keys only). A model whose `__str__` returns a `SafeString` still prints escaped on a LiveView. A legacy view whose QuerySet relation `.all()` raises a database error now raises it out of the render, as Django does, instead of logging it and rendering the rows without it. Per-sync cost measured on a 100-row held list: explicit 12.57 → 12.95 ms, legacy 1.10 → 2.15 ms. (#3936)
