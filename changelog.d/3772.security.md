- **A template that named a mutating callable ran it: `{{ users.delete }}` over a QuerySet deleted every row under `DjustTemplateBackend` and in a LiveView (#3772).** Django refuses, because `Model.delete` and `QuerySet.delete` carry `alters_data = True` and the engine never calls such a callable. The refusal existed where the Rust engine walks an object (`Context::maybe_call`), and `_rust.render_template`, which has no queryset step, was never affected. The call was made one step earlier. The Rust queryset serializer (`serialize_object_with_paths` in `crates/djust_live/src/lib.rs`, behind `DjustTemplateBackend.render` and the LiveView queryset JIT) walks the paths a template names and called every callable it found there with no `alters_data` / `do_not_call_in_templates` check; the Python codegen twin already had the check. So `{{ users.delete }}`, `{% for u in users %}{{ u.delete }}{% endfor %}`, `{{ u.save }}`, `{{ u.groups.clear }}`, `{{ u.groups.create }}`, `{{ g.user_set.clear }}` and `{{ g.user_set.create }}` each ran against the real rows. The reachable shapes are a QuerySet's rows and the related managers reached through them. A single model (`{{ user.delete }}`), a `list[Model]` and a top-level manager were already inert and stay so; they are kept in the test matrix as controls.

  The rule is now stated once, in `djust_core::template_call_guard` (`do_not_call_in_templates` first, then `alters_data`, Django's order), and both walkers ask it: the sidecar walk and the queryset serializer. A refused name is left out of the serialized row, exactly as a name the serialization floor denies is, so the template renders empty. The serializer's `.all()` call on a to-many attribute goes through the same guard. A callable with neither marker is still called (`{{ u.get_username }}`, `{{ u.groups.count }}`), as Django calls it. The order of the two reads is Django's: a callable carrying both markers is used as it is and prints as its repr, it is not refused as `alters_data`; that order is pinned in `crates/djust_core/tests/test_template_call_guard_3772.rs` and in `TestTheMarkerOrderIsDjangos3772`.

  Not changed: the fixed-name calls in `serialize_python_value` (`render()` on a component, four `get_*` names on a model), which a template author does not choose. Regression cases in `python/tests/test_alters_data_toplevel_3772.py`: every shape runs against a real table through `DjustTemplateBackend`, a LiveView and `_rust.render_template`, with Django's own engine as the control and a check that the detector sees a direct mutation.
