- **`sync_turn_wrapper` now covers `handle_tick()` and `handle_async_result()`, and the test client (#3625).** An app that opens a per-turn database scope in the wrapper (row-level security, a request-scoped context variable) had it in every step but these two: the tick and the hook that receives a `start_async` result ran on the worker thread with no scope, so rows read there came back empty or wrong. `handle_tick` is now the `"tick"` step (stock and `worker_threads` shapes) and `handle_async_result` an `"async"` step on every owner: the consumer, the runtime's explicit and legacy result turns, and embedded and sticky children. `LiveViewTestClient.send_event()`, `send_push()`, `trigger_info()` and `render_async()` (callback and `handle_async_result`) and `LiveComponentTestClient.send_event()` enter the same steps as the consumer, so a test of a handler no longer runs without the scope production gives it; an `async def` push or info hook is now run to completion (on a helper thread inside a running event loop) rather than left as an unawaited coroutine, and an `async def` `handle_async_result` or default-path `handle_tick` is refused with the same `TypeError` with or without a wrapper. A structural test pins the set of places that reference the two hooks and that each enters the step through the shared helper. The sync hooks that are still not wrapped (object-permission checks, `on_mount`, `connected`/`disconnected`, cursor and presence hooks, time-travel replay) are listed in the turn middleware guide and tracked in #3637. New cases in `python/djust/tests/test_sync_turn_wrapper_tick_async_3625.py`.
