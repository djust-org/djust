- **A view's `query_budget` is measured at run time, accepts event budgets, and is listed by `djust_audit` (#3701).** Follows #3686, where `query_budget` was read by `LiveViewSmokeTest` only. **Run time:** a view that declares a `query_budget` has the queries of each phase counted, on the thread that runs the step (a sync handler or `mount()` runs on a worker whose database connection a counter on the event loop would never see), and a phase over its number is a warning on the `djust._query_budget` logger while `DEBUG` is on or under pytest; with `LIVEVIEW_CONFIG["query_budget"] = "error"` the step raises `QueryBudgetExceeded` instead (`"warn"` measures whatever `DEBUG` says, `"off"` never). The meter hooks `djust.sync_turn.run_sync_step`, which every sync hop of every transport already goes through, so the HTTP GET, the WebSocket and SSE mount, `url_change`, events and the test client share one definition. A view with no `query_budget` pays one class attribute read per sync hop and installs nothing on the connection. **Event budgets:** `query_budget` takes `"event": n` (every `@event_handler`) and `"events": {handler: n}` (one handler, which wins), and the new `LiveViewSmokeTest.test_smoke_event_queries` calls each budgeted handler with the fuzz payloads plus `view_config[View]["event_params"]` and fails when a call ran more queries than its budget, whether or not `fuzz` is on. A handler named in `"events"` that no call succeeded for is an error rather than a pass, and one covered only by `"event"` is a `UserWarning`; a handler name the view does not have, or an `async def` / `@background` handler (nothing can measure those), is a `ValueError`, as is any other unknown key, so a budget nothing enforces is still rejected. One reader, `djust._query_budget.declared_budget`, serves the smoke test, the run-time meter, **V024** (a new Error check for an invalid `query_budget`) and `djust_audit`, and a test pins that nothing else reads the attribute; an event is the handler's own queries in the smoke test and at run time alike. An invalid `LIVEVIEW_CONFIG["query_budget"]` is **C029** at startup, and a request reads it as `"warn"` and logs that once instead of failing. **Audit:** `djust_audit` lists each view's budget, `(none)`, or `invalid: <reason>` (`query_budget_error` in `--json`, which never crashes over a bad declaration). Not measured: `async def` and `@background` handlers, `start_async` work and `handle_async_result`, ticks, the authorization hops, the `on_mount` hooks and `connected()` / `disconnected()`, a step nested inside another (an embedded `live_render` child's `get_context_data()`), and any database but the default. On an HTTP GET a view that overrides `get_context_data()` has it called twice (measured; framework behaviour, not changed here), and each pass is judged on its own, so a `render` or int budget under-reports the page. Documented in the testing guide, the smoke/fuzz guide, the `djust_audit` guide and the `LiveView` and testing API references.
