- **One `@rate_limit` budget per handler function, whatever name reaches it.** The shared store keyed buckets on the caller and the name the route used (the client-supplied `event_name` on WebSocket/SSE, the function name on the HTTP API), so a method reachable under two names (an alias attribute, or a second name bound in `mount`) had a separate budget per name. The bucket is now keyed on the function that actually runs (`__func__` of a bound method), accepted only when that function is declared on the owning class (or, for an ADR-031 component, on the class behind the bound proxy); only the exact builtin `staticmethod`/`classmethod` wrappers are unwrapped, and membership is compared with `is`. A handler whose identity cannot be determined this way (a property or other descriptor, a `functools.partial`, a callable instance, a function from an unrelated class) is refused with a named error rather than given a budget of its own, and two handlers that resolve to one key with different limit settings are refused rather than sharing the first one's settings. Functions made by one factory keep separate budgets. Tests: `python/djust/tests/test_ratelimit_post_fallback.py`.
