- **Closing an SSE stream now disposes a legacy view too (#3232).** Since #3221 a normal SSE close calls `SSESession.shutdown()`, but it disposed only explicit views: a legacy view's `start_async` / `@background` work kept running and could render into a queue nobody reads, its `wait_for_event` waiters stayed pending, its upload temp files stayed behind and its embedded children never ran `_cleanup_on_unregister`. `shutdown()` now gives a legacy view the WebSocket disconnect's legacy teardown (upload cleanup, waiter cancellation, child unregistration, Rust live-handle release), cancels its background work first as an explicit view's disposal does, and drops it from the session and runtime so a late result is discarded. As on the WebSocket, the legacy root's own `_cleanup_on_unregister` does not run. Every `shutdown()` caller gets this, including a rate-limit close. An EventSource reconnect's new session and view are untouched when the old stream closes. The explicit path is unchanged. New cases in `python/djust/tests/test_sse_legacy_close_3232.py`.
