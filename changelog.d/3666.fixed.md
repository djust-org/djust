- **A tag that takes an object renders under the Rust engine as it does under Django (#3666).** `{% field_error field=form.name %}` rendered nothing under the Rust engine and the error under Django: the engine hands a native handler its operands as strings and JSON, so a `BoundField` arrived as its widget HTML, a `Form` as its `str`, a `datetime` as `str(datetime)` and an item of a list as whatever `str` gives. The tags that take an object are measured, not listed by hand (`scripts/lib/template_library_parity/objects.py` renders every parameter of every tag with a value that records how it is used): `field_error`, `form_errors`, `combobox`, `rich_select`, `relative_time`, `avatar_group`, `conversation_thread`, `notification_popover` and `toast_container`. They no longer have a native handler class (`rust_handlers.OBJECT_ARGUMENT_TAGS`): each is registered as the `{% load %}` bridge handler, so the Python tag's own node renders it and the output is Django's by construction. They are registered up front, so they still work in a template that does not load the library. **Behaviour change:** the markup of `toast_container`, `notification_popover`, `combobox`, `relative_time` and `rich_select` under the Rust engine is now the Django tag's (`toast_container` is `dj-toast-container`, not `toast-container`), and a `{% toast_container %}` with no `toasts` is a `TemplateSyntaxError` as it is under Django (the handler used to read a context variable named `toasts`). Also behaviour changes: the six simple/inclusion tags among them now refuse an unknown keyword as Django does (see #3667), and `toast_container`, an inclusion tag, needs a template loader (`APP_DIRS` or `DIRS`) as it does under Django's engine, where the native handler needed none; per render the bridged tags are within 12% of the handlers they replace except `toast_container`, about 64 to 285 microseconds for three toasts (median of 400 renders, one machine). Not changed: a `Form` or `BoundField` bound by `{% for %}` or `{% with %}` inside the template still reaches a tag as its `str` (#3755); `json_viewer` renders a `datetime` differently in the two engines, a type dispatch the attribute-read measurement cannot see (#3756); a callable operand is not called by the engine as Django would. New `python/tests/test_native_handler_fidelity_3666_3667.py`; the parity baseline rows for the nine tags improve.
