- **`WizardMixin.next_step` ignored the step form a `dj-submit` posted, and `validate_field` did not validate (#3964).** A step rendered as `<form dj-submit="next_step">` was validated against `wizard_step_data` only, so unless every field had also sent a `validate_field` event the step failed as empty (or passed on stale values). `next_step` now merges the fields the CURRENT step's form declares (and nothing else: not the CSRF token, not another step's fields) into the step's data before validating, through the same `max_form_fields` / `max_form_data_size` / `max_form_members` bounds as every other client-named key (a post past them is refused whole); `submit_wizard` does the same for the last step. `validate_field` now also cleans that one field (`field.clean()` and the form's `clean_<name>()`, as `FormMixin.validate_field` does) and puts the failure in `wizard_step_errors[step][field]` while the person types. The wizard guide now says that `wizard_rendered_fields = ()` skips the per-render `field_html` work for a template that writes its own inputs. Regression tests in `python/djust/tests/test_wizard_submitted_step_3964_3965.py`.
