- **LogViewer stopped following a stream that trims old lines, and never resumed (#2985).** With `max_lines` set, trimming shrinks the content and the browser may clamp the scroll position; the scroll event for that clamp arrived after more lines had been appended and was read as the reader scrolling up, so from the third burst on the log ended a few pixels short of the newest line. The hook now only treats the position moving up as the reader scrolling when wheel, touch, key or pointer input on the log came just before it (or a pointer is held, as in a scrollbar drag), so a clamp, whenever its layout happens, never stops the follow, and a reader who scrolls up during a stream that trims every frame stays up. As a consequence, code that sets the log's `scrollTop` itself no longer stops the follow. The new Terminal hook has the same follow logic and the same fix.
