- **A formset whose form adds fields in `__init__` can mark rows for deletion (#3861).** `remove_row` exempted from `max_form_fields` only the fields a form class declares (`form.base_fields`) and an inline formset's foreign key, so a form that adds `d1`, `d2`, `d3` in `__init__` counted all of their seeded row keys: with 600 rows (1,800 such keys) none of the 600 deletes was stored. The exempt names now come from `formset_cls().empty_form.fields` (the unbound form, so they are the class's and never the client's), read once per formset class and cached weakly; a form that cannot be built without arguments keeps the declared fields exempt as before and logs the fallback once. Tests added for the inline foreign key (a real `ContentType` / `Permission` inline formset) and for the `TOTAL_FORMS` clamp's `max` against `min`. #3867 adds tests only (no behaviour change): the kept-rows sidecar entry never replaces an explicit entry, never ships for a name outside the context, and nothing is kept for a QuerySet reached through a container.
