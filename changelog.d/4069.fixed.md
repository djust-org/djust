- On an explicit view (the default policy), a loop row's relation walk over a QuerySet or model list supplied by `get_context_data()` now renders what Django renders: `{% for u in users %}{{ u.groups.count }}` / `{% for g in u.groups.all %}` / `{{ u.groups }}` / `{{ users.0.groups.all.0.name }}` and a reverse accessor (`g.user_set.all`) rendered empty. The native render now keeps the evaluated rows (never the QuerySet, so `{{ users.query }}` stays unreachable) for a name whose rows the template walks past their columns, floored like every sidecar value, with no extra query for the outer QuerySet. A loop over a filtered operand (`users|slice:':2'`, `dictsort`) or a QuerySet nested in a dict is not covered yet on an explicit view. (#4069)
