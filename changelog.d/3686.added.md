- **A view can declare its own query budget: `LiveView.query_budget`, read by `LiveViewSmokeTest`** (#3686). `LiveViewSmokeTest` had one `max_queries` for every view of an app, so a view that renders in 3 queries could grow tenfold and still pass under the limit a heavy report needs. `query_budget = 3` on a view caps its mount plus first render together; `query_budget = {"mount": 30, "render": 5}` caps each phase on its own (a phase left out falls back to `max_queries`). `test_smoke_queries` now takes each view's limit from `view_config[View]["max_queries"]` (new), else `View.query_budget`, else the class `max_queries`, and reports a view over budget by name with where its limit came from (`shop.views.ProductListView: 5 queries (max 3, from query_budget)`). A budget the smoke test cannot enforce (a dict key other than `mount`/`render`, a `bool`, a negative or non-int value) fails the test with a `ValueError` naming the view rather than being ignored. The default message for a view with no budget is unchanged. Run-time measurement, event budgets and the `djust_audit` listing follow in #3701. Documented in the testing guide, the smoke/fuzz guide and the `LiveView` and testing API references.
