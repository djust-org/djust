- **A Django `Form`, `BoundField` or formset crossing to the Rust engine as an object is no longer rendered until the template prints it (#3769).** The conversion of a form object called `str(form)` (the `as_div` render of every field) and `str(bf)` for every field a loop produced, on every render, for every form in the context, whether or not the template read it; a template that never touched the form paid 4-5x the cost of the flattened dict it replaced (#3755). `Encoded.display` is now a `DisplayText`: eager for every other object, and for a form / `BoundField` / formset an object that is asked for `str()` the first time a sink reads it (`{{ form }}`, a string filter, `|json_script`, a loop-cache hash), with the answer shared by every clone of the value. A form printed N times is rendered N times, as under Django; the eager conversion rendered it three times before the template printed anything (`hello` over a form in the context called `str(form)` three times) and once more per occurrence. `display_safe`, `str_raised` and (for every opaque carrier, where it was a copy of `display`) `json` are derived from that one reading and are methods (`Encoded::display()`, `display_safe()`, `str_raised()`, `json()`), so a new reader of the text cannot get a half-built answer; the walk floor is unchanged (the asked object is still the floored handle), and the teardown that clears a view's live handles (`clear_live_handles`) releases the text's own handle too, without running the object's `__str__`. A form whose `__str__` raises is now an ordinary carrier whose text raises at `{{ form }}` and nowhere else, as under Django. **Behaviour change, towards Django:** `str(form)` validates the form (`full_clean()`), so reading it at conversion validated every form the engine was handed. Spellings that depend on that accident now print what Django prints for a form nothing validated: `{{ form.cleaned_data }}` is empty (it was the cleaned data), `{{ form|pprint }}` says `valid=Unknown` (it said `valid=True` / `False`), and on a bound `ModelForm` `{{ form.instance.x }}` is the unmodified instance (it carried the submitted value). A view that calls `form.is_valid()`, or a template that reads `form.errors` / `form.is_valid`, is unaffected. **Cost, measured on a release build (CPU time per render, `DjustTemplateBackend`, a bound invalid form of N `CharField(help_text=...)`):** a template that never reads the form 734 -> 33 us at N=4, 3,240 -> 39 us at N=20, 30,035 -> 97 us at N=200; `{{ form.f0 }}` 796 -> 131 / 3,401 -> 141 / 30,021 -> 312 us; `{{ form }}` is now Django's own cost (1.9x faster than before, the same as Django's engine). **Not removed:** a loop over a large form still pays, per `BoundField`, the walk floor's re-derivation of the form's password-widget fields (`serialization._model_form_floor`), which is O(fields) and so O(fields^2) over a loop; it is floor code and was left as it is.
