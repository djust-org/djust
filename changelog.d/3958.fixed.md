- **`dj-submit`: the pressed submit button is lost under strict event parameters (#3958).** `_target`, its only channel, is never generated under the strict policy (ADR-036 decision Q2), and the button's own `name=value` was never a field. Under strict the pressed button's `name=value` is now a generated form field, as on a native post, and follows Q1 like every other generated value: it is sent only to a handler that declares that parameter or has a `**` catch-all, so naming a button cannot add a parameter to a closed handler (ADR-036 addendum, 2026-11-11). An unnamed or disabled button, a submit with no submitter, a name that is not an ASCII identifier starting with a letter (`save-draft`, `_x`), and a name the transports read as protocol (`event` and `params`, which the HTTP fallback reads as its `{event, params}` envelope and which re-routed the call, `component_id`, `view_id`, `csrfmiddlewaretoken`, `constructor`, `prototype`) send nothing, on the WebSocket and the HTTP fallback alike. Legacy handlers are unchanged (`_target` stays the channel and no field is added, since a legacy closed signature rejects an unexpected parameter). Covered by `tests/js/submit_submitter_3958.test.js` and `tests/js/form_events_review_3976.test.js`.
