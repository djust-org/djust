- **A connected view holds about a third less memory on a table page and a
  quarter less on a page of markup (#4319).** The Rust side keeps the same
  data in smaller shapes: an element's attributes are a sorted vector rather
  than a hash table (`djust_vdom::Attrs`, the same map API, iterating in name
  order), a value and a dict key in the Rust copy of the state are 40 and 32
  bytes rather than 80 and 48 (`Value::Object` and the name and fields of
  `Value::NamedTuple` are boxed, as is `ObjectKey::Other`), and the
  text-region index keeps positions only and reads each node's text from the
  tree. A ~100 KB table with its 880 rows in state went from 4.19 MB to
  2.92 MB per view and a ~100 KB page of markup from 1.49 MB to 1.13 MB; the
  table's ceiling in `test_view_memory.py` drops from 4.5 MB to 3.2 MB, and
  the scaling guide's per-view memory formula and tables are re-measured.
  Nothing sent to the browser changed: patches, wire snapshots and the
  regenerated VDOM diff fixtures are byte-identical. It still misses the
  provisional 2 MB for a 100 KB table, which needs a different
  representation of the retained tree.
