- **A value written into `<textarea>`, `<title>` or an HTML comment of a hybrid component `template` is escaped even when it is marked safe (#3914).** The content of `<textarea>` and `<title>` is text in which character references are decoded, ended by the first matching end tag, and `-->` ends a comment the same way, so markup in a value there can end the element. `Component.render` draws a class through its `template` when the crate constructor refuses a value (a lazy string is one) and always for a class with no crate counterpart, and that path left a marked-safe value alone: `TextArea(value=<lazy marked-safe text that ends the textarea>)` ended the element and put live markup after it. Now a `{{ }}` in that text is escaped whatever the value is marked as (a marked-safe string, a lazy one, an object whose text form is marked safe, a callable returning one; also `{{ v|safe }}` and under `{% autoescape off %}`). **Before/after**: `<textarea>{{ v }}</textarea>` with `v = mark_safe("<b>x</b>")` printed `<b>x</b>` and now prints `&lt;b&gt;x&lt;/b&gt;`; the same for `<title>` and for `<!-- {{ v }} -->`. An ordinary value prints exactly as before: a plain name keeps the engine's own formatting (a date localized, a number formatted), checked by rendering a corpus (strings, numbers, decimals, dates, datetimes, `None`, booleans, lists, dicts) before and after; a dotted path or a filtered expression ends in `|force_escape`, so a date or number there prints in its canonical form (`2026-01-02`). A callable in such a slot is called where the engine reaches the slot, not before, so one in a branch that does not render is not called. **Unchanged on purpose**: `<script>`, `<style>`, `<xmp>`, `<iframe>`, `<noembed>`, `<noframes>`, `<plaintext>` and `<noscript>` keep the author's markup. Entities are not decoded in them, so HTML escaping is the wrong encoding (`<script>var cfg = {{ cfg|safe }};</script>` must stay JSON); use `{{ data|json_script:"id" }}` or a `data-*` attribute to put data in a page. The scanner still reads the first seven as raw text, so an `<a href="{{ u }}">` inside `<xmp>` is not an attribute. Every other text slot keeps a marked-safe value's markup, as before; the remaining difference to the Rust and custom paths for ordinary text slots is documented in the components guide and tracked in #3932. A `{% blocktranslate %}` block in an attribute value or in that text is no longer broken (see the #3913 fragment); a tag that prints text inside `<textarea>` / `<title>` / a comment (`{% firstof %}`, `{% cycle %}`), shapes the scanner cannot follow like a browser does (an element name built by a tag, an end tag in another block than its start) and an `{% include %}`d partial that holds slots are named by the existing once-per-class warning (class, tag/attribute/element names, shape names and a count; never a value). The scanner also reads a raw-text end tag the way the HTML tokenizer does (ASCII case and whitespace; `</textarea-x>` is not an end tag) and follows an element opened inside `{% verbatim %}`.
