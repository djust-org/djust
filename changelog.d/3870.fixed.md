- **The Python `data_table` template rendered an empty cell for every cell of a dict row, an empty `data-value` on every clickable row, and read `sortable: False` as True (#3870).** `table.html` read a cell as `{{ row|dictsort:col.key|first }}`, but `dictsort` over a dict iterates its KEYS and resolves the column key against each, so the lookup was `""`; the same expression gave `data-value` (`row_click_value_key`), `data-href` (`row_url`) and the href of a link column (`col.link`). `{% if col.sortable|default:True %}` turned `False` into True, so an unsortable column still had `dj-click` on its header. Cells now come from a `table_cell` filter (a dict row's value; `""` for a missing key or a row that is not a dict; written with `str()` like the native table, so a number is not localised and `1000` is not `1,000`; a `mark_safe` string is kept, as every Python tag does), and `sortable` is `default_if_none:True`. The two URL sinks the fix makes live go through `table_href` (`url_attr`): `javascript:`, `data:` and `vbscript:` become `#`, the value is escaped, and a quote cannot end the attribute. The native table reads `sortable: None` as "not given" too, as the template does. `table.html` now begins with `{% load djust_components %}`, so a test that renders it with a bare `Engine()` registers the library (the three that did are updated). The native table's `data-value` and cells are pinned equal to the Python template's for dict rows with a missing key, a `None`, falsy values, a key named `items`, numbers and a hostile payload sweep. Rows that are not dicts still render nothing natively and an empty cell under Python, as before. A row's `data-value` is force-escaped, so a `mark_safe` row value cannot leave the attribute.
