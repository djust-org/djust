- **Persisted state over its size limit refuses that one change instead of
  breaking the view (#4095).** A change taking a view's `persist="server"`
  fields over `StateLimits` (64 KB encoded, 10,000 values, depth 16) answered
  500, and on a live connection every later event failed too, because the
  oversized value stayed on the view. The save is now refused before anything
  is written (`StateLimitExceeded`): the user gets an error naming the field and
  the limit (`code="state_too_large"`, status 413 on the HTTP fallback), the
  store keeps the last state that fit, and on WebSocket and SSE the view's
  declared server fields go back to that stored state, so the view, the store
  and the page agree and later events work. The limits are unchanged. Cases in
  `python/djust/tests/test_state_limit_refusal_4095.py`.
