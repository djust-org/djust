- **X105 also flags CSS named colours and `style=` attributes, and a new X106 flags literal `font-family` stacks** (#3687). `djust_audit --ast` already flagged hex and colour-function literals in the stylesheets a LiveView template links; three neighbouring cases passed. X105 now also counts a CSS named colour (`white`, `red`, `black`, ...) in a property that can hold a colour (`color`, `background`, `border*`, `outline*`, `box-shadow`, `fill`, `stroke`, and similar) and as the whole value of a custom property, so `animation-name: orange` and `grid-area: tan` are not findings; `transparent`, `currentColor`, the CSS-wide keywords and any literal inside a `var()` fallback stay allowed. It reads the `style="..."` attributes of templates in the live closure the same way (a `{{ }}` value is unknown, not a literal; a `{% %}` tag is skipped and its branches are read) and reports one finding per template, with `{# djust: noqa X105 #}` on the declaration's line to suppress. New X106 flags a `font-family` that is not a `var(--font-*)` theme token, and a `font` shorthand that names a family, in linked stylesheets (outside `@font-face`) and in `style` attributes; `inherit`, `initial`, `unset` and `revert` are allowed. X106 has its own code (`/* djust: noqa X106 */`, `{# djust: noqa X106 #}`), is a warning, and is listed in the UI summary cache (`rules`, `counts`) without triggering `djust.I003`.

  **Behavior change**: (a) `djust_audit --ast` reports more X1xx warnings, and X106 is new. (b) Projects that run `djust_audit --ast --strict` in CI will start to fail on the named colours, `style` attributes and font stacks they already had. (c) Fix the finding with a theme token (`hsl(var(--foreground))`, `var(--font-sans)`), suppress one declaration with `noqa X105` / `noqa X106`, or keep the previous scope with `--ast-no-ui`.
