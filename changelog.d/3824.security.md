- **A context value reaching a `{% djust_pwa_head %}`, `{% djust_pwa_manifest %}`, `{% djust_sw_register %}` or `{% djust_offline_indicator %}` argument can no longer write template code or markup into the page under the native engine (#3824).** The four handlers in `template_tags/pwa.py` bridged to the Django tags by writing the tag into Django template SOURCE as `key="<resolved value>"` and compiling it, so a value carrying a quote and `%}` ended the tag early and everything after it was compiled as template text: `{% djust_pwa_head name=evil %}` with `evil = 'a" %}<script>alert(1)</script>{% djust_pwa_head name="b'` rendered a live `<script>alert(1)</script>`. All 16 keywords the four tags take through this bridge were reachable, through a plain variable and through a dotted one (`u.name`); a tenant-configurable app name was enough. The Django engine resolves `name=var` as a value and was never affected. The handler now builds its source from constants only (a tag name and keyword names checked against `_TAG_PARAMS`, then one context-variable reference per keyword, `name=kw_name`) and passes every value in the render context, so Django resolves it as data and the tag's own escaping applies. `icons` (a list of dicts, which this bridge can only ever pass as a string) is no longer accepted: `{% djust_pwa_manifest icons=... %}` under the native engine now renders the failure comment instead of a silently odd manifest. A keyword the tag does not take, or a tag name outside the table, raises into the existing marked `<!-- djust: ... render failed -->` diagnostic instead of reaching the source. Two consequences to know: a quote-bearing value used to fail with that diagnostic and now renders, escaped; and an unquoted-safe literal such as `theme_color="Tom & Jerry's"` is now escaped in `<meta content>` (`Tom &amp; Jerry&#x27;s`) because the value is a plain string rather than a `SafeString` literal. Ordinary values render the same bytes (a differential over 48 ordinary cells: no difference), and for all 208 tag x keyword x payload cells the native engine now renders what the Django engine renders (89 differed before). `theme_color`/`background_color` that are not colour-shaped and a `sw_url` carrying a `javascript:`/`data:`/`vbscript:`/`blob:` scheme or a control character are refused in the shared Django tag functions (the default is used and the parameter name is logged), so both engines agree. `python/tests/test_pwa_failure_diagnostic_2434.py` and the `_ARG_VECTORS` row in `test_custom_tag_return_escape_2379.py` used a double-quote-bearing value as their only way to reach the diagnostic; both now use an unsupported keyword. Regression cases in `python/tests/test_pwa_tag_template_injection_3824.py`, gate-off verified (ten mutations, each caught).
