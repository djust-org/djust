- **The `theme_context` processor's `theme_presets` (about 12 KB) is no longer copied into every LiveView's stored state (#3631).** djust copies each JSON-serialisable context-processor value into the view's Rust state, so any app that installed `djust.theming.context_processors.theme_context` stored the preset list in the snapshot of every view, on the HTTP GET and on every WebSocket event, whether or not a template read it. A one-counter view stored 12,208 bytes after a GET and now stores 510. The value is a `RequestScopedList`: a real `list` (`isinstance(..., list)`, `json.dumps`, `{{ theme_presets|json_script:"p" }}`, `len`, indexing, `in` and `{% for %}` behave as before, in both template engines) that the bridge sends to the renderer through the raw-value sidecar instead of storing, and drops from a snapshot an earlier build stored. `ThemeMixin` supplies the same type, which also restores `json.dumps` and `isinstance(..., list)` on its `theme_presets` (the `LazyThemeList` it used since #3626, which had no JSON form, is gone). A processor of your own opts a large request-derived list out of the stored state with `djust.request_scoped.RequestScopedList(items)`; a plain list is stored as before. **Behaviour note:** `type(ctx["theme_presets"]) is list` is now `False`, and `yaml.safe_dump` of it raises `RepresenterError` (convert with `list(...)`; see `upgrade-to-1.3.md`). The type is public: `from djust.request_scoped import RequestScopedList`. New cases in `test_theme_context_state_weight_3631.py` (`TestTheStoredSnapshotOmitsThePresets`, `TestNothingBreaksForReaders`, `TestTheHttpPostFallback`, `TestAStaleStateEntryIsShed`, `TestTheWebSocketPath`). Refs #3626.
