- **`RedisPresenceBackend.list()` cost 2 + N Redis commands on every render (#3203).** Each call ran `cleanup_stale` (a `ZRANGEBYSCORE`, plus a MULTI/EXEC write pipeline when anything was stale), a second `ZRANGEBYSCORE`, and one `HGET` per member in a MULTI/EXEC pipeline; `list_presences()` in `get_context_data` and `online_count` call it on every render of every session, which made presence the largest Redis load in a multi-pod chat. A read is now one `ZRANGEBYSCORE` and one `HGETALL`, pipelined without a transaction, whatever the member count. `list()` runs `cleanup_stale` at most once per `cleanup_interval` (a new constructor argument, default 30 s) per presence key per process; a stale member is still left out of the list, because the read filters on the heartbeat score. Calling `cleanup_stale()` directly is unchanged. 8 regression cases in `python/djust/tests/test_redis_presence_list_cost_3203.py`, which count the commands fakeredis receives.
