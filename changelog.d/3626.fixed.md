- **`ThemeMixin` no longer puts about 80 KB of theme HTML in every view's state, and the `Large LiveView state` warning now says what it measured (#3626).** `ThemeMixin._setup_theme_context()` assigned `theme_head`, `theme_css`, `theme_switcher` and `theme_presets` as public attributes, so each was serialised into the stored Rust snapshot and the session save, and the private `_theme_css_raw` (the push-event CSS, ~18 KB) into the private-state save, even on a page that only prints the `{% theme_head %}` tag. They are now supplied to the template lazily, beside the context processors' output (`ThemeMixin._apply_context_processors`), and `view.theme_head` and the other three still work in Python as class attributes that render on each read and are never stored. A trivial one-counter `ThemeMixin` view stored 79,862 bytes after a GET and now stores 584; the rendered page is byte-identical on first render, and the next render after a theme switch re-sends the four values (`_djust_forced_changed_keys`, consumed once by `rust_bridge`). **Behaviour notes:** the mixin's values still win over a `theme_context` processor's, as the attributes did; `theme_context` is not needed for `{{ theme_head }}` on a `ThemeMixin` view; an assignment in a subclass (`self.theme_head = ...`) still takes precedence, and, as any assignment, makes it state; a restore skips the four strings a session written by an older release holds (`_state_restore.class_member_kind` treats a `_djust_framework_derived` attribute like a property). **Breaking, for code that reached the old attributes through the context:** `get_context_data()` no longer returns `theme_head`, `theme_css`, `theme_switcher` or `theme_presets` (read `self.theme_head`; templates are unaffected), and a view with no `request` renders them empty. `theme_presets_count` is still supplied. A view that skipped `mount()` (reconnect restore, restored sticky child) gets the values without `theme_context`, from its request. `theme_presets` is a `RequestScopedList` on these views, a real `list` the framework does not store (#3631; first shipped here as a lazy non-list object, which had no `json.dumps` form). The same warning now prints the snapshot's three parts (context, rendered tree, template) with the largest context keys, and its advice matches what was measured: render fewer and leaner rows; `temporary_assigns` empties the context copy after the next render but not the tree; streams and `get_render_only_context()` do not shrink the snapshot. New cases in `TestTheViewStateOmitsTheHeavyChunks`, `TestTheNamesStillWork`, `TestTheHttpPostFallback`, `TestTheWebSocketPath` (`test_theme_mixin_state_weight_3626.py`), in `TestAViewThatSkippedMount`, `TestTheDerivedNames`, `TestAThemeSwitch`, `TestTheLeftovers` (`test_theme_mixin_restore_and_switch_3626.py`) and in `TestDescribeSnapshot`, `TestTheAdviceMatchesWhatReducesTheNumber`, `TestTheWarningItself` (`test_large_state_warning_3626.py`). Refs #3626: the context processor's own `theme_presets` list (~11.7 KB in any view's snapshot) is #3631, and the stored tree/stream rows are #3632.
