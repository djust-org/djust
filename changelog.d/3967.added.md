- **`ModelFormMixin`: cheaper live validation and a record selected from the page, without weakening ADR-017 for writes (#3967).** Two opt-ins, both off by default. `object_recheck = "writes"`: an event that cannot write reuses the record authorized earlier on the same connection instead of looking it up and authorizing it again, so `dj-input="validate_field"` no longer costs a query per keystroke. Only the framework's own `validate_field` and the handlers named in `object_read_only_events` qualify; every other event (`submit_form`, `reset_form`, every handler of the app's, including ones that write without saying so) is a write and gets the full check, under every setting. The record is reused only while it is unchanged since it was authorized, the route and lookup are the same and the user is the same; a view that overrides `validate_field` gets the full check for it. `get_object_lookup()` (keys `pk_url_kwarg` / `slug_url_kwarg`, default the route's kwargs) selects the record from view state such as a `?open=<id>` parameter kept in `handle_params`; the record is then authorized after `mount()` and `handle_params()`, with the same queryset scoping and `has_object_permission()`. With `object_optional = True`, "nothing selected" is `object = None` and no form rather than a denial; a selected record that is missing, filtered out or forbidden (or a key that is not valid, `?open=abc`) is still the same denial, and switching the selection starts the form from the new record's own values. Differs from the issue: read-only is declared by an allowlist (an unmarked handler is a write) rather than `@event_handler(mutates=True)`, because the latter would turn an app's forgotten marker into a skipped authorization. Regression tests in `python/djust/tests/test_model_form_object_recheck_3967.py`.
