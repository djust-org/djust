- **An overriding `get_context_data()` ran twice per HTTP GET (#3725).** The GET evaluated the
  view's context once and cached it for the render that follows, but the cache short-circuit sat
  inside the stock `get_context_data()`, so a view that defined its own method (with or without
  `super()`) ran its whole body a second time from `_sync_state_to_rust()`: queries, API calls
  and side effects happened twice on first paint, and a query budget read double. The render now
  takes the context the request already computed, through one helper
  (`ContextMixin._context_for_render`) used by both render sinks, for legacy and explicit views.
  Events and later renders still evaluate afresh, because the GET clears the cache. A page GET
  now enters one `"render"` sync step instead of two (the sequence in the turn-middleware guide).
  Not changed: the HTTP POST fallback of a legacy view still evaluates twice, and an
  explicit-exposure view with a `template_name` page shell evaluates three times on a live
  mount. Regression coverage in `python/djust/tests/test_single_get_context_data_3725.py`.
