- **Component tags carry djust bindings and attributes (#3279, partial).** `{% theme_button %}` forwards any extra keyword to the element (`dj_click`, `dj_value_id`, `name`, `value`, `disabled`, `data_*`, `aria_*`; underscores become hyphens, each value is escaped) and `href=` / `element=` render an `<a class="btn ...">` for link-styled buttons. `{% theme_select %}` takes the same pass-through. `{% theme_input %}`, `{% theme_select %}` and `{% theme_textarea %}` accept `id=` so repeated fields get unique ids (default stays `name`). The shared pass-through now validates attribute names and refuses `on*` event-handler attributes and `javascript:` / `vbscript:` / `data:` URLs with `ValueError`; **upgrade note:** `{% theme_input %}` and `{% theme_progress %}` used to emit an `onfocus=` or `onchange=` keyword silently, they now raise (use a `dj-*` binding). On a link-styled button `type=` raises and `disabled=True` renders `aria-disabled="true" tabindex="-1"` without `href`; `djust_theme check-compat` warns about a project `button.html` that ignores `extra_attrs`, `href` and `tag`. Not included: block-tag forms of `theme_card` / `theme_alert`, which stay with #2894. Regression cases in `python/djust/tests/test_theming_component_attrs_3279_3288.py`.
