- **Every one of Django's 25 built-in template tags and 57 built-in filters is now supported, and `{% cache %}` was the last library tag left (#2517).** Four gaps closed in one arc, measured on Django's own `template_tests`: the engine subset moved 77.17% → 85.20% (808 → 892 of the 1,047 cells that reach an engine) and the whole label 83.59% → 89.35%, with zero cells regressing.

  `{% ifchanged %}` was a `Node::UnsupportedTag`, so a template carrying one failed to PARSE. It is now native, with both forms Django distinguishes: the no-operand form compares the RENDERED body — and reuses that string rather than rendering twice, so a `{% cycle %}` in the body advances once — while the operand form compares resolved values under `ignore_failures`. State is scoped to the innermost loop EXECUTION, mirroring Django's one `forloop` dict per `ForNode.render`, so an inner tag resets each time an outer loop re-enters it while iterations of the same loop share it. The comparison follows PYTHON equality (`0 == False` and `1 == 1.0` are one value; `1 != "1"`); the randomized differential found the first version's `{:?}` key wrong within sixty seeds.

  `{% cache %}` is bridged as a hand-written block handler over Django's own cache framework. Its compile function consumes a body (`parser.parse(("endcache",))`), which the generic `{% load %}` bridge cannot serve, and unlike `{% blocktranslate %}` its body is not data either — what it needs is the body RENDERED, which is exactly what djust's block-handler protocol delivers. Operands resolve through Django's own `FilterExpression`, so a filter chain (`{% cache 2|add:1 k %}`) works, an unresolvable expiry raises rather than silently meaning "forever", and a `template_fragments` cache is preferred over `default` as Django prefers it.

  `django.templatetags.static` is bridged for `{% get_static_prefix %}` / `{% get_media_prefix %}`. The native `{% static %}` is skipped explicitly: `_may_override` consults the handler REGISTRIES, and a native parser tag is in none of them, so without the skip the bridge would silently displace it.

  `string_if_invalid` is honoured on the `{{ var }}` path. Django does not merely substitute a marker — a non-empty setting RETURNS from `FilterExpression.resolve`, so the filter chain never runs, which is why `{{ missing|default:"Foo" }}` renders the marker and not `Foo`.

- **A template name can no longer escape its search directory (#2517, PR #2650 review).** `FilesystemTemplateLoader::find_template` did a bare `dir.join(name)` with no containment check — Django's loaders get one from `safe_join`, which raises `SuspiciousFileOperation` and skips the directory. The gap predates this work but was reachable only from a template author's literal until `{% include %}` / `{% extends %}` began resolving an unquoted operand from the render CONTEXT, at which point `{% include chosen %}` with a context-supplied name became an arbitrary-file read: measured, `t = "../../SECRET.txt"` rendered the file's contents where Django answers `TemplateDoesNotExist`. The check is lexical and runs before any filesystem call, so a symlink cannot race it, and it refuses an escaping `..` at ANY position — `a/../../x` is refused exactly like `../x`, which a prefix-only reading (all `construct_relative_path` does, and only for `{% extends %}`) would let through. A `..` that stays inside still resolves. The search also stats for a FILE now, not merely an existing path (#1805 is_dir parity).

- **`{% include %}` of a template that itself `{% extends %}` now renders instead of raising (#2531).** The include arm rendered the loaded nodes directly, so an `{% extends %}` among them reached the arm whose whole job is to say "this should have been handled at template level". Django renders an included template as a template in its own right, so its inheritance chain resolves before its body does. Now it does here too — for the plain and the `only` form, and with `{{ block.super }}` inside the included child.

- **`OPTIONS['debug']` and `OPTIONS['string_if_invalid']` are honoured, and an unrecognised `OPTIONS` key warns (#2518).** `DjustTemplateBackend.__init__` popped `context_processors` and silently discarded every other key, so a project configuring one got no error and no effect. `OPTIONS['autoescape']` is the deliberate exception: it is REFUSED with `ImproperlyConfigured` rather than honoured, because `Context::set_autoescape` has exactly two production writers by design (the `{% autoescape %}` render arm and the `include … only` copy) and a global escaping switch reachable from configuration is the shape those pins exist to refuse. Refusing loudly is the point — silently dropping it leaves the project believing escaping is off when it is not.
