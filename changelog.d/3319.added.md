- **Auth refusals carry a stable `code` on every transport, and reach the page without parsing message text (#3319).** The refusal frames that lacked one (a `@permission_required` handler, a mount refused with `PermissionDenied`) and the HTTP fallback's 403 bodies now carry `"code": "permission_denied"` next to the unchanged `error` text, as the revoked-authority and object-level frames already did. The SSE `reauth_on_event` frame sent the numeric close code `4403` as its `code`; it now sends `"permission_denied"`. On the client, `djust:error` gains `detail.code` (WebSocket, SSE and HTTP fallback) and `djust:auth-refused` gains `detail.error_code`, the code of the refusal frame that preceded the 4401/4403 close (`null` when there was none); `detail.code` stays the numeric close code. Documented in the authentication guide ("Refusal codes"). Regression cases in `python/djust/tests/test_auth_refusal_codes_3319.py` and `tests/js/auth-refusal-code-3319.test.js`.
