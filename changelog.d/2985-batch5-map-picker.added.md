- **MapPicker now ships its interaction and a vendored Leaflet (#2985, batch 5).** The component rendered a `dj-hook` that no shipped script answered. `components/static/djust_components/map-picker.js` now builds the map, puts a marker where the reader clicks, taps or (with the arrow keys and Enter) chooses, and sends `{lat, lng}` (finite numbers, latitude clamped, longitude wrapped, six decimals; the handler must still validate them) to `pick_event`. Leaflet 1.9.4 (BSD-2-Clause) is vendored under ADR-040 (`leaflet` in the components `djust_assets.json`, SBOM entry, license file, Subresource Integrity), loaded on demand once per page, and its marker images are passed as explicit URLs so hashed static names work. Tiles and attribution are kwargs (`tile_url`, `attribution`, `attribution_url`, `max_zoom`, plus `label` for the accessible name): the default is OpenStreetMap's standard tile layer with its attribution, which is for light use only (production apps should set their own tile server; viewers' IP addresses reach the tile provider); `tile_url=""` makes no tile request; no API key is stored or shipped. The attribution is built as text, a map whose tiles cannot load still picks and says so, the keyboard moves the marker and announces every move, and the server stays in charge of position and zoom. Markup changes are additive only (new `data-` attributes and an optional `aria-label`), on the component class, template tag and Rust handler alike; a byte comparison of 9,075 renders against the previous release is identical once those attributes are removed. The script registers in `window.DjustHooks` and only when neither hook registry already holds that name. 4 components from the issue remain.
