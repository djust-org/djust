- **`djust.testing` publishes live-session test helpers for explicit views (#4191).**
  An explicit view binds to a saved server session at mount and reads it,
  and its user, again on every turn. So a test with a stub user, a bare
  consumer or a request without a saved session is refused. The helper the
  framework's own tests used for this was private. `djust.testing` now
  exports it:
  `open_live_page(url, *, user=None, client=None, **extra)` does the page GET
  through the project's middleware and returns a `LivePage`. Its
  `post_event()` sends the HTTP fallback POST on the page's tab,
  `await connect()` mounts the view over a `WebsocketCommunicator` (a bare
  consumer, or the project's own ASGI application through its cookie), and
  `await connect_sse()` mounts it over djust's SSE stream. Each carries the
  page's session, user, tab and request extras, such as a tenant header.
  The returned `LiveSocket` / `LiveSSE` give `send_event()` (the answer
  matched by `ref`), `receive()` and `frames`. `live_session()` and
  `with_live_session()` give a hand-built communicator, ASGI scope or request
  a saved session and user. See "Real sessions and transports" in the testing
  guide.
