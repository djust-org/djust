- **An explicit view that also sets `enable_state_snapshot = True` no longer acknowledges a failed state save (#3211).** The flag is the legacy snapshot opt-in, but on the event path it sent an explicit view to the legacy best-effort save, which logs a failed or slow write and answers the event with a `patch` anyway. That bypassed ADR-038 E3 (the browser was shown a state storage did not have) and the #3200 deadline fix. Explicit views now always commit through `commit_explicit_turn`, whatever the flag says, as mount already did. The same applies to the parallel paths: an event on a component declaration (for example an ADR-034 interactive binding such as `DropdownMenu`, whose output handler writes the view's declared fields) now commits an explicit view's state before its frame, where before it was saved only best-effort with the flag and not at all without it; and the sticky-child save predicate now also requires both the child and the parent to use the legacy policy, since a legacy save under an explicit parent can never be restored. Legacy views are unchanged. New cases in `python/djust/tests/test_exposure_snapshot_opt_in_3211.py`.
