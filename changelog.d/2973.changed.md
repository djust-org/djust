- **Saved view state is keyed by tenant, and an unknown `PRESENCE_BACKEND` now fails loudly (#2973).** A view that uses `TenantMixin` keeps its state in two places, and both are now scoped by `get_state_key_prefix()`, which nothing called before: the state backend (`tenant:<id>:<session>_<page>...`) and the Django session (`liveview_tenant:<id>:<path>` and its `__private`, `_components` and `__sticky__` siblings, read by the HTTP fallback POST and by an `enable_state_snapshot` reconnect). One session that reached two tenants on the same URL shared one entry in each, so a POST on tenant B ran with tenant A's state. A tenant view with no resolved tenant (`tenant_required = False`) now saves and loads no state, instead of using the unprefixed key every other view shares. The id in the prefix is percent-encoded. The tenant context key is now render-only for the legacy session save: before, a restore (HTTP fallback POST, snapshot reconnect) replaced `self.tenant` with its serialized form, so `self.tenant.id` raised in the handler. Views without `TenantMixin` keep their keys, including on a project that only runs `TenantMiddleware` (the middleware resolves HTTP requests only, so scoping by it would key HTTP and WebSocket differently). **Upgrade note (one-time reset):** the keys for tenant views changed, so the state they saved under the old keys is no longer found. State backend: the first reconnect or page load builds a new Rust view and sends a full render instead of a patch; the orphaned entries expire with `SESSION_TTL`. Django session: the first HTTP fallback POST, or the first `enable_state_snapshot` reconnect, finds no saved state and re-runs `mount()`, so in-page state is lost once; the orphaned `liveview_<path>` entries stay until the session expires. Nothing needs migrating, and views without `TenantMixin` are not affected. `PRESENCE_BACKEND` values other than `memory`, `redis`, `tenant_memory` and `tenant_redis` (`tenant_redis` is routed through the global registry since #3047) now raise `ImproperlyConfigured` on first use instead of falling back to per-process memory, and `djust.C019` is now an **error** (it was a warning), so a typo stops `manage.py check` instead of silently making presence per-process. ADR-038 `persist="server"` envelopes are unchanged: bound to the tenant the request resolved at mount and refused across tenants, but not to a tenant set later with `set_tenant()`. Because C019 is an error, `runserver`, `migrate`, `test` and `check` refuse to run while a stale `PRESENCE_BACKEND` is set, even in a project that never uses presence; C019 also fires for `PRESENCE_BACKEND = None`. 39 regression cases in `python/djust/tests/test_tenant_state_keys_2973.py`, `python/djust/tests/test_tenant_session_state_2973.py` and `tests/unit/test_tenant_presence_2973.py`.
