- **Saved view state is keyed by tenant, and an unknown `PRESENCE_BACKEND` now fails loudly (#2973).** A view that uses `TenantMixin` stores its state-backend entry under `tenant:<id>:<session>_<page>...` through `get_state_key_prefix()`, which nothing called before: one session that reached two tenants on the same URL shared one entry. A tenant view with no resolved tenant (`tenant_required = False`) now saves and loads no state, instead of using the unprefixed key every other view shares. Views without `TenantMixin` keep their keys. **Upgrade note (one-time reset):** the key for tenant views changed, so the saved state they held (the stored Rust view, its context and the VDOM baseline the next diff uses) is orphaned. After you deploy, the first reconnect or page load of each tenant view builds a new one and sends a full render instead of a patch. Nothing needs migrating; the orphaned entries expire with `SESSION_TTL`. Views that do not use `TenantMixin` are not affected. `PRESENCE_BACKEND` values other than `memory`, `redis`, `tenant_memory` and `tenant_redis` (`tenant_redis` is routed through the global registry since #3047) now raise `ImproperlyConfigured` on first use instead of falling back to per-process memory, and `djust.C019` is now an **error** (it was a warning), so a typo stops `manage.py check` instead of silently making presence per-process. ADR-038 `persist="server"` envelopes are unchanged: they are bound to the tenant and refused across tenants already. 26 regression cases in `python/djust/tests/test_tenant_state_keys_2973.py` and `tests/unit/test_tenant_presence_2973.py`.
