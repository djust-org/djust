- **A context key named `__djust_typed_args__` no longer reaches a template tag handler (#3773).** `json_viewer` (and any handler that declares `TYPED_ARGS = True`) is handed its resolved operands under that reserved key. The engine put the key in only when the tag had a resolved operand, so for a tag whose operands were all quoted literals (`{% json_viewer data="x" class="plain" %}`) a top-level context key of that name, supplied by the application, stood in for the engine's value and replaced `data` and `class`. The output stayed escaped, so this was not an XSS; it was an application value overriding an engine-to-handler channel. The key is now the engine's alone: it is removed from the flat context map, from the raw-Python objects laid over it, and from the live frames a bridged tag reads, before any handler is called, and the engine puts its own value back only for a handler that declares `TYPED_ARGS`. A user value of any shape (a dict, a string, a list, a number, `None`, an object that cannot cross) no longer reaches an inline, block, assign or bridged handler. Regression cases in `python/tests/test_typed_args_reserved_key_3773.py`; each of the four removals is gate-off tested separately.
