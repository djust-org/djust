- **Directives the server runs on the page's view follow the page view's strict handler contract inside a component or an embedded child (#4225).** `dj-viewport-top` / `dj-viewport-bottom`, `dj-mutation`, `dj-copy-event`, `dj-dialog-close-event` and the JS-command `push` send no component or child id, so the server runs them on the page's view wherever the element sits. The browser looked the handler up under the nearest component or `{% live_render %}` child instead (`dj-viewport`, `push`), or did not apply the strict contract at all (`dj-mutation`, `dj-copy-event`, `dj-dialog-close-event`), and sent the 1.x payload a strict page handler refuses. Each now resolves the page view's contract, as `dj-auto-recover` does since #4178: a strict handler receives the generated values it declares (`edge`; `mutation`, `attrs`, `added`, `removed`; `text`) plus the element's `dj-value-*` arguments, over WebSocket, SSE and the HTTP fallback. A legacy or unlisted handler keeps its payload unchanged, and a binding that carries owner context (`dj-click` in a component) still uses the component's or child's contract.
