- **The `dj-update` accumulation scan is linear on Python versions whose `html.parser` is quadratic** — before 3.12.11 / 3.13.5 (gh-135462, CVE-2025-6069), `HTMLParser.close()` rescans an unterminated `<a ` or `<!--` at the end of the input once per `<`, so a template ending in junk after its last container took 36s instead of milliseconds (#3647's `outside any container` cases on 3.12.9). The scan no longer feeds the parser what follows the last `>`, which can complete no tag. The bounded-scan tests in `TestTheScanIsBounded` now assert that 4x the input costs under 8x the CPU time (`time.thread_time`), not that a scan finishes within 1s of wall-clock time, so they no longer fail on a loaded machine.
