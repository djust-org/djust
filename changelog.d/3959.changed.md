- **A repeated form-field name is now a list for `dj-submit` handlers, and `dj-change` / `dj-input` / `dj-blur` / `dj-focus` on a group of same-named checkboxes or a `<select multiple>` now send a list as `value`, under the legacy policy as well (#3959).** Migration, in the order it will bite:
  - A `dj-change` handler on a group of same-named checkboxes (for example a per-row toggle, `<input type="checkbox" name="done" dj-change="toggle_todo">` on every row, or `{% live_input "checkbox" %}` repeated with the same `handler` and no `name=`) now receives the list of checked values of the group (the form, or the whole page when the boxes are in no form), not "is this box ticked". An untyped `toggle(self, value=False, **kw)` sees a list, which is truthy while ANY box of the group is ticked, so unticking one of several ticked rows reads as still ticked; a handler declaring `value: bool` is rejected with a type error. Read `value` as a list, or give each box its own `name` to keep the per-box boolean. A lone checkbox is unchanged.
  - A `dj-submit` handler that read a repeated name as one string, for example the hidden-input-plus-checkbox idiom (`<input type="hidden" name="x" value="0">` then `<input type="checkbox" name="x" value="1">`, which used to see the last value), now receives `["0", "1"]` when the box is ticked and `"0"` when it is not, so a handler declaring `x: str` fails only while the box is ticked. Take the last element, or give the inputs different names.
  - This is the owner's decision for #3959 (`FormMixin.validate_field` must be able to validate a `MultipleChoiceField`); there is no opt-out attribute. See "Fields with several values" in `docs/website/guides/forms.md`. Pinned by `tests/js/form_events_review_3976.test.js` and `python/djust/tests/test_form_multi_value_review_3976.py`.
