- **`DJUST_STATE_SAVE_INTERVAL`: a WebSocket or SSE turn may answer before its state is saved (off by default).** Set to a number of seconds (0.5 to 60), a socket turn of a view with no declared `persist=` field sends its reply without waiting for storage, and the view's state is saved no later than the interval after the first unsaved change, when the connection closes, before a navigation replaces the view, and at the ASGI `lifespan` shutdown. A URL change, a turn that queues navigation, a handler that writes `request.session`, `@event_handler(save=True)`, `self.save_state()`, a strict store and a view with declared persistence still save before the reply; the HTTP fallback is unchanged. A view's `state_save_interval` overrides the setting; system checks `djust.C040` (an interval that cannot be used) and `djust.C041` (an interval a strict store makes moot). A tab's saved state carries a holder epoch: with an interval set, a reconnect or fallback request that restores the tab claims it, and an older connection for the same tab can no longer write over it. The default (`0`) keeps every turn saved before its reply. See `docs/website/state/save-frequency.md`.
