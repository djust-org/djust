- **`{% avatar src=... %}` no longer prints a script-capable URL, and every other URL parameter of djust's template tags and components was swept for the same gap (#3665).** The Python `avatar` tag emitted `src` verbatim, so `javascript:alert(1)` rendered `<img src="javascript:alert(1)">` under Django's engine while the native handler emitted `src="#"`; it now goes through `url_attr(src, image=True)`, the policy the handler uses (`data:image/...` stays, any other non-navigation scheme becomes `#`; on a TAG a `mark_safe` value is the author's explicit opt-out). `javascript:` in an `<img src>` does not run in a current browser, so none of this is exploitable today; each is a missing sanitiser. The sweep (`scripts/template-library-url-sweep.py`) drives EVERY parameter each tag can read — not the ones named like URLs — and every parameter of every driveable class component (`Component` and `LiveComponent`, under each CSS framework), with plain, case-folded, whitespace/control-character-obfuscated, entity- and percent-encoded `javascript:`/`vbscript:`/`data:text/html` payloads in four argument shapes (and once with the payload under a key other arguments name), through BOTH engines, and reads the final attributes. Besides the avatar it found seven more places that printed such a URL into an `<img>` (eight sinks in all): the `srcset` of `responsive_image` in both engines and of the `ResponsiveImage` class, and five class components that escaped with `html.escape` where their tag twins call `url_attr` (`ImageCropper`, `ImageUploadPreview`, `LiveIndicator`, `MentionsInput`, `OrgChart`). A `srcset` is a list of URLs, so a new `srcset_attr` checks each candidate as `url_attr` checks one image source; candidates are split exactly as the HTML specification's "parse a srcset attribute" splits them (parentheses in a descriptor do not nest, only ASCII whitespace separates), and the tests judge it with an independent port of that algorithm, not with the production parser. **The class components never honour the safe marker for these URLs**: a `SafeString` is checked and escaped like any other string, exactly as `html.escape` treated it before (an already-escaped `&amp;` becomes `&amp;amp;`); only the template tags keep the opt-out. **Behaviour changes:** a `blob:` image URL, which the native handlers already printed as `#`, is now `#` in the Python `avatar` tag and in these class sinks too; a `srcset` with no candidate (`""`, whitespace) is now omitted by every `responsive_image` path (Django's engine used to print `srcset=""`); a `None` avatar no longer renders a broken `<img>` in `MentionsInput`; and `djust_theming`'s URL denylist also refuses the obsolete `livescript:` and `mhtml:`. No `href`, `action` or other navigation sink emitted a script URL in either engine. The theming tags still pass every scheme the `djust_components` allowlist rejects (`blob:`, `file:`, custom schemes, ...); that is documented, not changed. New cases in `test_avatar_src_scheme_3665.py`, `test_image_url_sinks_3665.py`, `test_theming_url_denylist_3665.py` and `test_url_scheme_sweep_3665.py`; the parity baseline's `avatar` row moves (escaping 8 -> 6, other-attrs 5 -> 3) because the two engines now agree on the `src`.
