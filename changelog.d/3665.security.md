- **`{% avatar src=... %}` no longer prints a script-capable URL, and every other URL parameter of djust's template tags and components was swept for the same gap (#3665).** The Python `avatar` tag emitted `src` verbatim, so `javascript:alert(1)` rendered `<img src="javascript:alert(1)">` under Django's engine while the native handler emitted `src="#"`; it now goes through `url_attr(src, image=True)`, the policy the handler uses (`data:image/...` stays, any other non-navigation scheme becomes `#`, a `mark_safe` value is the author's explicit opt-out). `javascript:` in an `<img src>` does not run in a current browser, so none of this is exploitable today; each is a missing sanitiser. The sweep (`scripts/template-library-url-sweep.py`) drives EVERY parameter each tag can read — not the ones named like URLs — and every constructor parameter of every class component, with plain, case-folded, whitespace/control-character-obfuscated, entity- and percent-encoded `javascript:`/`vbscript:`/`data:text/html` payloads in four argument shapes (and once with the payload under a key other arguments name), through BOTH engines, and reads the final attributes. It found seven more places that printed such a URL into an `<img>`: the `srcset` of `responsive_image` in both engines and of the `ResponsiveImage` class (a `srcset` is a list of URLs, so a new `srcset_attr` checks each candidate as `url_attr` checks one image source) and five class components that escaped with `html.escape` where their tag twins call `url_attr` (`ImageCropper`, `ImageUploadPreview`, `LiveIndicator`, `MentionsInput`, `OrgChart`). No `href`, `action` or other navigation sink emitted a script URL in either engine. New cases in `test_avatar_src_scheme_3665.py`, `test_image_url_sinks_3665.py` and `test_url_scheme_sweep_3665.py`; the parity baseline's `avatar` row moves (escaping 8 -> 6, other-attrs 5 -> 3) because the two engines now agree on the `src`.
