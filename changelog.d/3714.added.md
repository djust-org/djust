- **`scripts/gate_off.py`: one shared gate-off harness (#3714).** State the mutations as data (file, text to find, replacement, label, and the test command that must catch it) in a `.json` or `.toml` file and run `python scripts/gate_off.py <file>` to get a `CAUGHT` / `SURVIVED` / `INVALID` table. It implements the rules CLAUDE.md already states (the issue records five v1.3.0-15 PRs each re-learning them in a throwaway harness). A mutation text that is not found (or found the wrong number of times), a replacement that changes nothing, a `.py` target that no longer compiles, a smoke command that fails on the mutant, a command that cannot start, tests that fail to collect (pytest's `1 error`, not `1 failed`), a hang or runaway *during collection* (an import-time hang is the same "broke the module" as an import-time raise) and a run in which no test passed are all `INVALID`, never a number; `runner: "exit"` reads only the exit status and treats 126/127 as `INVALID`. Test-time errors are counted with failures. Each run has a deadline and an RSS ceiling over its whole process group and a run-time runaway is reported as `CAUGHT` (`HUNG` / `RUNAWAY-MEMORY`) with the measurement. The file is restored from saved bytes in a `finally` (also on SIGINT, SIGTERM, SIGHUP and `atexit`), written to a new inode with a fresh mtime, and verified byte-identical by SHA-256; any restore failure, including an `OSError`, is a `RestoreError` (exit 3). `__pycache__` for each touched file is cleared before and after, and a symlinked target is mutated through the link and left a link. Overlapping runs are refused and a killed run is recovered, by two mechanisms: before anything runs the harness takes an exclusive `flock` on the directory of every target (the directory's inode survives the mutation's `os.replace`; the lock needs no environment variable or state directory, so a second run under another `HOME` is still refused with exit 4 and touches nothing; two files of one directory exclude each other, files in different directories do not), and before the first write it journals the original bytes and the mutant's hash under the target's full resolved path in a directory outside the tree (`$GATE_OFF_STATE_DIR`, else `.cache/gate-off` in the home the user database gives, not `$HOME`); a journal left by a SIGKILLed run is restored from before anything is snapshotted (or refused, exit 4, if the file was edited since). Recovery needs the same journal directory: a run killed under one explicit `$GATE_OFF_STATE_DIR` and followed by a run under another can still adopt the mutant, so `git status` after a SIGKILL remains the backstop. The harness tolerates only benign conditions (a process group already gone, a temp file already removed, the poll tick); a group that cannot be killed, a `.pyc` that cannot be deleted or a `ps` that is unavailable stop the run instead of turning a bound off. A red unmutated baseline stops the run. It cannot judge an equivalent mutation or two shadowing mechanisms; a `SURVIVED` row prints that question. 66 regression cases in `tests/unit/test_gate_off_3714.py` run it against a real fixture package (caught, survived, no-op, import-raising, import-hanging, setup-error, endless-loop, runaway-allocation, smoke-failing mutations; a crash, a real SIGINT / SIGTERM, an overlapping second run and a SIGKILL mid-run all end with the file restored or the second run refused). The harness is gate-off'd with itself: `scripts/gate-off-selfcheck.json` drops each rule in turn and every drop turns a test red. CLAUDE.md's three gate-off paragraphs now point at the script.
