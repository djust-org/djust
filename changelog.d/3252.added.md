- **Lazy and batched views are independently live over SSE, and views of one class keep their own saved state (#3252).** Over WebSocket each view a `mount` names with a `target_id` was already a view of its own; an SSE session hosted one view, so a `dj-lazy` container never hydrated over it and an event from inside one either did nothing or, through `sendEvent`'s fourth argument being a `keepalive` flag, could lose its address. An SSE session now hosts the page view plus views mounted beside it: a `mount` POST that names a `target_id` adds one with its own runtime, state, saves, authorization and teardown, its frames carry the `target_id`, `unmount` releases one, a navigation and the end of the stream release them all, a frame for an address with nothing mounted is refused with `code: "view_unavailable"`, and the client mounts them again after a reconnect. A `dj-hook` `pushEvent` now works over SSE (it used to need the WebSocket), addressed to the view it sits in. Without a stream (a browser with no `EventSource`) a lazy view's hydration reports `view_unavailable` instead of leaving a container that looks live. State isolation, on every transport: an explicit view's `persist="server"` envelope is stored under the view's own address (two views of one class used to restore whichever saved last; the page view's key is unchanged), and a view beside the page view mints, refreshes and revokes no navigation snapshot, so it can no longer replace or revoke the page view's. Still open on #3252: lazy views over the page-POST fallback, a non-sticky child's state between HTTP requests, events sent from code with no element, hydrating the destination's lazy containers after `live_redirect`, a shared render lock, and a refused login-required lazy view redirecting the whole page. Covered in `python/djust/tests/test_sse_view_slots_3252.py`, `python/djust/tests/test_multi_view_state_isolation_3252.py`, `tests/js/sse_view_slots_3252.test.js` and `tests/playwright/test_multi_view_sse_http.py`.
