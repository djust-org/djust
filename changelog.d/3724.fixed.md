- **Parsing a template is linear in its size when the text between tags holds no `>`; `extract_template_variables` was ~n^2.9.** The cause was not the variable walk but the parser: for every `{{ }}` and `{% if %}` it decided whether the position was inside an HTML tag by walking back over the preceding tokens until it met a text token containing `>`. A template whose blocks are separated by whitespace (every indented template) has no such token, so each call re-read the whole prefix, and each piece was prepended to a `String`, which copies it. 4x the blocks cost 43x as much (0.006 s to 0.28 s for 100 to 400 blocks). One forward pass over the tokens now gives the answer for every position (`html_tag_context_table`, reset at the same `>`-bearing text tokens the walk stopped at), built lazily the first time a parse asks and found again by the token slice being parsed, so 4x the blocks costs about 4x. The renderer parses with the same function, so the change reaches it too (render time was not measured); a Rust test compares every position of 3,000 random token streams and 8 named shapes with the old walk, which is kept in the test module as the oracle. The growth test that was `xfail(strict=True)` in `python/tests/test_template_variable_extraction.py` is now an ordinary test over three block shapes.
