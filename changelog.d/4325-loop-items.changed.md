- **A `{% for %}` re-renders only the items that changed (#4325).** Rust keeps the HTML of each item of an outermost loop from the previous render, keyed by index and a 128-bit keyed hash of the item value, and reuses it when the item, the list length, the render settings (autoescape, `string_if_invalid`, l10n, timezone, dj-if markers) and the loop's place in the template are all unchanged. A body that reads anything but the loop variables and `forloop`, uses `cycle`, `ifchanged`, `regroup`, `include`, a nested loop, a custom or time-dependent filter, or a value with a safe/unsafe mark, always renders; so does an item whose render read Python live. A loop not rendered for 64 renders is dropped. Switch: `djust._per_turn` `loop_item_render`. A seeded differential fuzz (`DJUST_FUZZ_4325_SEEDS`) checks it against a full render and catches a deliberately broken store.
