- **The daily Retro Gate Audit can no longer confuse "found something" with "crashed", or "clean" with "could not read" (#3129).** Two defects, one on each side of the workflow/script boundary. The workflow ran `scripts/audit-pipeline-bypass.py` under GitHub Actions' default `bash -e`, so it aborted at the script's exit 1 — its normal "found something" signal — before capturing the exit code, echoing the output, or emitting any annotation (`set +o pipefail` does nothing about `-e`); the observed result (run 37672728078) was a red cron with the findings thrown away, and because `steps.audit.outputs.flagged` was never written the summary fell through to its `else` branch and printed "✅ No flagged PRs." for an audit that never reported. Underneath, the exit code never carried the meaning the workflow assumed: an uncaught exception also exits 1, and a failed `gh` read was swallowed into an empty result — so an authentication failure produced a *clean* audit while an unparseable-JSON crash produced phantom *findings*. The script's exit status is now an explicit contract — `0` clean, `1` findings, `2` could not complete — with a final `AUDIT_VERDICT: clean|findings|incomplete` line as the machine-readable verdict, and a failed `gh`/`git` read raises `AuditIncomplete` instead of returning empty. The workflow dispatches on that verdict: `clean` stays green, `findings` stays green with one `::warning::` per flagged row, and `incomplete` (or no verdict at all) emits `::error::` and fails the step; the captured output is echoed to the run log and uploaded as an artifact, and the summary reports "no verdict" rather than clean when there is none. 10 regression cases in `tests/test_retro_gate_audit_workflow_3129.py`, including the real script driven through stub `gh`/`git` reads for the failed-read and crash paths, and a forged `AUDIT_VERDICT:` line in audit content that must not flip the verdict.
