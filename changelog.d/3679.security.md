- **`TtydTerminalView` took the WebSocket its terminal connects to straight from `?url=`, so a crafted link could point a victim's terminal at any server** — the browser sends every keystroke to that endpoint and draws its replies as terminal output, so an attacker's server could show a fake prompt and record what was typed. It is not a script scheme, so this was not script injection. `?url=` is now honoured only for a `ws://` or `wss://` URL whose origin (scheme, host and port, compared exactly) is the view's own `ttyd_url` or is listed in the new `ttyd_allowed_origins` class attribute, and only if it carries no query string (a ttyd started with `--url-arg` turns URL arguments into command-line arguments of the spawned process); anything else is ignored, with a warning that does not echo the value, and the view falls back to `ttyd_url`. The URL the browser receives is rebuilt from the allowed origin plus the requested path rather than echoed, and a value containing a backslash, whitespace, a control or non-ASCII character, userinfo, no host or more than 2048 characters is refused outright. A subclass's own `ttyd_url` is trusted as written and may carry a query. **Behaviour change:** `/shell/?url=ws://other-host:7681` no longer reaches `other-host` unless it is listed in `ttyd_allowed_origins` (or is the view's own `ttyd_url`). `TtydTerminalView` is also added to the packages the #3665 URL sweep walks (pinned as an undriven page) so a renderable class outside the swept packages is no longer invisible to it (#3679).
