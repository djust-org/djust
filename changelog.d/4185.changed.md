- **djust's own classes no longer state a legacy mode.** The admin change list and change form (`ModelListView`, `ModelDetailView`, and `ModelCreateView` built on it) and the ttyd terminal base class `TtydTerminalView` use explicit exposure, and the component `Meta.event` view-level alias (`toggle_dropdown`, `toggle_modal`, `set_tab` ...) is no longer pinned to the legacy parameter policy: it follows the project's policy. Their pages and frames over WebSocket, SSE and the HTTP fallback are the same as before. Under a project-wide strict policy the alias now compiles as a strict handler: its `component_id` is a framework-supplied argument, bound only when it is empty or names a component the view class declares (the rule the transports already apply before an event reaches the alias), and the page publishes the alias's strict contract (`value`, `**kwargs`), so the client sends it `dj-value-*` arguments, not `data-*`. Developer-visible differences: a `TtydTerminalView` subclass whose template reads its own attributes (`session_log`, `terminal_connected`) lists them in `get_context_data()` built on `super()`, or they render empty (`djust.T027` names each); an admin `change_list_widgets` / `change_form_widgets` view that still states `exposure_policy = "legacy"` makes the admin page fail to render (migrate the widget; `djust.V028` lists it); the alias's published handler metadata reads `parameter_policy: null` instead of `"legacy"`. The T027 hint and the unsupplied-name log no longer suggest `exposure_policy = "legacy"`. The `@live_view` decorator's class still states legacy until #4183. (#4185)
