- **`<body>` is a supported root (#3302).** A `<body>` that carries `dj-root` or `dj-view` is the view's root, on the Python render and the Rust VDOM alike, when nothing inside `<body>` declares a root; its children (a `<header>`, a `<main>`, a `<footer>`, ...) are the page's top-level content. Before, such a page connected and then replaced `<body>` with its first element. A page that already has a root keeps it: a `dj-root` or `dj-view` on an inner element still wins over `<body>`, a wrapper element keeps working as before, and the wire format is unchanged (on 40,000 generated pages, none that had a root the Python and Rust sides agreed on changed). A `dj-lazy` view's container now counts as another view's, like an embedded child's wrapper, so it never becomes the page's root. The nodes djust did not render for the view (its injected scripts and debug panel, dev toolbars, browser-extension nodes) stay in place when the client mounts, navigates or applies a full-HTML update, and the page's own scripts are not run a second time. `<body dj-root>` gets its view path stamped when it is the root. `djust.T025` no longer flags `<body>` (it still flags `<html>` and `<head>`, which are not supported). The client also keeps the `data-djust-target` address of a `dj-view` container when a page mount morphs it, so `dj-lazy` views inside a root mount.
