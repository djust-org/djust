- **One renderer per `djust.components.ui` simple component; the Rust simple-component crate is removed (#4002).** `Alert`, `Avatar`, `Badge`, `Button`, `Card`, `Divider`, `Icon`, `Modal`, `Progress`, `Range`, `Spinner`, `Switch`, `TextArea`, `Toast` and `Tooltip` rendered through a native class from the `djust_components` crate, fell back to an inline `template` when the crate refused a value (a lazy string), and carried per-framework `_render_custom` f-strings no render reached. Each now has one renderer, a Python `_render_custom` that draws the crate's markup byte for byte (pinned against 284 renders captured from the crate, `python/tests/test_ui_simple_golden_4002.py`). `Checkbox`, `Input`, `ButtonGroup` and `Offcanvas` keep their template and lose the unreachable `_render_custom`. The crate (about 4k lines) and the 15 `djust._rust.Rust*` classes are gone: measured per construct-and-render the Python renderer is 1.6x-2.9x faster than the crate path was (`docs/components/RUST_COMPONENTS.md`, `scripts/bench_ui_simple_components.py`). Three fixes come with it: `Tooltip` writes the space before `title=` the crate dropped, and an explicit `id=` on `Range`, `Switch` and `TextArea` is the element's `id` and the label's `for` (the crate used `name`). `Component.__init__` now sets the constructor kwargs as attributes whether or not the class names a `_rust_impl_class`, and `update()` no longer passes `state` to a native constructor.
- **`Alert`, `Badge`, `Button`, `Card`, `Dropdown`, `Modal`, `Progress` and `Spinner` in `djust.components.ui` render through their ui `*Component` twin, so their HTML changed (#4002).** Each maps its arguments onto its twin's (`AlertComponent`, `BadgeComponent`, ...) and returns the twin's markup, which follows `css_framework`. Every simple argument still works: one the twin has no equivalent for (`Badge.size`, `Card.variant`, `Modal.centered`, `Modal.dismissable=False`, `Spinner.sr_text`, an `Alert` variant outside info/success/warning/danger/error) raises a `DeprecationWarning` and is not drawn. Text is still escaped whatever it is marked as. What changes on a page: each element carries an `id` (the class's `id`); a shown `Modal` is `show d-block` with a backdrop and always draws its header and a default "Close" footer; a `Card` header is the card title; the default `Badge` loses `fs-6`. To keep the simple classes working without a view, the twins gained three things: `DropdownItem(url=..., disabled=...)` (the URL checked and escaped like any other), and `standalone=True` on `AlertComponent` / `ModalComponent`, which the simple classes pass, so the Bootstrap close controls are `data-bs-dismiss` and a hidden Bootstrap modal is drawn hidden for `data-bs-toggle` instead of as nothing. A registered component's output is unchanged. The per-class list is under "Markup that changed" in `docs/website/guides/migrating-to-2.0.md`. The other 21 simple classes have no ui twin and are unchanged.
