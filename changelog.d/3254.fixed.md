- **Closing an SSE stream untracks the closed view's presence, and a user open in a second tab is no longer removed by the first tab (#3254).** `SSESession.shutdown()` is synchronous and `untrack_presence` broadcasts through the synchronous channel-layer API, so the record lingered for `PRESENCE_TIMEOUT` (60 s) after the stream closed, whatever closed it (client gone, rate-limit close, abandoned stream). `shutdown()` now schedules the untrack onto a worker thread, or runs it inline when there is no running loop. With presence stored per connection (see the `changed` entry), the old stream's close after an EventSource reconnect removes only the old view's connection, so the registry/in-flight-mount guard #3313 added for that case is gone, and a navigation or close in one tab no longer removes a user who is still open in another. Same-room navigation no longer leaves and rejoins: the replacement view joins before the old view's presence is removed, on both the WebSocket and SSE transports.
