- **Closing an SSE stream untracks the closed view's presence (#3254).** `SSESession.shutdown()` is synchronous and `untrack_presence` broadcasts through the synchronous channel-layer API, so the record lingered for `PRESENCE_TIMEOUT` (60 s) after the stream closed, whatever closed it (client gone, rate-limit close, abandoned stream). `shutdown()` now schedules the untrack onto a worker thread, or runs it inline when there is no running loop. A session that an EventSource auto-reconnect has replaced under its id, or that a reconnect is still mounting to, is not untracked, so the old stream's close cannot delete the record the live session just created. Still open on #3254: same-room navigation leaves and rejoins, and a user open in a second tab is removed by the first tab's navigation or close (needs a per-connection or reference-counted presence record, a design decision).
