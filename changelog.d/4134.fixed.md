- **The last UI-state events component tags send by default have a framework answer, and every such tag takes `component_id=` (#4134).** `{% dropdown_menu %}` (`toggle_menu`), `{% split_button %}` (`toggle_split_menu`), `{% sidebar %}` (`toggle_sidebar`), `{% notification_center %}` / `{% notification_popover %}` (`toggle_notifications`), `{% tree_view %}` (`tree_expand`), `{% alert %}` / `{% page_alert %}` (`dismiss_alert`), `{% toast_container %}` (`dismiss_toast`) and `{% date_picker %}` (`date_prev_month`, `date_next_month`) were refused as "Event rejected" unless the application wrote a handler. `Dropdown` now answers the two menu toggles, and six new components in `djust.components.descriptors` answer the rest: `Sidebar` (`collapsed`), `NotificationCenter` (`is_open`), `TreeView` (`expanded`, the ids of the open nodes, passed to the tag's new `expanded=` argument), `Alert` (`dismissed`), `Toasts` (`toasts`, with `show(message, type=...)`) and `DatePicker` (`year`, `month`). `TreeView` refuses a node id that is not a non-empty string (or integer) of at most 256 characters, and expanding past 10,000 nodes; `Toasts` ignores an id that names no toast and keeps at most 50; `DatePicker` stops at the calendar's first and last month, and defaults its year and month each on its own, as the tag now does (one shared helper): `DatePicker(year=2030)` shows this month of 2030 and steps from it. Selecting a tree node, picking a date, marking a notification read and a menu item's action stay the application's, and `manage.py check` (`djust.T019`) now reports these tags too. The tags of the nine components added for #4126 (`{% lightbox %}`, `{% command_palette %}`, `{% export_dialog %}`, `{% announcement_bar %}`, `{% nav_menu %}`, `{% expandable_text %}`, `{% truncated_list %}`, `{% markdown_textarea %}`, `{% stepper %}` / `{% wizard %}`) and of the tags above take `component_id=` on both template engines, so two components of one type on a view can each be driven by their own tag; only the controls the component answers carry it, never one sending the application's event. `{% bottom_sheet %}` (`close_sheet`, answered by `Sheet`) joins the table, with `component_id=`. The native (socket-render) `{% accordion %}` ignored its `component_id=`, which the Django tag honoured; it now marks its own triggers (not a nested accordion's), and a standalone `{% accordion_item %}` renders as before. An event whose `component_id` is not a string of at most 256 characters (a list raised an uncaught `TypeError` from the lookup) is refused as "Event rejected" before the lookup, over the socket, SSE and the page-POST fallback. `manage.py check`'s hint names the full import (`from djust.components.descriptors import Alert`), since `djust.components` has other classes of the same names. A component state field named after a dict method (`items`, `keys`, `values`, `get`, `update` ...) is now refused when the class is created: it hid the method that saving state calls, so a view declaring such a component crashed when its state was saved. The theming gallery's preview field `values` is renamed `demo_values` for that reason. `scripts/check-handler-contracts.py` no longer lists the nine events as application actions.
