- **The UI-state events component tags send by default have a framework answer (#4126).** `{% lightbox %}` (`close_lightbox`, `lightbox_navigate`), `{% command_palette %}` (`close_palette`), `{% export_dialog %}` (`close_export`), `{% announcement_bar %}` (`dismiss_announcement`), `{% nav_menu %}` (`toggle_nav`), `{% expandable_text %}` (`toggle_expand`), `{% truncated_list %}` (`toggle_list`), `{% markdown_textarea %}` (`toggle_preview`) and `{% stepper %}` / `{% wizard %}` (`set_step`) were refused as "Event rejected" unless the application wrote a handler. Nine new components in `djust.components.descriptors` (`Lightbox`, `CommandPalette`, `ExportDialog`, `AnnouncementBar`, `NavMenu`, `ExpandableText`, `TruncatedList`, `MarkdownTextarea`, `Stepper`) answer them, as `Modal` and `Sheet` do since #4037: declare one on the view and pass its state to the tag. `manage.py check` now reports, as `djust.T019`, a tag in a view's template whose event nothing on the view answers (a `{% modal open=show %}` with no `Modal()` and no `close_modal` handler; a `{% cookie_consent %}` without an `accept_cookies` handler), naming the tag and what answers it. `Carousel()` without `total` logs a warning on the first click that cannot move it. `scripts/check-handler-contracts.py` no longer lists these events as application actions; `accept_cookies` and `palette_search` stay the application's, and the pushed (`stream_chunk`, `data_loaded`) and browser (`section_changed`) event names are not scanned, since none reaches the view. "Events a tag sends" in the components guide lists each tag's events and what answers them.
