- **`LIVEVIEW_CONFIG["http_status_of_state"]` sets the not-found/gone status map for the whole project, and V025 warns about a `get_http_status()` override that would replace it (#3706).** `http_status_of_state` (#3688) was a class attribute only, so a project with several base views repeated the map on each. A view that declares none now reads the config key; **the view's own attribute wins, then the config, and the two are never merged** (a view that declares `{}` opts out of the project's map; neither set answers 200 as before). `LiveView.http_status_of_state` is now an empty read-only mapping that compares equal to `{}`, so a view's own declaration (even `{}`) is told from "declared nothing" by identity. The key is validated like the form-data limits: when the config loads and on every `config.set()` / `config.update()`, it must map state names (`str`) to statuses (`int`, 100 to 599); anything else is logged and replaced by no map. **V025** (Warning, `manage.py check`) reports a class that defines `get_http_status()` while a project-wide map is configured, once per defining class, so per-view copies of the logic do not creep back; suppress it with `DJUST_CONFIG = {"suppress_checks": ["V025"]}` for an override that calls `super()`. The other items of #3706 (V023 `params_form` check, the test client driving `handle_params`, the reserved names) shipped in #3722. Not included: letting `mount()` raise `Http404` / `PermissionDenied` and render the view's own template under that status on every transport, and a per-field fallback for `handle_invalid_params` (#3874).
